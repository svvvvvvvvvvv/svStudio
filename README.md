# svStudio

**工作台。** 只管"给人用"，不管算法。

```
svFilm       纯引擎（没有界面、没有弹窗）      喂一张图 + 一组参数 → 出一张图
   ↑ 调用
svStudio     工作台（这里）                    人在这儿挑图、挑卷、调参、出片
```

## 两个台

| 台 | 干什么 | 从哪来 |
|---|---|---|
| **选片台** | 浏览主题、看大图、打星、按星级归位 | **从 `pickstation/` 搬过来**（它已是 Electron 33 + 原生 HTML/JS） |
| **调胶片参数台** | 挑胶片卷、调力度、调参数、**实时看预览**、出片 | **新做** |

★ 两个台**共用同一个 svFilm 引擎** —— 所以"选片时看到的图"就是"调色后的图"，不用导来导去。

## 怎么调 svFilm（C 方案：两条口子，一个引擎）

| 口子 | 形态 | 谁用 | 为什么 |
|---|---|---|---|
| **CLI** | `python -m svFilm.cli one <图> -o <出> --stock <卷>` | **别人的 agent**、脚本、一次性任务 | 最省事，一条命令就能用 |
| **本地 HTTP 服务** | `POST /render`（常驻进程） | **svStudio** | 常驻 ⇒ **模型只加载一次 + 解码缓存留在内存** ⇒ 换卷 ~1.5 s |

★ **CLI 是薄壳，内部走同一个引擎。** 两条口子不会各写一套算法。

### 为什么必须常驻（实测，2026-09-14）

| 做法 | 换一次卷要多久 |
|---|---|
| 每次调一下、**起一个 Python 进程** | **5.03 s**（且解码缓存留不下来）|
| **常驻进程 + 缓存解码** | **1.45 s** |

⇒ 差 3.5 倍 ⇒ **绝不允许"每次调用起一个进程"**。

## 边界（写死，别再缠在一起）

- **`svFilm` 不许有界面** —— 不许弹窗、不许读配置 UI、不许假设"用户在看"
- **`svStudio` 不许有算法** —— 影调/颜色/颗粒**一行都不许在这里**，全走引擎
- **`svStudio` 不许直接读 RAW 做处理** —— 解码是引擎的事（它才持有缓存）

★ 判断标准很简单：**"换个前端还要不要它？"** —— 要，就是引擎的；不要，就是这里的。
