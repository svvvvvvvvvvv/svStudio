# 反思：胶片引擎的参数，应该从卡的成片里反解

> 你说得对。我反复在做三件错事，所以一直没接住你最早讲的那件事。

---

## 1. 我错在哪

1. **把引擎当固定介质**：先套 3 个 profile / 旧「鹿井预设」，再谈卡。  
   但你要的是：**引擎参数本身从卡来**——卷、纸、化学、PE、WB、amount、gamma、颗粒、光晕、扫描、黑白端、格式，全部从匹配目录的成片里反解。

2. **测量是漏的**：我一直在测**皮肤 + 风格**（C/L/h、分位、tag），没有测**胶片介质**（grain/halation/纸/化学/扫描/黑白端/曝光/WB/格式）。  
   所以引擎参数只能从旧预设来，卡的特征只够选卡，不够驱动引擎。这就是“漏漏的测量”。

3. **把 LR 当主路径**：让 LR 做 Basic/Curve/CG/HSL 补，引擎保持“medium-only”。  
   但你的顺序是：**先把引擎参数从卡解出来，引擎渲出来就该像**；LR 只在最后补局部/placement，不是主力。

---

## 2. 正确顺序

```
匹配目录
  → 对该目录的成片做一次完整测量（介质 + 皮肤 + 风格）
  → 反解引擎参数（卷/纸/化学/PE/WB/amount/gamma/颗粒/光晕/扫描/黑白端/格式）
  → 用这组参数渲 3 张
  → A/B
  → 最后才用 LR 补局部
```

**没有预设；3 个 profile 只是候选锚点/标签，不是生产值。**

## 3. 完整测量：介质签名（每卡一次，存起来）

对匹配目录的成片（38/104 是 16 张），量：

| 维度 | 具体量 |
|---|---|
| 颗粒 | 高频噪声 rms、blur（染料云）、dye cloud µm |
| 光晕 | 高光边 red glow 强度/半径、diffusion |
| 纸/卷基色 | shadow/mid/high a/b、neutral、皮肤 h/C、白点/黑点 |
| 化学 | gamma/红黄配比、couplers 的彩度分配、cross-talk |
| 曝光/印相 | L 分布、p50、脸 L、PE 落点 |
| WB | 同图中性 a/b、皮肤 h |
| 扫描 | 清晰度/柔度、scanner USM、锐化半径 |
| 黑白端 | black5/white95、clip、端点形状 |
| 画幅 | 长边/景深/format |
| 曲线 | p5/p25/p50/p75/p95、toe/shoulder |
| 皮肤/风格 | C/L/h、ΔC、C_rank、分位、tag（保留的） |

**不是只测皮肤；介质每一项都要量。**  
这一份测量就是“最后一次测量成片”：存成 `card_medium_<id>.json`，后面不再重复读图。

## 4. 反解：从签名到引擎参数

1. 引擎探针（灰楔/色卡/平场/高光边/斜边）→ 量 `∂signature/∂param`（`J_engine`）。
2. 卡的签名与探针 baseline 的差 `Δsig`。
3. 解约束最小二乘：
   `Δp = argmin ||W(J·Δp - Δsig)||² + λ||Δp||²`，约束引擎量程、脸/皮肤硬门、背景可过曝。
4. 卷/纸的离散键：按签名距离选最近锚点做初值；**数值强度仍按卡解**（grain/halation/scan/black/white 可连续）。
5. 2–3 轮探针 → 量 → 更新；得到**这张卡专属的引擎参数集**。

输出：`card_engine_<id>.json`（卷/纸标签 + 所有数值）。

---

## 5. 和 LR 的关系

- 引擎先渲；A/B 对卡的成片。
- 如果引擎已经到 80%，LR 只补局部（皮肤/高光/边缘/氛围），不重做 Basic/Curve/CG。
- 如果引擎不到，先修引擎签名（颗粒/光晕/纸/化学/曝光），不是拿 LR 盖。
- LR 的目标仍是同一张卡；但它不是引擎参数的替代。
