## 一、配平基准 / 印相滤片

> 涉及 `config.PRESET_NEUTRAL_FROM_DB` / `PRESET_NEUTRAL_Y` / `PRESET_NEUTRAL_M`
> / `PRESET_FILTER_M_TRIM` / 各预设的 `print_y/m_filter_shift`。

### 1.1 `PRESET_NEUTRAL_FROM_DB = True` —— 配平基准换源（10-08 晚）

【原来错在哪】`neutral` 的语义（作者 README 原话）是「让 18% 灰在最终印相里完全中性的
起始设置」，而引擎按 **(相纸, 放大机光源, 底片)** 三维从数据库取。我们却关掉 DB、
用**一对硬编码常数**（Y 51.423 / M 50.713，源 = public 0.3.2 的 `fujifilm_pro_400h`）
发给全部 10 条预设 ⇒ 除了 Pro400H 那两条，其余全是**用别人的中性值配自己的底片**。

【实测偏差】（0.3.4 库 vs 我们用的常数，单位 CC）：
- C200 三条 −27.2(M) / −56.9(Y) · Ektar100 −17.8 / −10.6 · Portra400 三条 +7.1 / −1.1
- Pro400H 两条 +10.6 / +0.7 · Ultramax400 +0.05 / −7.75

⇒ 独立验证：18% 灰在 C200 上印出来 **b\* = +30.0**（严重偏黄）、Ektar 上 **a\* = +12.7**（偏红）；
换成 DB 之后 C200 的 18% 灰变成 **a\* −0.8 / b\* +1.4**。
⇒ 而 a\*=0 的实测零点落在 M 58.99，DB 给 kodak_ultramax_400 的是 58.66 —— **差 0.33 CC**，
所以"DB 是对的"是量出来的，不是信仰。

【为什么现在敢开】各预设的 `print_y/m_filter_shift` 已同步**重表**成
「旧总量 − 新中性(DB)」⇒ **总滤片量逐条不变 ⇒ 画面不变**
（实测 10 条 18% 灰 Δa\*/Δb\*/ΔL 全部 = 0.00）。这是**纯换参数化**，不是改观感。

⚠ 别把重表后的 shift 当"风格值"调 —— 它是"扣掉正确中性后的余量"，
真正的冷暖身份要看**总量**（= 中性 + shift）。
⚠ 读 DB 的顺序是 `c_filter, m_filter, y_filter`，**别按 y/m 猜**。

### 1.2 `PRESET_FILTER_M_TRIM = 0.0` —— 印相品红底座补偿（10-08 新增 → 当晚归零）

【为什么单开一个键、不去改 `PRESET_NEUTRAL_M`】`neutral` 的语义是**标定基准**
（来源 = public 0.3.2 滤片库 `fujifilm_pro_400h` = [C 0 / M 50.713 / Y 51.423]，
`selftest` 钉着绝对值防 Y/M 对调）⇒ **它不是剂量旋钮**。
而这一档要的是「在标定基准之上整条链统一多加一点品红」= **剂量** ⇒ 另开键，
`neutral` 保持标定值不动（"一个量一个主人"）。

【加在哪】`presets._apply`：`m_filter_shift += 本键`
⇒ 与 A/B 里量过的 `cc_m8` 档**逐位一致**（品红总量 49.713 → **57.713 CC**）。
⚠ **对预闪不生效**（`filter_enlarger_source.py:31-32`：预闪只读 `neutral + preflash_shift`）
—— 这正是被量的那一档。

【为什么当晚就归零】+8CC 品红是 10-08 那次"五条复评"里唯一改了观感的动作，用来修"整张偏红"。
现在查清了：那条红**就是配平基准用错**（拿了 Pro400H 的中性值配 Ultramax/Portra 的底片）。
鹿井这条原本差 **−7.95 CC**，+8 之后恰好落到 **+0.05** —— 所以它有效，但它修的是"表用错了"。

【为什么必须撤】它是**一把全局的刀**：同一个 +8 把 Portra400 推成 **+7.1**、
Pro400H 推成 **+10.6**（修好一条、弄坏两条），而 C200 那三条本来就差 −27 也没救到。
中性值一旦逐条查表（`PRESET_NEUTRAL_FROM_DB=True`），这把刀就没有存在理由了。
⇒ 保留这个键作为"剂量旋钮"以备将来，但**默认必须是 0**。

### 1.3 印相滤片轴：两根轴的名分（10-08 查清，A/B `_debug/_x5_ab.py`）

【结构】**这才是"零点"的答案**
- **主曝光**：`filter_enlarger_source.py:17-18` ⇒ `m = m_neutral + m_shift`（y 同理）
  ⇒ `neutral` 与 `shift` 是**同一根 CC 轴**（Kodak CC 单位，`transmittance = 10^-(CC/100)`）。
- **预闪**：同文件 `:31-32` ⇒ 只读 `neutral + preflash_shift`（**不看 `shift`**）。
- `enlarger_neutral_illuminant()`（neutral、不含 shift）**全仓库无调用点 = 死代码**。

⇒ ★ **零点在 `neutral`；`shift` 是逐预设/逐场景的偏移**（10 条预设 y 3~13、m −4~+2
就是靠它分家的 ⇒ **不许把 10 条的 shift 一起归零**，那是把预设的冷暖身份抹平）。
⇒ 10-07 说的"neutral 填错导致偏红"**想简单了**：那天量到的"shift −1→+8 与
neutral 50.7→57.7 结果相同"只在**主曝光**上成立；预闪那一臂是另一回事
（10-08 实测"把 shift 并进 neutral"对 1289：脸 a\* −0.36 / b\* −0.90 / 色相 −1.97）。

【缺品红的证据 —— 两个症状一起出现才算证据】
我们总量 = 50.713 + (−1) = **49.713 CC**；作者 schema 默认 **65**。
印相缺品红 ⇒ 相纸偏品红（红 + 蓝）⇒ 同一件事的两个面：
1. 肤色**偏红**：1289 脸 a\* 17.85（三位大师带 4~14）、色相 **25.3°**（带 49~63）；
2. 高光**偏品红**：我们 52 张原尺寸成片的按区 Lab `whi` 段 a\* **+2.69** / b\* **−2.03**，
   而三位大师的 `whi` 段全是**中性**（鹿井 +0.39/−0.01 · 増田 +0.39/+0.95 · 滨田 −0.79/0.00）。

【+8 的实测（1289，3120，`cc_m8` 档）】
脸 a\* 17.85→**10.65** · b\* 8.44→**14.52** · C\* 19.85→18.51 · 色相 25.3→**53.7** · 脸 L\* 72.1→73.1
⇒ **五项全部落进大师带**；高光段 R−B −30 → **+2**（大师带 −2~+10、中位 +3）。
⚠ 剂量都试过：+4 ⇒ 色相只到 38.4°（**还差**）、高光 R−B 仍 **−23**；
+15（作者默认 65）会把色相推过 75°（**过头**）⇒ **+8 是让肤色与高光同时到位的档**。
【代价，如实记】**整张彩度降**：C50 10.16→8.03 · C90 21.47→16.64（−23%）。
⚠ 当年记的"这一项要由颜色层 `grade.mix` 抬回来"**已作废** ——
**颜色层 10-10 整段删除了**（见 `config.py` 文件头）⇒ 彩度这一项现在**没有补偿层**，
要调就是调引擎（`dir_couplers` / 卷 / 纸）。依据见技能 §186。
