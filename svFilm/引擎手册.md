# 二、引擎的关键语义

```
★ `{"mul":k}` 乘的是**预设自己的基值**（不是上层解析后的值）
★ 层序：`_scene_engine["*"]` → `_stock_engine[<预设>]` → 轴层（**后者盖前者**）
★ `overrides` 的键名 = **运行时属性路径**（`simulation.print_exposure` ⇒ `enlarger.print_exposure`）
★ **改 exposure 的那一层 = `exposure.py` 的 `ev' = (1-w)·ev + b`**
  ⇒ 「逐图算印相曝光」**只能在这层做**；`print_exposure` 是**整卷常数**，加一层 = 重复计数
★ `film_format_mm` = 画幅**长边**（mm）⇒ 70 vs 36 ⇒ 三条空间族 σ_px **×0.514**
★ `film_format_mm` 语义 = `max(图长边)` ⇒ **裁图后只是近似**
★ ★★ **`presets.render()` 裸调不读 `targets.json`**
  ⇒ 生产路径 = `targets.scene_engine(sc, stock, cfg)` 之后作为 overrides 传入
★ ★ **`overrides` 必须整份传**：只传"要改的那根"会让 `density_curves_morph.active` 丢
  （它只在 `_scene_engine["*"]` 里是 True）⇒ 整根 morph **静默死掉**
```

## 场景覆盖的四层与三种值写法（`targets.scene_engine`）

```
★ 层序（**越具体越靠后，顺序不能反**）：
  ① `_scene_engine["*"]`（全局兜底）→ ② `_stock_engine[<预设名>]`（按预设基值；**当前为空**）
  → ③ `_scene_engine["<轴>=…"]` / `"<轴>=*"`（按场景）→ ④ `lighttype=<光型>`（**最后、优先级最高**）
  · 反序的代价：把 `"*"` 放后面会把预设基值**静默盖掉**（表现 = "明明写了却不生效"）
  · `"*"` 为什么必要：`"<轴>=*"` 只在**该轴判出了值**时才命中（轴为 `None` 时整轴跳过），
    而"判不出光位"很常见（没主体 / 人检不出）⇒ 那些片一条都不命中

★ 三种值写法（语义**不同**）：
  · **标量 / 列表** = 绝对值，直接覆盖
  · **`{"add": Δ}`** = 在**前面所有层算出的值之上加** Δ（老契约：基准必须已在前面的层里）
  · **`{"by": "deg_x", "delta": Δ}`** = 在**基线之上**再加 `Δ × 程度量`（程度量 0~1，来自
    `scene.classify()` 的 `raw['light']`）。★ 三条性质：**连续**（无台阶）· **耐判据换代**
    （量平滑移动、不整批换人）· **弃权 = 安全侧**（量拿不到 ⇒ 乘 0 ⇒ 什么都不加）。
    ★ `{"by"}` 的基准**允许落到预设基线**，`{"add"}` **不允许**
  · **`{"mul": k}`** = 乘在**该预设的基线**上；只有传了 `stock` 才解析得动，`stock=None` 时
    原样返回 ⇒ 下游 `presets._render_locked` **当场报**"字段路径走不通"（**故意的**）

★ **形状必须一致，否则当场抛**：`halation_strength` 这类是**每通道一个值**（0~1 的元组）
  ⇒ 给标量会**默默改掉 R:G:B 比例**（"看着生效了、其实改的是另一件事"）；
  标量配标量、列表配列表（长度也要一致），两处累加点（`_acc` 与最终落地）都要查

★ **第一原理**：**任何「读图像统计量 → 反馈全局参数」的规则必然振荡**（没有不动点）
  ⇒ 覆盖只能是"**按场景选中预先定好的值**"，不能是"按量闭环调节"

★ **两个静默失效点**（都修过了，别再犯）：
  · `targets.load()` 原先是**进程内永久缓存** ⇒ 同进程改 `targets.json` **不生效且不报错**
    ⇒ 改文件指纹 `(mtime_ns, size)`（`mtime` 秒精度、同秒两次会漏判；`size` 兜 `os.replace`）；
    **保留 dict 身份**（`clear()`+`update()`）；文件缺失 / 读到半截 ⇒ **当场抛**
  · `pipeline` 的渲染缓存 key 原来**不含靶** ⇒ 改了 `targets.json` 仍命中旧缓存 = "拧了没反应"
```

## ① `film_render.dir_couplers.*`（9 个矩阵元 + `amount`；密度依赖）

```
★★ 作者原话（`spektrafilm/README.md（作者仓库）:107-111`）：
   「data-sheet curves are really not enough ... The key is to understand that film emulsions
     contain couplers ... these are very important for achieving the desired saturation」
   ⇒ ★ 他说"最关键的一步 = 耦合剂"，目的 = "想要的饱和度"
   ⚠ 但他**没写 "most important"** —— 引用时不许升级措辞
★★ 而 9 个矩阵元是 TODO（`params_builder.py:175`）：
   「gamma_interlayer_b_to_rg = (0.168, 0.226)  # just eyeballed, optimize!」
   ⇒ ★ "目标已写、还没做" ⇒ 我们那条把 9 个矩阵元**原样用引擎默认**（零实测）
★★ `inhibition_interlayer` 与 `amount` 在 Lab 响应空间**夹角余弦 0.9905**
   ⇒ 机制① 的"强度"只有**一个**自由度；三条的 raw gamma 字段逐位相同（形状也没分家）
★ 已做对的：负片端耦合剂在跑、**相纸端不跑**（`_apply_print_specifics()` 空函数）
   —— 与作者设计一致（`README.md:95-98`：相纸端"no couplers in this case"）
```

**★ 主旋钮 = `couplers.amount`，而它不是"只动彩度"的旋钮：**
```
★★ **颊色相响应 増田 +40.7° / 单位 amount**（鹿井 −32、滨田 ~0）⇒ **连符号都不同**
★ 増田 +0.10 的 Δ`b*−a*` +2.07 里 **只有 +0.43 是幅度、+1.85 全部来自色相**
★ 它对**亮度 / 白端 / 中性轴**基本不动（这一部分成立）
★★ **对 `A4_b`（中/亮）杠杆 ≈ 0**（走一整档只值分辨力的 0.2~4.1%）
   —— 机制：纯标量倍率**同乘分子分母**，比值不动
```

**★ "改色相配比"两条路：**
| 路 | 斜率 | 代价 |
|---|---|---|
| **`film_gamma_factor` 3 元组** | **+145 / 单位 \|dg\|max** | **ΔC\* ≈ +0.27（≈免费）** ⇒ ★ **首选** |
| `couplers.amount` | +19.9 / 单位 | **颊 C\* +2.3** ⇒ **贵 8 倍** |

## ② 逐通道密度曲线（`gamma_factor_{rgb}` / `density_curve_gamma` 3 元组）

```
★★ **两入口不是同一根旋钮**：
   · 印相端 = **绕枢轴旋转**（da\* 变号于 L\*≈54）
   · 胶片端 = **单瓣**（da\* 全程同号、L\*10~80、两端趋零）
★ 但**两入口都不是"暗端选择性"**：暗瓣/其它档 = 印相 ≤0.78 / 胶片 ≤0.51
  ⇒ A2（"只推暗端"）**两入口都做不到**（三通道近共线，硬解要 |dγ| ≈ 7.7，物理不可行）
★ `presets.py:383` 的 `float()` 已放开 ⇒ **3 元组可落地**（标量或 3 元组都收）
```

★★ **实测：这一路不是"中性轴黄绿"的刀**（10-16，生产预设 11 张整批的 5 条可判系统性失败上试的）
```
背景：新链（portra_400 + portra_endura + pe 0.62 + lc 0.80）下，中性轴的系统性失败为
  `NA 20_40/60_80/80_100 b*` **偏高（黄）** 与 `NA 40_60/60_80/80_100 a*` **偏负（绿）**
  ⇒ 都是 **A 类**（内容弱依赖、可对他的绝对带）

实测（5 臂 x 2 张，`film_render.density_curve_gamma` = 负片端逐通道 γ）：
  · **γ_B +0.08** ⇒ `NA 80_100 b*` **3.83 → 0.97 ✓ 进带**（黄确实被压），
    ⚠ 但同时 `NA 20_40 a*` **−2.41 → −5.72**、**脸 C\* 17.9 → 26.4** ⇒ **不是干净的刀**
  · **γ_B +0.16** ⇒ 中段出 **`nan`** ⇒ ★ **越界，不可用**（记下这个边界）
  · **γ_R +0.08** ⇒ `a*` 反而更负（−2.41 → −6.10）—— ★ **与"γ↑ ⇒ 印相该色↑"的朴素推导相反**
    ⇒ 因为**中性配平在灰上会抵掉一部分**（DB 中性随 (纸,光源,底片) 走）⇒ **净效应会翻号**
  ⇒ ★★ **规矩：这一路的符号不许推，只能实测**；且要同时盯 `脸 C*`（它是第一个被带崩的量）
```

★★★ **印相端那一入口 = 中性轴的刀**（10-16，实测确认它的"绕枢轴"形状真能用）
```
对象：`print_render.density_curves_morph.gamma_factor_{red,green,blue}`（默认全 1.0）
作用：逐通道乘在相纸密度曲线的 γ 上（`:26-32`）⇒ 与 `gamma_factor_fast/_slow`（趾部/肩部）相乘

实测（生产预设 portra_400 + PE + pe 0.62 + lc 0.80；NA = 中性轴五档，带 = 大师逐图 [P25,P75]）：
  · **`gamma_factor_red` +0.10** ⇒ `NA 0_20 a*` **−0.68 → −1.89 ✓ 进带**、
    `NA 80_100 a*` **−0.37 → −0.35 ✓**；**−0.10 完全镜像** ⇒ ★ **"绕 L*≈54 旋转"实测成立**
  · `gamma_factor_red` **+0.15** ⇒ 11 张整批 **22 条落带 5 → 9**
    （新进带：黑端收窄比 · 白端收窄比 · `NA 0_20 a*` · `NA 60_80 b*` · `NA 80_100 a*` · 脸 a*；
      代价：`NA 20_40 a*` 与 `脸 C*` 掉出 —— 脸 C* 从 ✓ 变 ↑）
  · `gamma_factor_blue` +0.10~0.20 ⇒ 降 `b*`（黄）且**脸 C\* 不动** ⇒ **比负片端那根干净**
  · `gamma_factor_green` +0.10 ⇒ **错方向**（暗端 a* 上升、亮端更负）
  · ★ **不要叠 `gamma_factor_fast`**：它把 `脸 C*` 推到 22（1231 到 29，超出带顶 26.06）
★ 结论：**改中性轴的黄绿，走印相端逐通道；负片端同一路不是刀**（见上一块）。
  ⚠ 两个入口的形状不同正是判据：印相端**绕枢轴**（能用）、负片端**单瓣**（会把 a* 整段拖走）
```

# 四、空间族（颗粒 / 柔光 / halation）

## ★★★ 验收 = 「**物理方向 + 目检**」，**不是"像大师"**

```
★★★ **大师是【真实胶片机】拍的，我们是【数码相机】拍的** —— 两条不同的链**
   · 大师的颗粒 = 乳剂里真实银盐的随机簇（拍摄时**记录**进去的）
   · 我们的颗粒 = 引擎在数码图上叠的噪声（后期**造**出来的）
   · halation：大师是"光穿乳剂→片基背反射→记录"；我们是**模拟**
   ⇒ ★ **来源不同 ⇒「对上去」本身没有定义**
★ **物理/器材事实只提供【方向】**（他用了柔光镜 / 卷抗晕弱 / 画幅 6×7 / 逆光 ⇒ 晕明显）
   ❌ **不提供【值】** —— 他的 "Pro-Mist 1/8" 是在他的镜头+他的胶片上；
   我们设同档 = 在数码图上叠加 ⇒ **效果不等价** ⇒ 值必须在**我们自己的数码链**上定（试 + 目检）
★ ★ 空间族是**唯一"可以不靠大师数字就正当定值"的一族**（依据在**器材**里，不在成片里）
★ ⚠ **必须【全长边】判**（2048 上高频已被缩图抹掉）
★ ⚠ **它会串到颜色**（halation 是带色的）⇒ 改它要同时看肤色 / 脸−臂 / 中性轴
```

## ★★ 已测出的物理事实

```
★★ **颗粒幅度 vs 亮度：中调最响、两端归零**（实测峰 L*45–60，解析峰 L*30–45）
   ⇒ **我们原生像物理** ✓（机制：σ(D)=√(D(Dmax−D)/n) × 影调斜率 ⇒ 两头都塌）
   ⚠ 差异：真实"最粗"在**负片最薄处（阴影）**，我们在**输出中调**（落点由冲扫斜率决定）
★★ **颗粒功率谱：原生是白噪声（−0.162 = 平）** ⇒ **满足"大于乳剂相关长度上谱应平"** ✓
   · 交付物上的陡降（−1.355）是 `grain.blur` 做的，**形状随口径变** ⇒ 不是颗粒的内禀结构
   · ⚠ **"真实银盐是团簇"这个假设，二手材料不支持**（Selwyn / 专利 CA2309002A1：
     "grain noise seems to be white noise blurred by the film scanner PSF"）
★ **halation**：`σ_h` per-channel ⇒ G 收窄到 0.45σ_R
   · 交付尺度 R/G：65 µm 处 **7.2** → 130 µm 处 **3.6**；**贴边 R/G = 1.35**（由幅度比 8:2 定死）
   ⇒ 0.45 **只改"多快变红"，改不了贴边那一瞬**
★ **画幅**：36 → 70 ⇒ 三条空间族 σ_px **×0.514**（已验）
```

## ★★ 两条不可复现的事实（**取差前必读**）

```
★★★ **`print_render.glare` 永不可复现**
   · 根因：走 **numba RNG**（`fast_binomial` / `fast_poisson` / `fast_lognormal_from_mean_std`），
     **`np.random.seed()` 管不到**（numba 0.67 无 `_init` 钩子）
   · 实测：**同参两渲 max|Δ| = 22 码**
   ⇒ ★★ **任何"同参两渲取差"必须先关 glare**
★★★ **"同参两渲差 = 纯颗粒"是错的**
   · 整链同参两渲的**负片密度场本身就不一样**（颗粒模型入参 hash 变了）
   · 量级：**6264** 上密度差只有 1e-4（颗粒 0.132）⇒ 可忽略
   · ⚠ **2048 上与颗粒同量级** ⇒ **不许用 2048 的颗粒绝对值**（只能当方向）
```

## ★★★ 量法铁律

```

| `white_correction` / `black_correction` | `CR:116-150`；两者全关 ⇒ `CR:121` 直接返回 | False / False | ★**门控**：只开白 ⇒ `black_level` 用实测 `_y_black`；只开黑 ⇒ `white_level` 用实测 `_y_white`；全开 ⇒ 用设定两级；再 `m=(w−b)/(y_w−y_b)`、`y'=clip(m·y+q,0,1)` ★另有 gate：`scan_film`+负片不校正 |
| `white_level` / `black_level` | `CR:26-27,154-160`：**先按 sRGB 解码**再当线性 Y 目标 | 0.98 / 0.01 | ↑白 ⇒ 白端更亮；↑黑 ⇒ 黑位抬（**0.98 → 线性 0.955；0.01 → 1e-4**）|

## 9.9 `io.output_gamut_compress`

| 参数 | 作用形式 | 默认 | 说明 |
|---|---|---|---|
| `active` | ★**只读属性**（`GC:246-248` = `algorithm != "off"`）| — | **写不进去** |
| `algorithm` | `GC:196-198` 六值，dispatch `GC:1217-1240` | **cam16ucs** | `off` ⇒ 原样输出（可越 [0,1]）；`aces_rgc` ⇒ 只在目标 RGB 里做 per-channel knee；其余四个（oklch/oklrab/jzazbz/cam16ucs）走感知极坐标压缩，**缺 `output_color_space` 会抛错** |

| `lightness_compression` | **同一 knee**，但作用在 `L_norm = L/L_white`（`GC:705-738`）；**单边、黑锚定**（L<0 不动）| (0.7,1.0,2.2) | `t↑` ⇒ 更少高光被压（亮部更"顶"）；`p↑` ⇒ 拐点更硬 ★**不在 GUI**，只能 JSON/API；★`aces_rgc` **不吃它**；★`L_white` 随空间变（oklch/oklrab=1.0 · jzazbz=D65 Jz · cam16ucs=Jp_w≈100）|

## 17.2 ★★ 两条**可以直接复用**的标定方法

```
① **中性/白平衡标定的前提必须钉死**（vkdt 的做法）：couplers 开 · `g film=1.0` · preflash 关 · **glare=0**
   ⇒ 否则"中性灰不平"里混进了 couplers 与眩光的贡献（我们这边还有一条：`print_render.glare` 不可复现）
② **y/m 中性点用最小二乘解**（ART 的做法）：拿 18% 灰当输入，解一对 (y, m) 让输出落到中性；
   `bounds ±10 CC`、起点 (0,0)、`max_nfev=20`
   ⇒ 比"手扫 + 看哪档顺眼"快一个量级，且**可复现**
   ⚠ 我们这边必须先切到 `neutral_print_filters_from_database` 的同一口径（否则解出来的是"相对谁"的中性）
```

## 17.3 社区踩过的坑（原话要点 + 出处）

```
★ **couplers 的扩散默认太锐**：「默认的 20/200 让图看起来像**烤过**；用 **5/20** 仍拿到颜色的好处」
  （pixls.us 讨论帖）⇒ 呼应我们 `diffusion_size_um = 20`（引擎默认），**tail 200 从没被设过**
★ **couplers 会把黄/橙推向绿侧**：某些卷上"作用很小，却把肤色推到我讨厌的地方" ⇒ 改它必须复量肤色
★ **DIR couplers 滑杆上限 1.0**（darktable）：因为要能从实测曲线**反解**；"某些卷远早于 2.0 就崩"
  ⇒ 我们这边 `amount` 别做大跨越（AGENTS §二.5 也有"别横跳"）
★ **scanner 白校正"疑似有 bug 却被依赖"**：社区 preset 里普遍开着 —— 与我们"钉 True"的处置同向
★ **输入白平衡最难搞**（尤其反转片）："一直在跟输入白平衡（D65）斗"
★ **想要干净数码观感 ⇒ 关 grain + halation**，此时会**暴露 DIR couplers 造成的硬局部对比/锐化**
★ **到不了 100% 白 = 高光落在肩部压缩；到不了 100% 黑 = 趾部密度饱和 + 扫描眩光抬黑**
  ⇒ 我们"白端只有 89.5 / 黑端贴不住"这两个症状，**社区认领的是同一件事**
★ 社区 preset 的两个共同设定（pixls.us 分享帖）：**film format 全用 65mm**（"grain 手感对，35mm 太多"）·
  **scanner/white correction 全开** · 多数 **preflash 0.03**
  ⇒ ⚠ 这两条是**别人那条链的观感结论**，只能当方向（我们空间族的验收本来就是"方向 + 目检"）
```

## 18.1 他给每个旋钮的**语义**（README 原话要点）

```
★ `exposure_compensation_ev` = **改负片的曝光**

  （三个通道各一套控制 —— 即 RGB 三个数）

# 十、自检探针（合成图）的口径与仪器事实

> 这一节讲**我们自己的合成探针**（`selftest.py` 里那几张考卷）—— 它量的是"链的传递函数"，
> 与大师语料无关。★ 必须记住它的**仪器误差**，否则会把"探针读数"当成"真值"。

```
★ 探针电平代表**真实工作点**，不是随便定的：
  · `_PROBE_SCENE_GAIN = 0.2018`（探针本体整体增益）
  · `_PROBE_ABS_ROWS = 16`（图表顶部 16 行**不乘增益**，重建一条 0→1 的绝对灰阶斜坡）
    —— 锁 ①②③④⑧ 问的都是"纯白进去出来是不是白"这类**绝对输入电平**问题
  · 口径：`io.load(raf, 1024)` → 长边 256 最近邻预览 → ProPhoto 线性 Y 的**全图均值**。
    52 张真实 RAW：meanY P10 0.0439 / **中位 0.0693** / P90 0.1400；`s=log2(meanY/0.184)` 中位 **−1.41**
  · ★ **硬事实**：含全量程灰阶的图表**不可能**同时拥有真实照片的 meanY
    （灰阶一项就贡献 ~0.10 > 真实中位 0.0693）⇒ 只能把斜坡压到 **1.78%** 面积
★ **链是逐像素的**：探针整体乘 1.0/0.5/0.2135/0.1067（跨 3.2 档），`输出L* ~ 输入L*`
  是**同一条曲线**（预测 vs 实测 max|Δ| = 1.11 L*）⇒ 探针电平**不改传递函数**，
  只决定"锁采在输入轴的哪一段"
★ ★★ **探针几何有 ~3.2 L\* 系统偏置**（暗端）：读数比真实照片同电平低 3.2 L*
  （绝对灰阶条左右是降了电平的暗图块 ⇒ glare 比真实场景少）
  ⇒ **②④ 那几条锁钉的是"探针读数"，不是真值**
★ **探针挂在"曝光主人"下游** ⇒ **每改一次曝光，这几条锁都会漂一次**；
  实测余量：②「54.3±4」在 `w=0.6` 之后只剩 **0.5 L\***
★ **合成图表的 R1 恒低于真实照片带**（同引擎同一天）：灰阶斜坡 0.543 ｜ 16 级灰块 0.466 ｜
  黑白灰三块 0.309 ｜ 整张图表 0.395~0.409 ｜ 真实照片批（生产路径）0.689/0.863/0.916（n=11）
  ⇒ ★ **探针值不许拿 `[0.538,0.837]` 当界判**（那是**真实照片**口径的界）；
  要用探针判方向，得**另定一套探针自己的界**
★ **同内容配对的量级**（18 张分层 / 1.5 亿像素 / 同像素：真实 RAW ↔ 同一张的富士直出）：

  | 输入 RAW | 旧链 | 锚落地后（我们） | 富士直出 |
  |---|---|---|---|
  | L\*21.2 | 47.5 | **57.5** | 60.5 |
  | L\*53.3 | 86.5 | **91.5** | 88.5 |
  | L\*70~100 | 92.5~93.5 | **93.5（顶死）** | 94.5~**99.5** |

  ⇒ **白端确实还差约 6 L\***
★ **中性轴的病因在上游（相纸/光源/底片），不在颜色层**：把 `zone_abs`/`sh_abs`/`hi_abs` 全清零，
  中性轴几乎不动。⚠ 配方允许"暗部偏青蓝" ⇒ L20 单独放宽
★ ⚠ **已证否**：「合成探针的肤色块彩度倍率」**不能当风格验收标准** ——
  探针只量"变换对探针的放大倍率"，**它不知道大师的输出水平该是多少**（范畴错误）
★ **成本**：一张探针 = 一次全链渲染，本机 ~3.6 s
```

## `{"add": Δ}` / `{"by": 程度量, delta: Δ}` 的两条硬约束

```
★ `{"add": Δ}` **必须有一个数值底**（先在 `"*"` 层给基准），否则静默忽略；
  多轴命中时是**相加**（不是后匹配的轴盖掉前面的）—— 组内单调实测：
  正逆光+平 69.77 < 正逆光+正常 74.62 < 正逆光+大 78.09

  ② 基准是**逐通道元组**时（如光晕幅度在引擎里是 0~1 的元组）Δ **必须给列表**，
  给标量会默默改掉 R:G:B 比例

# 十一、量尺定义（评分卡 / 局部对比 `lc` / 内容关系）

```
★★ **局部对比 `lc` 的冻结定义**（改定义 = **必须 bump `LC_VERSION` 并重算大师带**）
  · **量什么**：**带限 RMS 对比度**（Peli 1990, JOSA A 7(10):2032）：先带通、再取 `σ/L̄`
    —— 不是逐像素梯度、不是局部标准差窗口；实现 = **DoG 带通**（拉普拉斯金字塔一层）
  · **在哪量**：`measure()` 里已经在算的那张 L*（与卡片其它项同一像素数组、同一把重采样）
  · **尺度锚在画面宽度**，不是像素：归一到 `LC_SIDE_W = 1080`（**只缩不放**），
    频带 = **宽度的分数** `周期 ∈ [W/64, W/16]`
    ⇒ ★ **不锚在"µm / 片幅"**：大师的参照是 xhs JPG、**片幅未知** ⇒ 锚在片幅上两边对不齐
  · **频带为什么是这个**：大师源是 1080 宽的小红书 JPG（强压缩）⇒ 细于 W/64（≈17px）两边不可比；
    粗于 W/16（≈68px）不是"局部"了（那是 `span` 管的事）
  · **归一**：`lc = 100 × std(band) / mean(L*)`（整张均值当 `L̄`）⇒ 无量纲、可跨尺寸比
  · **形状**：另报 4 个倍频程子带 `lc_b1..lc_b4`（两个 `lc` 相同的片子，细/粗带分布可以完全不同）
  · 大师带在 `data/targets.json` 的 `_lc_band`（1076 张）；**缺失 ⇒ 该项只报不打分**
★★ **内容关系三级**（`targets.json` 的 `_provenance`）：
  `cross` 跨内容（大师语料 vs 我们）⇒ **只能当线索**；`same` 同内容（合成图 / 同片配对）⇒
  才可作**对照 / 验收**；`phys` 物理或上游依据
  ★ 依据：Adobe US9857953（完全迁移统计会"产生伪影、值被拉伸得过于激进"）+
    Reinhard 2001 的已知局限（**无法建立空间/语义对应**，内容差大时退化）
★ ⚠ **已证否**：一把没有正式定义、也没进评分卡的尺子**不能用来定值**
  （`diffusion_size_um` 60 vs 作者默认 20 这个 3 倍偏离，当初就是照"正中靶 1.10"定的；
  09-30 同一"定义"却测出 3.33 ⇒ 自己写「1.10 无法复核」）
```

# 十二、直方图规格（`hist.py`；LR 画法）

```
★ **四条叠一张**：最上**亮度**（灰），下面叠 **R/G/B** 三条彩色；**加色混合**（不是 alpha 叠加）
  ⇒ R+G 黄 · G+B 青 · R+B 品红 · 三条齐 灰白（实现 = 三通道各自填充后逐像素相加截断）
★ 横轴 = **显示域** 0~255（**不是 Lab L\***）；LR 官方：直方图"假定 gamma ≈2.2、用类 sRGB 响应曲线"
★ 横轴分 5 区 `Blacks/Shadows/Exposure/Highlights/Whites`：⚠ LR 里是**跟随滑块的软区间**，
  本项目按**等分 20%** 画 = 画法近似（图上已注明）
★ **两端裁切三角**：判据 = **任一通道到达端点**（与 LR 一致）；颜色 = **加色混合的"被裁通道"色**
  （单通道→该色 · R+G→黄 · G+B→青 · R+B→品红 · 三通道→白）
  ⚠ **已证否**：`luma == 255` **不是**"高光被裁"（它数的是纯白像素）——
  实测鹿井参照的**蓝通道裁了 0.227%**、老判据报 **0.000%**，三角根本不亮
★ **纵轴固定 ⇒ 跨图可比**：满格 = 单档占画面 `YMAX_RATIO = 7%`，再开 `Y_GAMMA = 0.45` 幂压缩
  （来源：原尺寸量 242 张 ⇒ P50 2.2% / P90 6.7% / 最大 41.5% ⇒ 取 7% ≈ P90，
  约 90% 的照片不会被削平）。★ **刻意不走 LR 的"自适应"路**（两张图就没法比高矮）；
  代价：**高度不是线性比例**（图上"半高"实际约 1.5%）
★ ⚠ **缩放会改直方图**：同一张有颗粒的成片，缩到 400px 单档峰值 **8.68%** / 900px **5.79%** /
  **原尺寸 3.34%**（2.6 倍）；有颗粒的图受影响远大于平滑图
  ⇒ ★ **跨图比必须都用原尺寸**
★ **16 位不能静默降位**：PIL `.convert('RGB')` 会把 16 位砍成 8 位 ⇒ 0.0x% 量级的端点判断直接失效
  ⇒ 8 位按 /255、16 位按 /65535
★ **档位口径**：0~1 显示值 → 0~255 必须**四舍五入**（与 `color.display_to_u8` 同口径），
  不能用 `.astype(int)` 截断（否则"喂浮点数组"和"喂 8bit 成片"落进不同的档）
★ `waveform()` 的分工：直方图只答"**有多少**"，它答"**在哪里**"
```

## 13.2 已证否（别改回去）

```
❌「三通道都 ≥ 0.995 才算爆」= **死轴**：显示域 99.8 只是 sRGB 把 1.0 以上一律压到 255 的假象
   （那 4 张线性最大值只有 1.261、三通道同时贴顶的像素 0.000%）⇒ 正解是**线性域通道最大值 ≥ 1.0**
❌「最亮块在主体之外」几乎没有区分力（真实照片的最亮块几乎总在主体外）⇒ 区分「光源 vs 渐变」要用 `spike`
❌「有一条贴边就整张弃权」⇒ 只有**所有**证据都弱才兜底（否则 `E_tb=−54.8` 那种确定片会被判掉）
❌ 单向证据用 `abs()` 守卫（`E_bg` 只有正、`E_tb` 只有负支持逆光，只有 `E_lr` 双向）
❌ 把"过曝区在主体外"当因果证据：掩膜（头发/衣服常很暗）会污染 `E_bg` ⇒ 因果**必需**、支持只能放大
❌ **光型不用来选测光区**（41 张有脸的、零渲染）：逆光下"对人测光"确实好于 `matrix`
   （`r2(s_颊~s_M)` 0.504 vs 0.116），但**缝隙光下同样是"对人 / 对脸"更好**（0.422 / 0.826 vs 0.258）
   ⇒ 测光区仍按"**脸占比门限 + 脸档**"决定
❌「缝隙光一律退回 `matrix`」**不成立**：那条只有 **n=2**，n=10 的跟踪度复验**不支持**
```

## 13.3 光型（`lighttype.py`）：为什么必须单独一类

```
★ 量：`Y = RGB_to_XYZ(sRGB, 解码)[...,1]`（线性化 Y）
  · `ratio_p` = 人掩膜内 Y 均值 ÷ 整张 Y 均值（**人相对整张亮不亮**；掩膜内 <200px ⇒ None）
  · `ratio_f` = 脸内 Y 均值 ÷ 整张；`spread_f` = 脸内 (P90−P10) ÷ 脸中位
  · `hot` = FACE 皮肤掩膜内 `Y > 1.6 × 脸中位` 的像素占比 %（**脸上斑驳 = 缝隙光的直接证据**）
★ 判型（顺序即优先级）：`hot ≥ 15%` ⇒ **缝隙光** ｜ 否则 `ratio_p < 1.0` ⇒ **逆光**
  ｜ 否则 `ratio_f > 1.15` ⇒ **面光** ｜ 其余 ⇒ **中性** ｜ 取不到 `ratio_p` ⇒ **未知**
★ **为什么单独一类**：缝隙光（树叶/栏杆/窗户漏下的斑驳光）在主体身上是**亮斑 + 暗块并存**
  ⇒ 平均落在哪边都不对；而它与 `back` 轴**互补** —— `back` 比的是"主体 vs 身后背景"，
  缝隙光在**背景那侧看不出区别** ⇒ 会被 `back` 判成"面光/顺平光"兜底档
★ 它**不是** `scene.AXES` 的一轴，但进 `scene.key`（第 5 个 token），
  并在 `scene_engine()` 里作**最后、优先级最高**的覆盖层
★ ⚠ 阈值（15% / 1.0 / 1.15）是 **n=29 上定的绝对阈值** ⇒ **跨链不可移植**；
  同文件里的 `spread_f`（比值量）算出来却没人用
★ **量级（本批素材口径）**：`overwhite` 命中很干净（52 张里 6 张 = 11.5%，其余 0.0%）；
  `deg_source` 覆盖率 ≈ 0（通道建好、数值待"强光源"素材）；`deg_reflect` 只输出不驱动参数
★ ⚠ **判据量的是「解码后」那张图，不是成片**：两域亮度差得远（解码后中位 L\*≈21、成片≈61）
  ⇒ **阈值必须按"解码后"那档标**，否则所有片子落进同一个桶
```

# 十四、机型表与 baseline exposure（`cameras.py`）

```
★ **为什么需要它**：相机厂商**故意让 RAW 欠曝**，把"把中点抬回来"留给转换器做
  ⇒ DNG 规范里叫 **baseline exposure**；Adobe 系是**静默**做掉的；
  RawTherapee 官方文档：目的就是**让亮度匹配机内 JPEG**。
  LibRaw 作者原话：相机灰点通常只在满量程的 **7~12%**，要抬回 **18%**，
  「0.7~1.5EV gray point move is usual」，而且**要用一条自定义 tone curve 把高光压下去**
★ **表里两样东西，别混**：
  · ① `baseline_ev` = 与**机型**绑定的常数基线（富士基底 **0.72**；未知机型 ⇒ **0，不猜**）
  · ② 富士 DR 档的**额外**欠曝 `FUJI_DR_BIAS = {100:0.0, 200:1.0, 400:2.0}`（**不含**那 0.72 基底）
    —— 来源：darktable lua `fujifilm_dynamic_range` 实测 `RawExposureBias` 总量
    100/200/400 DR = −0.72/−1.72/−2.72 EV，减去基底 ⇒ 0/1/2
  · 最终补量 = `baseline_ev + FUJI_DR_BIAS[dr]`；若机身写了精确的 `0x9650 RawExposureBias`
    ⇒ **直接用那个值**（它是**含基础偏移的总量**，不要再加 `baseline_ev`）
    ⚠ 但**代码里目前没有这条分支**（`lookup()` 只返回表项）⇒ 覆盖逻辑在已删的 `rawmeta` 路上
  · 键 = `(make, model)` 小写；只写 `model` 也能命中
★ **怎么填**：`python -m svFilm.cli calib <RAW+JPG 同名对>` 打印建议值；
  优先拿"曝光标准"的样张（中灰落在 18%），**别拿夜景**
★ **量级（口径 = 同名 RAW+机内 JPG 配对）**：X-T30 III + DR400 合计 **+2.72 EV**
  （16 张批量中位差 −3.8 档 → **−0.84 档**）；X100VI DR400 零点 **+2.18 EV**（与 +2.184 互相印证），
  **高光端增益从 ×9.79 滚回 ×1.0**（自带肩部）
★ ⚠ **同一台机身 DR 会变**：整库 759 张里 DR100 **118** / DR200 **66** / DR400 **575**
  ⇒ **必须逐张读**（按机型写死 DR400 会错掉那 184 张）
★ ❌ 已证否：「X-T30 III 解码本身已含 0.18 中灰标定 ⇒ `baseline_ev = 0`」——
  当时只看了**两张**样张，样本太少把结论带偏
```

# 十五、svFilm 这一层的机制（测光 / 后处理 / 空间缩放）

## 15.1 测光链（"看哪里"唯一能改，且不许闭环）

```
★ 引擎的锚是**写死的 `0.184`**（`filming.py:126`）⇒ **不读图 ⇒ 不振荡**；
  而任何「读图像统计量 → 反馈到全局参数」的规则**必然振荡**（没有不动点）
  ⇒ ★ **要改"人好不好看"，只能改「看哪里」（输入侧），不能改「看多少」（输出侧）**
★ **`subject`（测光看人）实测**：37 张复验，逆光组脸 **+17.6**、**变差 0 张**，自带伺服
  （+21.0 / +13.7 / +8.6 / +3.7 / **−1.8**）；对照"全局提亮"那条 52 张：中位没变、
  `>75` 的从 2 张炸到 **14 张**
★ **人掩膜口径**：`person.person()` 是 **0~1 浮点置信度** ⇒ 占比必须按**阈值 0.5** 算
  （`mean(m>0)` 在浮点掩膜上**恒等于 1.000**）。实测分离度：合成图（没人）**0.000** ｜
  真实照片 **0.241~0.485**。**守卫区间 [0.005, 0.70]**：超出即**弃权**并留 stderr 痕迹 ——
  合成图纯白/灰阶会让它输出**占比 1.000 的整幅掩膜** ⇒ 退化成"按整幅测光"而**结果看着还挺合理**
★ **有脸用脸**：`r2(颊 ~ 脸读数) = 0.890` vs `r2(颊 ~ 人读数) = 0.346`；**脸用二值 `>0.5`**
  （软口径 `r2` 只有 **0.310**，比"人"还差）
★ **锚与人本的分工**：`EXPOSURE_ANCHOR_W = 0.6`（`ev' = (1−w)·ev + b`）——
  `w=1.0` 时 `ev'` 是常数、测光完全不进画面；`0.6` 让"看哪里"重新有效

## 15.2 后处理：`_post_scan` 的色度模糊（**当前在跑**）

```
★ 尺子「**色度/亮度锐度比**」= 高通 σ=1.5px 的色度能量 ÷ 亮度能量：
  **鹿井大师 747 张 0.60** ｜ **我们 1.03** ｜ 用户 LR 0.94 ｜ 相机直出 0.71
  ⇒ **我们比大师锐 70%**
★ 做法：在 **CIELAB 的 a\*/b\* 上**模糊 ⇒ **只动色度、不动细节**；
  σ 用**画面宽度比例**（`CHROMA_BLUR_W = 0.0015`，2000px ≈ 3px）
★ ⚠ 它是**减弱型效果**、失效时画面与直方图**都不报警** ⇒ `_post_scan` 必须
  "吞掉异常但留痕迹"（`stderr` + `_POST_SCAN_ERROR`）
```

## 15.3 像素键（绝对像素 σ）必须随渲染尺寸缩放

```

★ ⇒ ★ **判颗粒/锐度必须在全长边判**（2048 上高频已被缩图抹掉，量出来的绝对值不可用）
★ ⚠ **掩膜 / 尺寸换了必须重标阈值**（`SCENE_BACK_*` 那类）：
  掩膜从全身换成头肩（`person.py`）后，"某块基本在主体之外"的块变多 ⇒ `clip_blk_off` 系统性变大
```

## 15.4 halation 的绿层核（`HALATION_G_SIGMA_RATIO = 0.45`）

```
★ 物理：光晕**近处橙、远处红**（绿层只在返光最强处被推动 ⇒ 阈值非线性）
★ 而 `diffusion.py:72-75` 的 halation 段**三通道共用 σ** ⇒ `H_R/H_G ≡ a_R/a_G`、
  **与半径无关** ⇒ 模型**表达不出**"近橙远红"
★ 把 G 的核做窄 = 该非线性**在线性模型里的最佳替身**（G/R ∈ 0.4~0.5 ⇒ 取 **0.45**）
★ **能力边界**：紧贴边缘那一瞬间的比值仍 = `a_R/a_G`（归一化高斯的**边缘响应峰值 = a/2、与 σ 无关**）
  ⇒ 本旋钮改的是"**多快变红**"（过渡长度 = σ_G）
★ `halation_strength` 是引擎给 `('still','weak')` 的**物理基线，一个字都不动**
```

```

# 十六、模块级机制（服务 / 编排 / 入口 / 安全侧）

## 16.1 常驻服务与编排（`service.py` / `pipeline.py`）

```
★ **路由契约**：出图三支 `/render` `/base` `/export` 直接回**图片字节**（改参数 = 改 URL）；
  `/health` `/stocks` `/load` `/stats` `/list` `/scan` 回 JSON。**只绑 127.0.0.1**，零依赖
★ **`side` 语义**：不传 = 沿用已解码那份；给了别的尺寸 = **按那个尺寸重新解码**再跑链；
  `/export` 不传 = **原图全尺寸**。★ **换尺寸绝不复用另一尺寸的 Sample** —— 颗粒是物理量
  （同一块平坦区实测 2048 / 3000 / 原图 = **0.63 / 0.77 / 1.87**）
★ **三层缓存**：`_cache`（id→Sample，给 `/render`）· `_path_cache`（路径+尺寸+解码签名→Sample）·
  `_STAGES`（段缓存 = 胶片段及其之前的产物）
★ **解码签名 = `io.load_raw` 真读的四个键**（`PUBLIC_WB` / `_TEMPERATURE` / `_TINT` / `_COLORSPACE`）；
  `side=None` 必须映射成**独立键**（`'full'`），不能 `int(None)`、也不能与别的尺寸撞键
★ **段缓存键的契约**：`(film, _sample_uid, stock, shape, scene.VERSION, cfg 签名, overrides 键, 靶键)`
  · **必须含**「判据版本 + overrides + 靶 + config 签名」—— **漏一项就是"拧了没反应"**
  · 键由 `config.CACHE_KEY_PREFIXES` **前缀表驱动**（手抄元组必漏旋钮）
  · 构造失败**不许**退化成 `None`（那会让所有变体塌成同一个键）⇒ 用**带标记的哨兵元组**
  · ★ **场景必须在算键之前算**（键里要放它的结果）；放到键之后 ⇒ `NameError` 被 `except` 吞掉
    ⇒ **overrides / 靶从来没进过键**（静默）
  · `scene_engine` 失败**不许静默**：它一失败，全局 `"*"`（含 `morph`）整批失效、跨度立刻掉一截
    ⇒ 记进 `report['scene_engine_error']`
  · `_sample_uid` = 路径 + 类型 + 尺寸；**无路径样本用内容摘要（blake2b），绝不用 `id()`**
    （对象回收后 `id` 会复用 ⇒ 两个不同样本撞键、互相串图）
★ **量级（口径 = 700 长边）**：每次调用起进程 5.03 s vs 常驻 + 缓存解码 **1.45 s**（3.5×）；
  `io.load_raw` 一个人占全链 **57%**（JPG ≈0.36 s / RAW ≈2.3 s）；段缓存把 3.8 s 降到 **0.99 s**
★ **内存上限（实测撞出来的）**：引擎内部有个 `(81, 像素数)` 的 float64 中间量 ⇒ 40MP 要 **24.2 GiB**
  （进程当场死）⇒ `EXPORT_MAX_SIDE=3000`（6MP）= 56 s；条带包装后 7752×5178 = 380 s/张。
  **被夹住必须回 `side_clamped`，不许静默降级**
★ **Windows 平台事实**：`ThreadingHTTPServer.allow_reuse_address=1` 在 Windows 上走 **SO_REUSEADDR**，
  语义是"**可以抢**" ⇒ 第二个 `bind` **不报错**、两个引擎同时挂一个端口 ⇒ 故意关掉它 +
  启动前 `_port_taken()` 探测
★ **尺寸回执走响应头**（`X-Sv-W/H/Side/Side-Requested/Side-Clamped`）⇒ 探针/自检**不用解 JPEG**
  就能断言实际出的尺寸
★ ⚠ **`/stocks` 必须现读 `presets`**（写死风格名会在预设删掉后直接 500）
```

## 16.2 入口与工具（`io.py` / `color.py` / `paths.py` / `cli.py`）

```
★ **入口关口做三件事**（做完下游不许再关心"这张图是谁拍的"）：
  ① 解码（RAW 走 rawpy：线性、相机白平衡、关自动亮度；JPG 走 PIL）
  ② IDT：白平衡 + 色彩矩阵 + 黑白电平 —— RAW 由 rawpy 一次做完；**JPG 已在相机里做完、拿不回来
     ⇒ "显式降级"**  ③ 归一：对外只吐 `lin`（白点 1.0）与 `disp`（0~1）
★ **只留一条路：RAW → 场景线性 → 引擎**。为什么不自建入口提亮/逐张落点：
  · 预设的印相曝光 `pe` 是按**这个输入**标定的（线性中位 **Y≈0.056**）；自己那条会提到 **Y≈0.42**

  · **能在引擎里实现的就别自己再留一套**（入口提亮由 `camera.auto_exposure` 做；

★ **三个域**（全项目只允许这三个名字）：`lin` 线性域（白点 1.0、中灰≈0.18）· `disp` 显示域 0~1 ·

★ `l2s`（lin→disp）**不做上限裁剪**（便于检出错值）；`luma` 用 **Rec.709 权重**；
  **所有阈值判据统一用 `gray_of` 这把尺子**；`to_lab(disp)` 内部先 `s2l`（**入参是显示域**）
★ **存盘口径**：`quality` + **`subsampling=0`（4:4:4）** + `optimize=True`
★ **EXIF 陷阱**：`exif_transpose()` 之后**必须把 orientation 抹成 1**，否则存回去会被**转两次**
★ **产出路径规范**（不许在别处拼路径）：`<root>/效果debug/<YYYY-MM-DD>/<目的说明>/<文件名>`；
  ★ **更早的日期目录已整体挪到 `效果debug/_归档_2026-09/`** ⇒ 引用旧路径**必须带这个前缀**，否则死链
★ **CLI 输出命名铁律**：`dir` / `one` 的产出名带 **`_svFilm` 后缀** —— 不能叫 `<名字>.jpg`

  输出路径 == 输入路径时**跳过**（不覆盖原片）
★ `_expand` 按内置扩展名表扫描（`--glob` 只是占位）；**整棵跳过自家产出树**（`paths.TOP`）

## 16.3 人在哪 / 扫描段 / 交付约束

```
★ **`person.py` 只做"人在哪"**：给"人物整体位置"的**粗掩膜**，只服务**光位**轴
  （光位判据 = 「主体 vs 它身后的背景」⇒ 必须有"主体在哪"）。**不做人脸识别 / 认人 / 肤色调色**
★ **模型与开销**：`_models/selfie_multiclass_256x256.tflite`（输入固定 256×256）⇒ **~0.3 s/张**；
  对照 `birefnet-portrait` **~7 s** ⇒ 不要那个开销
★ **一次前向 6 类**：BG=0 · HAIR=1 · SKIN=2（身体皮肤）· **FACE=3（脸上的皮肤）** · CLOTH=4 · OTHER=5
  ⇒ 取第 3 类的**边际成本是 0**（**不是**"再跑一次人脸识别"）；用途**只限证据**
★ **已知短板（如实记）**：它是**视频会议自拍（头肩）**模型 ⇒ 全身 / 人小 / 白衣服低对比会整块漏，
  也会**多框**（实测：某张把人的占比从 11.6% 涨到 57.5%）
  ⇒ **人小 / 只有背景 ⇒ 弃权（`None`，`back` 写 `-`）是合法输出，不许硬给"顺平光"**；
  只检出头肩时方向仍然对（逆光因果 = "主体欠曝、背景过亮"）
★ **线程/平台**：`ImageSegmenter` **不是线程安全的** ⇒ 建实例与调用都串行化；
  **mediapipe 只吃 ASCII 路径**（本工程路径含中文）⇒ 复制到临时目录再用
★ **`scanfx.py` 为什么要存在**：上游 `color_reference.py` 在"扫负片"这条路**故意不做黑白校正**
  （注释原文 "do not correct negative film scans"）—— 理由合理：**负片没有绝对的黑白参考**。
  ⇒ `io.scan_film=True` 时引擎输出**没有被锚定**（合成图实测：纯白 → L\*32、中灰 **b\* +27**）
  ⇒ 本模块按**真实冲扫店扫描仪**做的 ②③ 补上：**每通道按分位定黑白点、线性拉伸**
★ **绝不改 vendor 文件**（`_tools/README.md` 写明"改动：无，原样拷的"）
  ⇒ 只能**类级 monkey-patch**（自检钉着：vendor 里不许出现我们的标记 `SVFILM_BAND`）
★ **条带包装为什么逐位不变**：那条链**全是逐像素的**（3 通道进 → 81 波段 → 3 通道出），
  81 **纯属中间量** ⇒ 按行切开分别算、拼回来数学上完全相同（实测最大逐位差 **0.000e+00**）；
  阈值 `BAND_MIN_PX = 1000000`（**小于这么多像素不切** ⇒ 700 预览走原路、行为一模一样）
★ **计时的陷阱**：vendor 那条 `@timeit` 是 `timings[key] = elapsed`（**覆盖**）
  ⇒ 逐条带调用只会留下"最后一条带"的时间（假数），必须把**总时间**写回去
```

## 十、**印相白平台**：最亮中性像素的 b* 是「相纸无染料白」的色度（10-17 实测）

```
现象：中性像素（C*<=8）在 **L* 80-100 档的 b* 恒约 +0.82~+0.96**，且**所有旋钮都动不了它**：
      逐通道 γ_B 0.95~1.20 · γ_fast/γ_slow · couplers.amount 0.76~1.45 · lc 0.70~off ·
      knee (0,1,3)/(0,1,6)/(0,1,10) · halation 1.5/0.5/0 与 8/2/0 · 入口 WB 4600~5200 ·
      色调 0.95~1.00 · **换卷换纸** —— 全部 ±0.01
