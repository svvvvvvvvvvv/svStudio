# 先看成片：当前设计能不能到“十之八九”

> 你问的是对的问题：**目的是成片好看、像大师、人物好看、有氛围有质感；不是工程，不是对齐数值。**  
> 这篇不再加机制，只回答：现在这套能不能到 80–90%，差在哪，下一步怎么验。

---

## 1. 先把目的排个序

1. **成片好看**：人物好看、肤色对、光有氛围、有胶片质感。
2. **像大师**：同一情境下，别人分不出哪张是大师、哪张是我们。
3. **稳定**：同一批/同一场景，不是一张好一张崩。
4. **可复现**：换一批、换尺寸、换 LR/引擎，结果还在。
5. **可解释**：知道哪一步动了什么。

**数值/卡片/标签/匹配/验收，全是 1–4 的工具。**  
如果工具本身变成目的，就会像最近这样：修了很久，成片还没被证明。

---

## 2. 诚实回答：现在能不能到 80–90%

### 能到 80% 的部分

- **匹配**：ResNet50 top-3 78.7%，top-1 54.5%；38 已确认。找对场景这件事，基本成立。
- **介质**：3 个 profile（portra_400+endura / gold_200+endura；颗粒/光晕/化学/格式）是现成的；氛围/质感的底在。
- **色彩/影调**：卡片 target + LR Basic/Curve/CG/HSL 的分工是对的；在**匹配对、光/姿态不差、曝光正常**的图上，色彩的 80% 是可达的。
- **批次一致**：卡是批次级，不是逐图；这点比旧 per-image master 对。

### 还没证明的部分

- **LR solver 还没跑**：Basic/Curve/CG 目前是设计 + `cal_*` 敏感度，不是已验证的闭环。
- **look loop 没闭**：没有“渲一张 → 和大师并排 → 看差在哪 → 改一个 owner”的循环。
- **最后 10–20% 不在架构里**：在**局部**（皮肤/眼睛/高光/颗粒）、在**光/姿态/表情**、在**原片**。系统能把色彩/影调/氛围做到 80%，但**不能把一张平光/姿态不对的照片变成大师**。
- **数值不是成片**：C/L/分位/残差可以指导，但不能替代眼睛；追求 residual=0 可能得到“正确但不好看”。

### 所以

**“LR 完成之后十之八九”在“匹配对 + 光/姿态不差 + 曝光正常”的图上，是合理目标；在当前状态下，是“可能但未证明”。**  
**最后那一两成，不是再加一层架构能解决的，是局部 + 光 + 原片 + 眼睛。**

---

## 3. 现在最该做的不是加机制，是 look-first

### 3.1 小样本 blind A/B（不渲整批）

- 选 **3–5 张你真正喜欢的卡**：38/104、013、014、021、130（或其组合）。
- 每个卡选 **1 张同情境的图**（大师原图 / 或匹配批次里最接近的一张）。
- 用**当前最好的链路**跑一版：介质 profile + 当前 v9 + 卡片 target 的 LR Basic/Curve/CG/HSL（能跑多少跑多少，不追求完整 solver）。
- **并排 + 盲看**：你（最好再加 1–2 个不看参数的人）判断“哪张是大师 / 哪张是我们 / 差在哪”。
- **记录**：肤色、明暗、彩度、分级、颗粒、高光、局部、氛围；**不记 residual**。

### 3.2 只修最大的那个差距

- 一次只改一个 owner：肤色差→HSL/肤色；高光差→Highlights/曲线；氛围差→介质/颗粒/光晕；局部差→局部 retouch；光/姿态差→**这不是调色能修的**，换图/换匹配。
- 改完再 blind A/B；**两次不过就停**，别陷入无限调参。

### 3.3 80–90% 的验收定义

- **blind A/B**：在匹配情境下，你/旁人**不能稳定指出**哪张是大师、哪张是我们；
- 人物好看、氛围/质感在；**不是** residual/分位对齐。
- 如果 blind A/B 只能到 70%，那就诚实接受 70%，并明确“最后 30% 是光/姿态/原片/局部”，不再拿架构去补。

---

## 4. 这套设计和“工程化”的边界

| 系统能负责 | 系统不负责 |
|---|---|
| 找对场景（匹配） | 原片的光/姿态/表情 |
| 介质/颗粒/光晕/纸 | 摄影师的布光/构图 |
| 色彩/影调/分级的 80% | 局部修图（皮肤/眼睛/牙齿/碎发） |
| 批次一致/可复现 | “这张就是不好看”的原片问题 |
| 解释“为什么像” | 替代眼睛 |

**承认边界，才不会拿架构去补原片。**

---

## 5. 和 freeze 的关系

- freeze 不是目的；freeze 是为了**不再横跳**。
- 但 **freeze 的验收必须是 blind A/B**，不是“契约齐了/测试绿了”。
- 顺序应该反过来：**先 look-first 小样本 → 找到最大差距 → 只修那一个 → 再 freeze 能产出这个 look 的设计**。  
  不是“先把设计冻死，再希望它好看”。

---

4. 两次之后，如果到 80%，就 freeze 这套；如果不到，就诚实说“当前到 X%，差在 Y”，不再加架构。
