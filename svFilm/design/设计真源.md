# 引擎 ↔ LR 分工手册（2026-10-29）

> 🔒 **已锁定**：只有人授权后才能改。代码与本文冲突时**改代码**。
> 数据/复盘/证据 → `交接.md`、专题报告、`问题台账.md`；引擎事实 → `引擎手册.md`。

## 0 三十秒版

```
给一个照片目录
 → 整批渲完（基线卡）→ 用全批测量算匹配 → 出 5 个候选页（带大师样片）
 → **人拍板选一张**
 → 用这张卡的介质渲全批 ①（引擎不做白端求解，见 §4.1）
 → 用同一张卡求解 LR 七步（一次算）→ 出 ③
 → 验收 + 记账 + 出验收页
```

两条不能破的：**一次算、一次验**（不许导出来看给多少）· **目标只能是区间，不是点**。

## 1 卡：只有一种

**匹配卡 = 一套大师作品 = 一个目录。**

| 语料 | 卡数 | 规则 |
|---|---|---|
| 鹿井 | 62 | 一个子目录一张 |
| 滨田 | 1 | 整个语料一张（n=19） |
| 小红书 | 1 | 整个语料一张（n=31） |
| **合计** | **64** | |

命名：有子目录用子目录名；整语料散图用 `<语料>（整套）`；**卡名必须唯一**。

**卡里装**：样片 · 介质（卷/纸/画幅/纹理档）· 形状（toe/shoulder/contrast_win/skew）· 色彩（中性轴 a/b、色相六段、暖冷）· 关系（脸÷背景亮部、人÷背景中位、光比）· 光分布。

**卡里不装绝对落点**（p50/p95/clip 的分布）——那随"拍什么"变，不随风格变。只当**参考**。

已废术语：生产卡 · 参照卡 · 大师预设 · 两层卡。现在只有匹配卡。

## 2 分工

| | 引擎 | LR | 人 |
|---|---|---|---|
| 管 | 卷/纸（风格）· 颗粒/光晕/柔光（质感）· 出片（落点由引擎的中灰归一决定，**不求解白端**）· 白点 | 落点 · 白黑两端 · 影调形状 · 局部（人）· 颜色 | 意图（亮/暖/浓/软）· 审片 · 选卡 |
| 不管 | 逐图亮度落点 · 追某个数 | 质感（做不到也不该做） | 数值 |

引擎自己的测光**留着**：印相配平锚写死 0.184 ⇒ 不读图 ⇒ 不振荡；它做的是"中灰归一"，
效果就是每张的出片余量一致。**不许在外面再乘一个 EV/PE**（那就是手册说的振荡路径）。

## 3 LR 七步

| 步 | 只负责 | 不许碰 |
|---|---|---|
| ① 看哪里 | 脸 / 人 / 整幅 | 读数不可信时装作有读数 |
| ② 曝光 | **整幅**落点（直方图定） | 为脸动（脸的账归 ⑦） |
| ③ 白端 | 背景亮部不到平台 | 为提脸把白端推过头 |
| ④ 高光/阴影 | 压爆点 · 抬暗部（**成对**） | 单动一个 |
| ⑤ 黑端 | 保住"够得着黑" | 拿它拉对比 |
| ⑥ 曲线 | 按残差修**形状**（每锚点 ≤3 L\*） | 追形状 · 替 ③④ 干活 · 动 p50 |
| ⑦ 局部（人物蒙版） | 人身上的影调：曝光/高光/阴影/白/黑/对比/曲线/饱和 | 整人均匀提 · 越过关系约束 · 改整幅 |
| ⑧ 彩色 | 肤色 + 整体色调 | 拿它修亮度 |

★ **②③④⑤ 是一件事的四个面**：抬白不压黑 = 发灰；压高光不抬阴影 = 死黑。

★ **⑦ 的最小步**：LR 滑块一档（LocalExposure2012 步长 0.01 = 0.04 EV）。

### 3.5 三处冲突，各自的裁决

| 冲突 | 裁决 |
|---|---|
| 曝光 vs 曲线的 p50 | 曲线**不许动 p50**（两处同时平移会打） |
| Highlights vs 曲线肩部 | **只用 Highlights**，曲线肩部不动（功能重叠，Highlights 是"按亮度局部"，更准） |
| 全局饱和 vs 点颜色 | **先全局、后局部**；全局只补"整幅偏灰"，**不许用它补肤色** |

# 6B LR 求解器：七步全开（2026-10-30 定稿，实现以此为准）

> 上一版的问题：**每张都压白、一次只挪一个旋钮**。
> 两个都错。这一节把七步各自"什么时候动、动多少、公式从哪来"写死。

## 6B.1 先纠正一个假门槛：p95 ≤ 93 不是大师的特征

实测大师成片（859 张，v3 口径）：

```
整幅 p95   中位 91.0 ｜ P10 85.5 ｜ P90 96.1     ← 27% 的成片 p95 > 93
整幅 clip  中位 0.09% ｜ P90 0.83%
卡的 p95 带中点：中位 90.1，范围 84.2~95.8
```

⇒ 我原来把 **p95 ≤ 93 当硬门**，会让 **27% 的大师成片不合格**。
  那不是"学大师"，那是我自己造的门。

**正确的白端判据**：

```
主判据 = clip（人身上）超没超**这张卡的 clip 带**
参考量 = p95（对照卡的 p95 带）—— 只报，不判死
```

## 6B.2 七步：每一步的触发条件、公式、出处

| 步 | 什么时候动 | 动多少（公式） | 出处 |
|---|---|---|---|
| ② 曝光 | **只在安全线破了才动**：① 的 p1 < 1.0 或整幅 clip 超过卡带的上沿 | `EV = 3·log2((Lt+16)/(L0+16))` | CIELAB 立方根段（可算） |
| ③ 白端 | **只在 ⑥ 之后仍有残差**：残差 = 人的 clip − 卡 clip 带上沿。曲线已解决 ⇒ **不动** | 残差 ≤ 0.5% ⇒ 0；否则 `−min(30, 残差×60)`（LR 刻度，半可算） | LR 无公开传递函数 ⇒ 只给方向 |
| ④ 高光/阴影 | 默认 **0**（与 ⑥ 肩部重叠） | 只当曲线预算耗尽时接手 | §3.5 裁决 |
| ⑤ 黑端 | 只在 p1 < 1.0 时动 | `−10`（一档），一次性 | 物理（不堵） |
| ⑥ 曲线 | **总是动**（这是形状，风格的主载体） | 由卡的 toe/shoulder/contrast_win 反推 16 点 LUT；肩部目标 = 卡 p95 带中点 | §6B.3（可算） |
| ⑦ 局部 | 只在"脸低于目标"或"人的比值为外"时动 | `EV = (目标 − 现值)/eval_slope(现值)`；`LocalExposure2012 = EV/4`；上限：人 p99 不许过**卡的 p95 带上沿** | CIELAB 斜率 + 实测 EV/4 |
| ⑧ 彩色 | 总是动（幅度小） | 饱和：`min(12, (卡脸C下沿 − 我们的脸C)×3)`；分离色调：冷暖方向由卡 warm_cool_b 带中点定，强度 `min(8, 4+|中点|×0.5)` | 卡带 + LR 无公开式 |

★ 关键：**③ 的触发看"⑥ 之后"，不看 ①**。上一版每张都压白，就是因为拿 ① 的 p95 去触发。
  曲线落地后 ① 的 p95（95~100）已经被 shoulder 收到 88.6，残差为零 ⇒ ③ 全程不动。

## 6B.3 ⑥ 曲线的公式（可复算，不跑 LR）

```
输入：卡的形状带 toe / shoulder / contrast_win（P25~P75 的中点）
     卡的 p95 带中点 → 肩部目标 `W`
锚点（L* 域）：
    p5  → 6                      （趾部起点，胶片黑不纯黑）
    p25 → 6 + toe
    p75 → p25' + contrast_win
    p95 → min(p75' + shoulder, W)   ← 肩部落在卡的 p95 上，这就是"学大师的白端"
    p50 → (p25' + p75') / 2
插值：PCHIP（单调，不反折 ⇒ 不出 banding）
输出：16 点 (x,y) 0..255，写进 crs:ToneCurvePV2012
```

## 6B.4 七步的顺序与依赖（"一起动"的含义）

```
⑥ 曲线（先做，它是全局形状）
   ↓ 预测曲线后的值（apply_lut，可算）
⑦ 局部（以"曲线之后"的脸/人为起点 ⇒ 曲线压掉多少，局部补回多少）
   ↓
② 曝光 / ⑤ 黑端（只补安全线）
   ↓
③ 白端（只看⑥之后的残差）
   ↓
⑧ 彩色（最后，不动亮度）
```

**这就是"一起动"**：不是各算各的，而是**上一步的结果进下一步的输入**（曲线→局部→白端）。

### 6C XMP 数值语义：每个标签的单位与公式

> 出处：Adobe XMP / Camera Raw Settings 标签定义（[exiftool TagNames](https://exiftool.org/TagNames.pdf) 的
> `Camera Raw Settings` 一节）、Adobe Lightroom 参考手册（各滑杆作用域的官方描述）、
> RawPedia（管线顺序）。**有单位的直接换算，不许再自测系数。**

| 标签 | 单位 / 范围 | 语义（文档口径） | 我们怎么用 |
|---|---|---|---|
| `crs:Exposure2012` | **EV**（−5~+5） | 整体增益 ×2^EV，在中灰附近线性 | `EV = 3·log2((Lt+16)/(L0+16))`（CIELAB 立方根段精确反解） |
| `crs:Contrast2012` | −100~100 | 围绕中灰的对比，**主要作用中间调**（Adobe 原文） | 默认 0：形状交给曲线（§3.5 裁决） |
| `crs:Highlights2012` | −100~100 | 恢复/压缩**高光**（按亮度区域，非全局） | 默认 0；⑥ 预算耗尽才接手 |
| `crs:Shadows2012` | −100~100 | 提/压**阴影** | 默认 0 |
| `crs:Whites2012` | −100~100 | **白点**（把最亮端推上/拉下） | 只在 ⑥ 之后仍有残差时动 |
| `crs:Blacks2012` | −100~100 | **黑点** | 只在 p1 < 卡的 p5 下沿时动 |
| `crs:ToneCurvePV2012` | `(x,y)` 各 **0..255**，分段线性 | **显示域**的主色调曲线，`ToneCurveName2012="Custom"` | 由卡的 shape 带反推 16 点（PCHIP，单调） |
| `crs:SplitToningHighlightHue` | 0~360 | 高光染色的色相 | 由卡的 `warm_cool_b` 中点定方向 |
| `crs:SplitToningHighlightSaturation` | 0~100 | 高光染色强度 | `min(8, 4+|中点|×0.5)` |
| `crs:SplitToningShadowHue/Saturation` | 0~360 / 0~100 | 阴影染色 | 与高光反相 |
| `crs:SplitToningBalance` | −100~100 | 高/低光染色的配比 | 0（对称） |
| `crs:Saturation` / `crs:Vibrance` | −100~100 | 全局饱和 / 肤色保护型饱和 | 由卡 `face_C` 带 vs 我们的脸 C 算 |
| `crs:LocalExposure2012` | **EV**（蒙版内） | 局部曝光，单位与全局曝光相同 | `EV = ΔL / eval_slope(L)`，**按 EV 直接写** |
| `crs:LocalHighlights2012` | −100~100（蒙版内） | 局部高光 | 暂用 0（桥回读 nil，见下） |

#### 6C.1 一条必须纠正的旧账：`LocalExposure2012 = EV/4`

```
旧写法（2026-10-29）：写进 LR 的 LocalExposure2012 = fill_ev / 4，并说"实测公式，三档已验"。
问题：标签本身的单位就是 **EV**（与全局曝光同单位）。÷4 是**自测系数**，
      不是文档口径 —— 它多半在补偿别的东西（主体蒙版的羽化/衰减，或重复施加）。
按 §6B.5 的纪律：有单位的直接换算 ⇒ **应当是 1:1 写 EV**。
待办：用一次对照（同一张，写 EV vs EV/4，量脸 L）确认蒙版是否真的衰减 4 倍；
      确认后要么 1:1 用，要么把衰减写成一个**有出处的**系数（蒙版面积/羽化半径的函数），不许留"÷4"。
```

#### 6C.2 由此改掉的三处做法

```
1 曝光/局部曝光：一律用 EV 反解（CIELAB），不再试档位
2 曲线：直接算 16 点 LUT（0..255 显示域），不再"挪一点看效果"
3 白端/黑端：只在残差与物理线下动；幅度按残差换算，不用固定 −8
```

### 6B.6 「照着卡求解」的映射表（每个阈值从卡的哪个带来）

| 用到的地方 | 取卡的哪个带 | 取法 |
|---|---|---|
| ② 曝光的安全线 | `p5` 带下沿 / `p1` | 破了才动（暗端） |
| ③ 白端残差门 | `p95` 带上沿（并受物理线 96 约束） | `min(96, p95_hi)` |
| ③ 爆白门 | `clip` 带上沿（下限 0.3%） | `max(clip_hi, 0.3)`，再与物理线 1% 取小 |
| ⑤ 黑端 | `p5` 带下沿 | p1 低于它才动 |
| ⑥ 曲线肩部 | `p95` 带中点 | 肩部落点 |
| ⑥ 曲线的 toe / 中调 | `toe` / `contrast_win` 带中点 | LUT 锚点 |
| ⑦ 脸目标 | `face_over_bg` 带 × 这张图自己的 `bg.L_p90` | 关系，不用绝对值 |
| ⑦ 人目标 | `person_over_bg` 带 × 这张图自己的 `bg.L` | 关系，不用绝对值 |
| ⑦ 补光上限 | `p95` 带上沿 | 人 p99 不许过它 |
| ⑧ 饱和 | `face_C` 带的上下沿 | 低于下沿补、高于上沿收 |
| ⑧ 分离色调 | `warm_cool_b` 带中点 | 定冷暖方向与强度 |

★ 只有两类东西**不来自卡**（这是设计允许的例外）：
  1. **物理线**：L\* 99 = 可见平台（clip）、p1 的黑端、CIELAB 换算
  2. **生理线**：T4 的脸亮度下界 55（§4.1），它比卡带更宽时取它

## 6B.5 两条纪律（这一版新增）

```
1 每一步都要有"不动"的合法状态：动是例外，不是默认。
   上一版的错：③ 每张都动 ⇒ 说明触发条件写错了（拿 ① 的 p95 当门）。
2 每个旋钮的幅度要么可算（CIELAB / LUT / 卡带），要么只给方向并记账。
   不许出现"一档 −8"这种没有出处的常数。
```

### 4.1 硬门（不变量，破了 = 错）

**为什么 ① 的白端不判（2026-10-30 实测）**

```
presets.py 硬写 print_exposure_compensation=True + normalize_print_exposure=True
⇒ 印相曝光按 18.4% 中灰归一化，print_exposure **被覆盖**
⇒ render_safe 的 pe 二分对 p95 基本无效：
   p95_max 从 96 改到 93，10 张 ① 的 p50/p95 几乎一字不变（45.6/99.1 → 45.5/99.2）

所以：① 的白端由"场景 + 扫描白端"决定，不由引擎求解。
     引擎只保证**不剪死**（它自己的测光），白端（p95/clip）由 LR 的 ③ 负责。
```

**白端的 clip 只看人（2026-10-30）**

```
919 那批实测：1231 整幅 clip 5.29%，但**人身上 0.00%**（全是天空）
              1526 整幅 1.58%，但**人身上 9.53%**（白裙爆了）
⇒ 拿整幅 clip 当门，会为了天空去压整幅；该压的正是 1526 那种。
所以 T1 的 clip 判**人（1−BG）**；整幅/天空的 clip 记在账里当线索，不当门。
```

**关系带用 P25~P75，不用 P10~P90（2026-10-30）**

```
关系是比值（脸÷背景亮部 · 人÷背景中位）。P10~P90 会被极端场景拉宽：
004 那张卡的 person_over_bg 原为 [1.17, 2.98] —— 上沿 2.98 = 人比背景亮 3 倍，
几乎没有判别力（10 张里 8 张"已在带内" ⇒ 局部步空转）。
改用 **P25~P75**（004 变成 [1.24, 2.21]），并在算比值时加分母护栏（背景中位 < 20 的图不参与）。
```

**★ 局部步必须带亮度范围（2026-10-30 实测证据）**

```
卡 004 的计划：1231 局部 +1.27 EV，1726 局部 +0.97 EV
按"整人主体蒙版"执行（现在 lrsink 的做法）后：
  1231  人 p99  81.6 → 96.5   人 clip 0.00% → 0.55%   ← 白裙被提爆
  1307  人 clip 1.92% → 7.78%                        ← 更糟
  1726  人 p99  68.2 → 83.5   脸 30.2 → 47.1          ← 这张要的就是提

⇒ 整人均匀提一定会把人的亮部推上去（§43 早就写了"主体 ∩ 亮度范围"）。
   执行层现在用的是纯主体蒙版，所以这条设计还没落地。
   下一步：局部蒙版必须叠加亮度范围（只提人身上的暗部）。
```

### 4.2 可行域（来自卡；落进去算成，域内不排名）

```
关系：脸÷背景亮部 · 人÷背景中位 · 暖冷 · 光比
形状：toe / shoulder / contrast_win / skew
色彩：中性轴五段 a/b · 色相六段 share/C
```

卡的**分布区间只作参考**（讲代价用），**不进可行域**。

### 4.3 优先级

```
不变量 > 可行域 > 意图
例外：脸 vs 背景高光冲突 ⇒ **脸优先**（背景可过曝，脸不许被压暗）
域内多解 ⇒ 取旋钮动得最少的
```

### 4.4 门与线索

```
门 = 有阈值、判过不过、会挡流程；线索 = 只报不判
任何量入代码必须标清是哪种。混用是历史错误的主要来源。
```

### 4.5 「对齐卡」与「打靶」怎么分（可操作）

| | 对齐（要的） | 打靶（不要的） |
|---|---|---|
| 用卡的什么 | 区间 / 关系 / 形状 / 配比 | 某个**点值** |
| 判成功 | 落进域就算成，域内不排名 | 越接近那个点越好 |
| 解不唯一 | 取旋钮动得最少的 | 继续调到等于卡 |
| 卡的数字 | 边界与线索 | 目标 |

**自检**：把卡的中位整体平移 2 L\* —— 解**跟着动**就是打靶；只有跨出区间时才动，才是对齐。

### 4.6 T4 的区间

```
顺光/中性：脸 L* 55~85（生理常识 + 语料区间，宽区间不是靶）
逆光：不另设点值 —— 靠 ⑦（局部）与 4.2 的关系约束，不给"该到 62"这种数
```

## 5 口径（一个词只有一个意思）

| 词 | 定义 |
|---|---|
| **肤色** | 画圆（R=0.30 脸宽）→ **圆里取一个点** → 四条证明它是皮肤：9×9 局部平整（a/b std ≤6）· 0.06/0.10/0.14 脸宽三尺度一致（ΔE≤4）· 与圆内中位接近（ΔE≤8）· 不许是最亮/最暗（P8~P92）。点在 1080 域固定，①②③ 用同一像素 |
| **脸 / 人 / 背景** | 脸 = FACE；人 = 1−BG（含头发衣服手）；背景 = BG。**脸的读数是判据，人的掩膜是作用域，背景是参照** |
| **背景：全幅 vs 近邻** | 全幅用于落点/收白/白点；**近邻（外扩 0.9 脸宽）用于判光位与"人有没有浮出"** |
| **光向量** | 四个证据：左右梯度 `d_lr_img` · 近邻背景比 `ratio_near90` · 发丝−脸 `hvf` · 斑驳 `clump`。**不是三维向量，不是角度**；离散成 back/back_side/side/front/dappled，只用于选区间与分组，**不给剂量** |
| 光向量**做不到** | 前后（z）分量 · 顶光（眉眼污染）· 绝对角度 |
| **亮度** | CIELAB D65 的 L\*；统计在原生分辨率，检测在 1080 再放大 |
| **单位** | 1 EV = ×2 光；每档抬 `0.231·(L+16)` L\*（CIELAB）；LR 的 `LocalExposure2012 = EV/4` |

## 6 求解：一次算

### 6.1 可算的三根（有闭式）

```
① 曝光   E = 3·log2((Lt+16)/(L0+16))       ← CIELAB 立方根段精确式
② 曲线   16 点 LUT 显式 ⇒ 锚点位移就是答案；每锚点 ≤3 L*
③ 局部   LocalExposure2012 = EV/4；ΔL 用该处 eval_slope
```

### 6.2 半可算的四根（无公开式）

```
Whites / Blacks / Highlights / Shadows
· 只在前三步之后**撞界**时动，一档最小步，不迭代第二次
· 不许当落点主力；动了要记账
```

### 6.3 顺序

```
可行域 → ① 曝光 → ② 曲线 → ③ 局部 → ④ 撞界修正 → 出片一次 → 验
                                                    └→ 不达标：记账，不回头
```

### 6.4 账（一条一笔）

```
{ dim · got · want[区间] · gap · layer(card/engine/exposure/curve/local/white/color) · action }

账的去处（三处缺一不算）：`plans.json`（机读）· 验收页（人读）· `交接.md`（跨会话）。

### 6.5 意图

```
四维：亮 / 暖 / 浓 / 软（可为空）
进匹配：只改**候选排序偏好**（更亮 → 偏 p50/p95 高的卡；更暖 → 偏暖冷值正的卡…），不改"像哪一套"
进求解：只产生**偏移**；出域就贴着区间边缘停，不许破域
```

### 6.6 批次

```
一批一张卡（人拍板的那张）。
混合批（明显两类场景）不自动拆，匹配页提示"可能含两类"，拆不拆人定。
换卡 = 人的决定，要留痕（换前/换后 · 原因 · 影响哪几张），换完从步 5 重来。

## 9 认识论（六条，每条都是踩出来的）

| # | 条款 | 踩过的坑 |
|---|---|---|
| E1 | **能推的不测** | 去测"每档抬多少 L\*"，其实 CIELAB 能算 |
| E2 | **判据要对改动敏感** | 改颗粒模糊却用 p95 验收（77.7≈78.1“没变”），整批糊了 |
| E3 | **同物同口径才可比** | 跨 ① 版本比肤色，取样点漂了，报出 20 L\* 的假差 |
| E4 | **输出不许当输入** | 导出来看给多少 ⇒ 闭环、打靶 |
| E5 | **分布宽 ≠ 概念错** | 套内方差大就断言"一套不是一种风格"；其实是那个量在测场景 |
| E6 | **断言也会错** | 测试钉住"两张卡边界必须不同"，把错误信念锁了三轮 |

推论：**判据字段必须是当前口径的**（用旧字段 `skin.n` 判可信度，凭空造出 34% 的缺陷）；
**一条规则不能从一个样本推广**（按鹿井的命名习惯过滤，把滨田/小红书两张卡滤掉了）。

## 10 公式与数值的出处

| 量 | 出处 | 怎么用 |
|---|---|---|
| L\* ↔ 亮度 Y | **CIELAB / CIE 1976**（分段式，可逆） | 直接算 |
| 每档抬多少 L\* | 同一标准的局部斜率 `0.231·(L+16)`；精确反解 `E=3·log2((Lt+16)/(L0+16))` | 算，不测 |
| 颗粒 RMS 粒度 | **ANSI/I3A IT2.40**（48 µm 孔径 · 净密度 1.0） | 引擎照它实现 |
| 主光:辅光比 | 厂商与教材口径（Sekonic《Studio Lighting: Understanding Ratios》） | 只给方向与档级 |
| 逆光/开放阴影比直射低几档 | 摄影实践口径（约 2~2.5 档） | 只当量级；区间从语料取 |
| 肤色偏好（白、有血气） | 视觉研究（记忆色比实测更亮、略更饱和） | 只当方向 |
| 胶片肩部/趾部 | 厂家 datasheet 的 D-logE 曲线 | 形状靠卷纸，不靠 LR 曲线造 |
| 可行域的区间 | **大师语料**（64 张卡的画像） | 唯一"自己量"的合法部分，且量的是**区间** |
| LR 的 Highlights/Shadows/Whites/Blacks | **无公开传递函数** | 只给方向 + 一次验 |
| LR 点颜色的 SatScale/HueShift | **无公开式** | 同上 |

规则：要一个新常数，先问"标准能不能算 / 论文厂家有没有 / 语料区间能不能取"；
三者都不行 ⇒ 只给方向，不许编斜率。**任何"我渲一批量出来"的常数一律作废。**

## 13 大师作品的测量规格（字段 × 手段 × 方法 × 口径）

> 准备重测之前把这张表定死：**每个字段用什么算、怎么算、在哪一域算、什么时候弃权**。
> 口径不需要"物理出处"，但必须**固定且可复现**；变了就算新版本（记 `measure_sha`）。

### 13.1 公共约定（所有字段都遵守）

```
域        检测（人脸/人体/分割）在**长边 1080** 上算，结果放大回原生；统计在**原生分辨率**上做
色彩      CIELAB D65；L* 0~100 浮点；C* = hypot(a,b)；h = atan2(b,a) 度
掩膜      FACE（YuNet 五点+框）· PERSON = 1 − BG（自拍分割）· BG = 分割的背景类
弃权      任何一项失败 ⇒ 出 `null` + `err` 字段，**不许填 0、不许静默跳过**
确定性    同一张图连测两次必须逐位一致（无随机、无时间依赖）
版本      每次改动记 `measure_sha`；跨版本的数据不许相减
```

### 13.2 逐字段

| 字段 | 手段 | 方法 | 口径 / 阈值 |
|---|---|---|---|
| `img.p*` | numpy 分位 | 全图 L\* 的分位：p1/p5/p10/p25/p50/p75/p90/p95/p99 | 全图像素，不排除任何区域 |
| `img.clip_pct` | 同上 | L\* ≥ 99 的像素占比（%） | 99 是"可见平台"的量化下限 |
| `img.contrast` | 同上 | p95 − p5 | — |
| `shape.toe` | 分位组合 | p25 − p5 | 见 13.3 |
| `shape.shoulder` | 同上 | p95 − p75 | |
| `shape.contrast_win` | 同上 | p75 − p25 | |
| `shape.skew` | 同上 | (p50 − p5) / (p95 − p5) | 分母 < 1 时弃权 |
| `bg.L/C/a/b` | BG 掩膜 | BG 类像素的 L/C/a/b 中位 | 掩膜覆盖 < 5% 画幅 ⇒ 弃权 |
| `bg.L_p10 / L_p90 / L_p95` | 同上 | BG 类像素的 L\* 分位 | 同上 |
| `env_share` | 掩膜面积 | BG 像素数 ÷ 全图像素数 | — |
| `near_bg.L_p50 / L_p90` | 圆形膨胀 | 以脸框中心为心、外扩 **0.9×脸宽**的圆盘内 ∩ BG | 圆盘与 BG 交集 < 2000 px ⇒ 弃权 |
| `person.share/L/p95` | PERSON 掩膜 | 1−BG 的占比 / L 中位 / L p95 | 占比 < 3% 或 > 60% ⇒ 弃权（多半分割错了） |
| `face_w_native` | YuNet | 原生分辨率下的脸框宽（px） | 1080 域 < 40 px ⇒ 弃权 |
| `face_size` | 同上 | 脸框面积 ÷ 画幅面积 | — |
| `face_mask_share` | 同上 | FACE 面积 ÷ 画幅 | — |
| `skin.L/C/h` | **圆里取点** | 画圆（R=0.30 脸宽）→ 选一个点 → 四条证明 → 取该点 9×9 中位色 | 见 13.4 |
| `skin.xy/rgb/w` | 同上 | 点坐标（1080 域）/ 该点 RGB / 窗半径 | — |
| `skin.mad / dE_scale / dE_rep` | 同上 | 三条证明的实测值（存下来，别只存结论） | mad ≤6 · dE_scale ≤4 · dE_rep ≤8 |
| `white_point.a/b/C` | BG ∩ 亮部 | BG ∧ L ≥ p95(BG) 的 a/b 中位 | 样本 < 500 px ⇒ 弃权 |
| `white_point.L_thr` | 同上 | 用到的 p95(BG) 阈值本身 | — |
| `rim.bright_share` | 环带 | 脸框外扩 1.2~1.6×脸宽 的环内 ∧ 非 FACE ∧ L > 脸中位+8 的占比 | **线索**，不作门 |
| `light.d_lr_img` | 左/右半脸 | 沿眼线切左右两半（各自 ∩ FACE），左右 L 中位之差 ÷ 脸反差；正 = **画面右**亮 | 任一半 < 200 px ⇒ 弃权 |
| `light.ratio_near90` | 近邻背景 | 脸中位 ÷ `near_bg.L_p90` | 近邻弃权则一并弃权 |
| `light.hvf` | 发丝环 | 脸框上沿外扩带（发丝）内 ∧ 非 FACE 的 L p90 − 脸中位 | 带内 < 300 px ⇒ 弃权 |
| `light.clump` | 残差 | 脸内 L 去掉一阶平面拟合后的 std ÷ 脸反差 | 见 13.5 |
| `light.label/conf` | 分类 | 由上面四个分量离散成 back/back_side/side/front/dappled | 证据不足 ⇒ `unknown`（宁可弃权） |
| `light_ratio` | 双区 | `bg.L_p90 / max(face_L, 1)` | 逆光时背景亮部使比值 >1；**这是比值，不是判据** |
| `warm_cool_b` | BG 色彩 | BG 亮部（L≥p90）与暗部（L≤p10）的 b\* 之差 | 任一侧 < 300 px ⇒ 弃权 |
| `neutral_axis` | 五段 | 全图按 L 分五段（等宽），每段取 a/b 中位 | 每段 < 1% 像素 ⇒ 该段 null |
| `hue_bands` | 六段 | 按 h 分六段（0/60/120/180/240/300°），每段取像素 share 与 C 中位 | 与 120° 边界对齐 |

### 13.3 形状四项为什么这么定

```
toe            = p25 − p5     趾部"抬起来多少"
shoulder       = p95 − p75    肩部"压下去多少"
contrast_win   = p75 − p25    中间调的展开量（最能代表"风格"的一项）
skew           = (p50−p5)/(p95−p5)   中间调偏上还是偏下（0.5 = 居中）
```

### 13.4 肤色为什么是"一个点"（不是圆盘中位）

```
① 局部平整    9×9 窗内 a/b 两通道 std 之和 ≤ 6
② 多尺度一致  0.06 / 0.10 / 0.14 脸宽 三个窗的中位色彼此 ΔE ≤ 4
③ 代表性      点的颜色与圆内中位色 ΔE ≤ 8
④ 合理性      L ∈ [38,96] · h ∈ [5,95] · 且点的 L 在该脸的 [P8, P92] 之间（不许是最亮/最暗）

取法：圆内"离圆心近 + 局部最平整 + 颜色最接近圆内中位"的像素
镜像点只作诊断：两侧因侧光不同而不同，那是光照事实，不是测量错误
```

### 13.5 clump 与"顶光/前后测不出来"

```
clump：脸内 L 减去「一阶平面 a·x + b·y + c」的残差 std，再除以脸反差（p95−p5）
       —— 去掉左右/上下的整体斜坡，剩下的才是斑驳（缝隙光）

测不出来，别硬测：
  顶光  上下半脸的差被眉/眼/嘴污染（语料中位就是"下比上亮"）
  前后  单图没有深度
  角度  只有"哪边 + 多强"，没有"多少度"
```

### 13.6 大师作品**不测**的

```
颗粒 rms       空间族无跨链等价（手册 §四）
模糊量         同上
我方颜色偏差   那是我们的问题，不是场景的需求（也进不了匹配）
```

### 13.7 测之前先验三件事（省一次全量返工）

```
1 确定性   同一张图连测两次，逐位一致
2 掩膜     抽 20 张看：FACE 有没有吃到头发、PERSON 有没有把墙当人、BG 占比是否合理
3 弃权     故意喂一张小人脸 / 无脸的图，确认**出 null 而不是 0**
```

### 13.8 关系量要**存下来**，不要留给下游算

```
rel.face_over_bg   = skin.L ÷ bg.L_p90
rel.person_over_bg = person.L ÷ bg.L
rel.gap            = bg.L_p90 − skin.L
```

原因：这三条用哪个背景（全幅还是近邻）、哪个分位（p50 还是 p90）一旦被下游各自决定，
同一份数据就会算出不同的关系 —— 那正是"跨态比出假差"的来源。
