# 第三部分 · 目标从哪来（2026-10-29 收尾）

> 上一节留的洞：「卡」废掉以后，"该到哪儿"没有定义了。这一节补上。

## 13 核心转换：从「打靶」改成「守不变量 + 实现意图」

旧体系：给一个数（卡的中位），解到它上面去。**问题**：那个数来自别人的成片，
而别人的成片是别人的风格 + 别人的调色 —— 追它等于追别人的口味。

新体系：不问"该到多少"，问两件事：

```
① 有没有破不变量？（破了就是错，与风格无关）
② 有没有实现意图？（意图是人给的，可以为空）
```

**意图为空时，系统只满足不变量**——输出就是"这卷该怎么出"。这才是"胶片风格"的含义：
风格来自卷、纸、显影，不来自某个数字。

## 14 不变量清单（全部可测，都有阈值）

### 14.1 技术不变量（引擎负责；破了 = 成像错误）

| # | 不变量 | 判据 | 阈值来自哪 |
|---|---|---|---|
| T1 | 白端不剪 | `clip_pct` < 阈值 | 物理：剪掉的细节不可恢复 |
| T2 | 黑端不堵 | `p1` > 阈值 | 同上 |
| T3 | 白点不偏色 | 白点 `|a|,|b|` ≤ 2 | **量化下限**（8-bit a/b 分辨率 ~1） |
| T4 | 脸不过曝/不欠 | 脸 `L*` 落在 55~85 | 生理常识区，不是某个靶 |
| T5 | 脸不灰 | 肤色 `C*` ≥ 10 | 低于此即"发灰"，与风格无关 |

### 14.2 结构不变量（LR 负责；破了 = 用了下游补上游）

| # | 不变量 | 判据 |
|---|---|---|
| S1 | **改色不改明暗** | 点颜色前后，皮肤 L 分布 p10/p50/p90 变化 ≤1 |
| S2 | **改局部不动全局** | 背景 a/b、背景占比变化 ≤ 阈值 |
| S3 | **曲线不替介质背锅** | 曲线每锚点位移 ≤3 L* |
| S4 | **不许把脸推出人样** | 改色后肤色仍在 T4/T5 之内 |
| S5 | **一段顶到上限就是上游错** | 任一段触界 ⇒ 回上游，不许加宽预算 |

## 15 意图（人给，可为空）

| 维度 | 例 | 谁给 |
|---|---|---|
| 亮 / 暗 | 「再亮半档」 | 人 |
| 暖 / 冷 | 「暖一点」 | 人 |
| 浓 / 淡 | 「淡一点」 | 人 |
| 软 / 硬 | 「柔一点」 | 人（走卷纸或柔光档，不是 USM） |

意图只改**方向与幅度**，永远不许把系统推出不变量区。**冲突时以不变量为准。**

## 18 阈值怎么定（避免旧靶从后门回来）

```
量化下限（T3、容差）     → 由位深/分辨率算，不是拍的
物理不可逆（T1、T2）     → 剪了就没有，阈值取"可见剪裁"的量级
生理常识（T4、T5）       → 人的脸不会那么暗/那么灰，取宽区间
结构（S1~S5）            → 由"谁负责什么"推出来
```

**关键区别**：不变量是**宽区间**（"不许越界"），靶是**窄点**（"必须到这里"）。
旧体系死在把窄点当标准；新体系只用宽区间。

# 第四部分 · 收口：引擎只做质感与风格（2026-10-29 定）

## 19 最终分工

| | 引擎 | LR |
|---|---|---|
| **做** | 卷/纸（风格）· 颗粒 · 光晕 · 柔光（质感）· 出片留余量 · 白点按卷纸配对 | 曝光落点 · 明暗分布 · 颜色（饱和度/色相/局部肤色）· 逐图任何微调 |
| **不做** | 任何逐图的曝光/亮度落点 · 任何"追某个数"的颜色对齐 | 质感（做不到，也不该做） |
| **判据** | T0 余量 · T3 白点 | S1~S5 结构不变量 + 意图 |

## 20 引擎侧做的事（一个求解 + 三样由卡给的边界）

```
① 选卷/纸/画幅      ← 由**匹配卡**带（风格身份，不是求解）
② 印相曝光（唯一求解）← 一次出片内二分：黑 ≤ 卡的 p1 区间、p95 ≤ 卡的 p95 区间
   ★ 这是**逐图**的（每张的底片亮度不同），但它是"把边界守住"，不是"给脸找落点"
③ 白点              ← 卡的介质（卷+纸的配对），不逐批解
④ 纹理              ← 卡自带规格与风格档（颗粒/染料云/光晕/柔光）
```

**没有"逐图解曝光落点"这回事** —— 那是 LR 的活（§45）。引擎只保证：这张底片不剪不死、白点不偏。

## 21 引擎里那几个"自己的测光"要留着

手册 §15.1：引擎的印相配平锚**写死 0.184 ⇒ 不读图 ⇒ 不振荡**。
它做的事是"把中灰归一"，效果恰好就是**保证每张的出片余量一致**。

所以：
- **保留** 引擎自带的中灰归一 / auto_exposure —— 它不是"我们的曝光旋钮"，是**余量保证机制**
- **不要再** 在外面乘我们的 EV / PE（那就是手册说会振荡的那条路）
- 它若把某张曝到余量不足（T0 不过），那是**卷/纸或入口 WB 的问题**，不是"再乘一个系数"

## 22 随这条决定作废的东西

| 作废 | 原因 |
|---|---|
| 脸锚闭环（`run919_anchor.py` 那套） | 曝光归 LR，不需要在引擎侧解 |
| `person_pe_band` / `person_pe_target_l` / 服装带 / `lc` 动态 | 都是"引擎侧调曝光落点"的机制，整体不需要 |
| `−36 L*/EV` 斜率标定 | 同上；换卷/纸不用再重标 |
| 曝光三层主人的记账 | 只剩引擎自带归一这一层 |
| `PERSON_PE_*` 一整套环境变量与常数 | 同上 |

## 23 LR 侧因此变重（但它是为这个而生的）

```
曝光落点    → Basic 曝光 / 曲线 p50
明暗分布    → 曲线（每锚点位移不再受 3 L* 约束？—— 不，仍受约束见下）
颜色        → 全局饱和/鲜艳度 + 点颜色（肤色）+ HSL（必要时）
```

**唯一保留的约束**：曲线位移仍受 S3（≤3 L\*）限制 —— 但那是为了防止"曲线替介质背锅"，
而不是限制 LR 的表达力。**LR 的曝光（Basic 的 Exposure 滑杆）不受这条限制**，
它本来就是用来定落点的。

## 24 一句话总结

> **引擎交一张"带余量、不偏色、有胶片质感的底片"；LR 决定这张底片最终长多亮、什么颜色。**
> 引擎不追任何数值，只守余量和白点。

# 第五部分 · 「以人为本」保留，但迁到 LR（2026-10-29 定）

## 25 结论：原则保留，执行位置改变

「以人为本」不是某个引擎旋钮，是**一条"看哪里"的规则**：曝光/明暗以**人（脸）**为准，
不以整幅直方图为准则。这条规则与在哪个工具里执行无关。

```
引擎上的旧形态：测光掩膜（face/person/matrix）+ 服装带 + 逆光换锚 + pe 闭环
LR 上的新形态：  Basic 曝光以脸为目标 + 曲线管形状 + Highlights 收白 + 点颜色管肤色
```

## 26 旧设计里要保留的四条规则

| # | 规则 | 为什么保留 | 当年证据 |
|---|---|---|---|
| H1 | **有脸用脸** | 脸的读数比"人"更准 | `r²(颊~脸) = 0.890` vs `r²(颊~人) = 0.346` |
| H2 | **降级链**：脸 → 人 → 整幅 | 小脸/无脸不能硬算 | 掩膜覆盖率守卫 [0.005, 0.70]，超界弃权 |
| H3 | **白端保护**（不为提脸把白推爆） | 逆光提亮最大的副作用 | `clip_hi 0 → 11.06` 那次 |
| H4 | **逆光识别**（脸比背景暗 ⇒ 该提的是脸） | 顺光/逆光要相反处理 | 逆光组脸 +17.6、变差 0 张 |

（光位 `lighttype` / `rim` 作为先验可以留，但它是**辅助**，不是判据。）

## 27 旧机制怎么迁到 LR（旧文已删）

> 那张"引擎旧机制 → LR 做法"的一一对应表已作废：它写的是**引擎还在管曝光落点**时的迁移，
> 现在那张表里的 `pe` 闭环、服装带、脸锚标定都已经不在链上了。现行职责见 §38 / §43。

## 28 LR 上这条规则的三条约束

```
L1 脸是【约束】，不是【唯一目标】：脸要落进合理亮度区（T4：55~85），
                              但不必落到某个具体值
L2 脸优先（2026-10-29 晚改）：脸必须进区，且**不许被收白压暗**（Δ ≤ 1 L*）；
                          背景过曝可以接受，收不住就接受，不回引擎
                          （旧写法「没有白端预算就不许提」已废：那等于让背景的账压住脸）
L3 逆光与顺光【分别处理】：光位由 `light_probe` 前馈判定（读 ①，不读 ③；第八部分 §47），
   ⚠ 人可覆盖（`--light`）；判据量到的东西见 §47 的出处表。
```


**光位判据（线索，不是求解入口）**

> 求解时的光位走 light_probe（第八部分 §47）；下面这套双区统计只当**旁证与 fallback**。

**双区统计（查过论文/专利）**

```
出处：专利 CN109815905B（亮区 vs 暗区均值差超阈值 ⇒ 逆光）
     专利 CN102013006B（前景掩膜内**绝对暗**像素占比超阈值 ⇒ 逆光）
     论文 Tsai & Yeh, IEEE TCE 2010（YIQ + 照明分析，模糊分类 back/normal/front-lit）

现在用的两个量（测量层新加）：
  gap  = 背景亮部 L_p90 − 脸 L     ← 双区对比
  dark = 脸掩膜内 L≤40 的像素占比   ← 前景暗占比
判据：dark ≥ 0.35 且 gap ≥ 12 ⇒ backlit ｜ gap ≥ 35 ⇒ backlit
      dark ≤ 0.12 且 gap ≤ 12 ⇒ frontlit ｜ 其余 ⇒ **unknown（模糊的交给人）**
```
**只会判错成 unknown，不会判错成相反方向**——这是刻意的：宁可不判，不许误导。
人可以用 `--light` 覆盖。

**轮廓光保护**：收白把发丝亮边压掉一半以上就报警（`rim.bright_share` → 日志）。
"亮边还在 ⇒ 可以停；亮边没了 ⇒ 提过头"——这是实操资料给的停手标准。

**光位判据的演进**：早期两版自动判据都出过反例（详见交接/专题报告），
现在求解只认 `light_probe`（第八部分 §47），双区统计仅作旁证。

## 29 于是"以人为本"这件事的完整归属

| 环节 | 谁做 | 用什么 |
|---|---|---|
| 找到人/脸 | 引擎（已实现，成熟） | `person_masks` / YuNet；掩膜在 1080 上算 |
| 判断"该看哪里" | **LR 求解器** | 有脸看脸 → 没脸看人 → 都没有看整幅 |
| 执行提亮/收白 | **LR** | 曝光、Highlights、曲线；不用引擎 pe |
| 校验 | 数值 | T4（脸在合理区）+ T1（不爆白） |

**注意**：LR 的"按亮度局部"（Highlights）等于"按位置局部"的近似——
它会连带同亮度的白裙/白墙。这条要在验收时看（S2 选择性门的变体）。

# 第六部分 · LR 侧：只留裁决与接口（§33~§35）

> 原 §29.5~§32（看哪里/曝光/收白/曲线/饱和的顺序与解锁条件）已被**第八部分**取代，本部分只留仍有效的部分。

## 33 三处冲突，各自的裁决

| 冲突 | 裁决 | 理由 |
|---|---|---|
| **曝光 vs 曲线的 p50** | 曲线**不许动 p50**（S3） | 两处同时平移就会打 |
| **Highlights vs 曲线肩部** | **只用 Highlights**，曲线肩部不动 | 两者功能重叠；Highlights 是"按亮度局部"，比曲线精确 |
| **全局饱和 vs 点颜色** | **先全局、后局部**；全局只补"整幅偏灰"，不许用它补肤色 | 全局会连带环境，而肤色是局部问题 |

## 34 LR 侧的"靶"其实也是不变量

引擎收口之后，LR 的判据同样不是"追某批成片"，而是：

```
T1 不爆白   T4 脸在 55~85   T5 肤色 C ≥ 10
S1 改色不改明暗   S2 改局部不动全局   S4 不许把脸推出人样
意图（亮/暖/浓/软）：人给，可为空
```

**"该到多少"这件事在 LR 里也不存在了**——只有"不许破"和"如果你要，我可以往哪个方向推"。

## 35 数据接口（LR 求解吃什么）

| 步 | 吃什么 | 哪一态 |
|---|---|---|
| ① 看哪里 | 脸的测量（`face_w`、`face_size`、`skin` 是否有效） | ① |
| ② 曝光 | ① 的脸 L 中位（引擎刚出来的样子） | ① |
| ③ 收白 | ① 的 `clip_pct` / `p99`；③ 验 | ① 算、③ 验 |
| ④ 曲线 | ① 的五分位 → 出曲线；② 是结果 | ① → ② |
| ⑥ 点颜色 | ② 的肤色（过曲线未加色） | ② → ③ |

**忘了这一条就会犯老错**：拿 ③ 的数去定 ② 的参数。

# 第八部分 · LR 侧的完整分工（2026-10-29 深夜改口，**取代**旧第六部分 §29.5~§32（旧文已删））

> 为什么要改：上一版把 LR 收窄成了"主体蒙版补脸"，全局曝光/白端/黑端/高光阴影/曲线/分级全被砍掉，
> 而且用量值当剂量（62 / 封顶 1.0 档 / 12 C 每单位）。结果：1627 被补到人物浮出画面；

> 本部分是**设计层**：只写组成 / 职责 / 边界 / 协作 / 成功判据 / 不做什么。**不写任何参数值。**

## 37 一句话

LR 不是"补脸器"，它负责**这张底片最终多亮、白黑两端落在哪、影调什么形状、局部怎么补、颜色怎么定**。
主体蒙版只是它手上的一件工具，**不是它的上限**。

## 38 七步职责表（一根旋钮管一件事，边界写死）

| 步 | 旋钮 | 只负责 | 不许碰 |
|---|---|---|---|
| ① 看哪里 | 无（选择） | 判定看脸 / 看人 / 看整幅 | 不许在读数不可信时假装有读数 |
| ② 基础曝光 | `Exposure` | **整幅落点**（由整幅直方图定） | 不许为脸动（脸的账归 ⑦） |
| ③ 白端 | `Whites` | 背景亮部刚好不到平台 | 不许为提脸而把白端推过头 |
| ④ 高光 / 阴影 | `Highlights` · `Shadows` | 压背景爆点 / 抬暗部信息，**成对定** | 不许单动一个（一个压一个抬，会互相抵消） |
| ⑤ 黑端 | `Blacks` | 保住"够得着黑"，③④ 抬起来的底也要跟着压住 | 不许用它拉对比 |
| ⑥ 曲线 | 点曲线 | 按直方图**残差**修形状，预算内 | 不许追形状、不许替 ③④ 干活 |
| ⑦ 局部（人物蒙版） | **一套局部旋钮**：曝光 · 高光 · 阴影 · 白 · 黑 · 对比 · 曲线 · 饱和 | 在整幅已定之后，**只对人**做的那一层（脸的账在这里） | 不许整人均匀提（人会浮出）；不许越过 §40② 的关系；不许改整幅落点 |
| ⑧ 彩色 | 点颜色 · 曲线色阶 · 分级 | 肤色（色相/彩度/亮度）+ 整幅色调 | 不许拿它修亮度 |

★ ②③④⑤ **是一组**，必须一起被看到：抬白不压黑 = 整幅发灰；压高光不抬阴影 = 死黑。这不是"多做几根"，是**同一件事的四个面**。

## 39 求解读什么（这条决定了会不会变成闭环）

```
能读：①（引擎底片）的测量
能读：★ **匹配到的那张卡的画像**（它就是"这批该像什么样"的**可行域**，见 §40.1）
能读：①→② 的**预测**（曝光/曲线有可算模型）
能读：③（出片后）的测量，**只用于验收与记账**
不许：读 ③ 之后回头改参数再导 —— 那就是闭环（手册那条"必然振荡"）
```

一次算、一次验。**不收敛就记账，不改参数再导。**

## 40 判据：不变量（硬边界）+ 匹配卡给的可行域 + 意图

```
① 不变量（破了 = 成像错误）：T0~T5 / S1~S5（见 invariants.py，阈值出处写在那里）
② 可行域 —— **由匹配到的那张卡给出**，四样东西：
   a. **分布区间**：p5/p25/p50/p75/p95、clip、p1 的 P10~P90 带（不是中位）
   b. **关系**：脸/背景亮部、人物中位/背景中位、暖冷（亮部 b − 暗部 b）、光比
   c. **形状**：toe / shoulder / contrast_win / skew（卡的性格，不是一条线）
   d. **色彩**：中性轴五段的 a/b、色相六段的 share 与 C、肤色 C/h 的带
③ 意图（人给，可为空，只产生偏移）
```

★ 求解器做的事：**在 ①（硬边界）之内，找解落在 ② 的可行域里**。不是"把每个量推到卡的中位"。
★ ② 的区间/关系全部**从匹配卡量**（`refcards.py` 已有 64 张的画像 + IQR）；不写死在本设计里。

## 40.1 「对齐卡」与「打靶」的分界线（这一条决定方向对不对）

上一轮把这件事做歪过（为了对上某一批的 p95 去破坏主体），所以界线要写死：

| | 对齐（要的） | 打靶（不要的） |
|---|---|---|
| 用的是卡的什么 | **区间 / 关系 / 形状 / 色彩配比** | 某个**点值**（中位、某一档、某个 p95） |
| 判成功的条件 | **落进可行域**就算成，域内不排名 | 越接近那个点越好 |
| 解不唯一时 | 取**旋钮动得最少**的那个解 | 继续调到手头这个数等于卡 |
| 卡的数字角色 | **边界与线索** | **目标** |
| 破了时怎么办 | 记账（哪条域没落进去、差多少） | 改参数再导 |

★ 一句话：**"落在卡的区间里"是充分条件；"等于卡的中位"不是目标。**
★ 检验方法：把卡的中位整体平移 2 L\*，如果我的解跟着动 ⇒ 那是打靶；如果解只在跨出区间时才动 ⇒ 那是对齐。

## 41 为什么"剂量公式"必须废

上一版的剂量是 `(目标 − 现脸) / 常数`，并封顶。它有两个死穴：

1. **目标是点值** ⇒ 打靶。1627 打到封顶，人物浮出。
2. **主体蒙版是整人均匀提** ⇒ 脸和衣服一起亮，人脸一旦超过环境，人就"贴"在背景上。

替代：**⑦ 只提"人身上的暗部"**（主体蒙版 ∩ 亮度范围），并且**被 §40② 的可行域夹住**。
在这样的约束下，剂量不是算出来的一个数，而是**求解器在可行域内的可行解**。

## 42 顺序与解锁（从粗到细）

```
② 曝光 → ③ 白端 → ⑤ 黑端 → ④ 高光/阴影 → ⑥ 曲线 → ⑦ 局部 → ⑧ 彩色
```

- 每一步只在**上一步的不变量成立**时才做（② 破了先去修 ②，不许往下做）
- ④ 必须在 ③⑤ 之间做：白黑两端定了，高光阴影才有意义
- ⑦ 最后做，因为它最容易把人从环境里拔出来；做完必须用 §40② 的关系复核
- 每一步不达标 ⇒ **记账**（写进 notes：哪个不变量、差多少、归哪一层），不许就地试参数

## 43 局部层（⑦）：人物蒙版承载的是一整套旋钮，不是一个曝光值

```
蒙版形态：主体（subject）× 亮度范围（只对暗部生效）—— 纯主体蒙版会把人整体提亮，人必浮出
蒙版内部（允许，且**只**这些）：
    局部曝光 · 局部高光 · 局部阴影 · 局部白 · 局部黑 · 局部对比 · 局部曲线 · 局部饱和
    颜色（色相/彩度）也在这层做 —— 但**亮度不许用彩色去修**，反之亦然
```

**为什么是"一整套"而不是"一个曝光值"**（这是这一版设计的关键改动）：

- 整人均匀提曝光 ⇒ 脸亮了，白衣服也亮了，人从环境里拔出来（1627 的实证）。
- 局部层能做的正解是**在人的内部改影调形状**：抬"人身上的阴影"、同时把"人身上的白端"压住 ——
  脸亮起来，衣服不跟着炸，人还留在环境里。这是全局那几根旋钮做不到的（它们一动就是整幅）。

**三条边界**：

```
· 关系守卫：做完必须满足 §40② 三条关系，否则回退（不是加档，是退回上一个可行解）
· 不改整幅：局部层不许动到蒙版外的像素（S2 选择性门）
· 上限由可行域定：不存在"最多提几档"这种常数；可行域是关系围出来的
```

**和全局那七步的关系**：⑦ 是**收尾的最后一层**，不是"另一套全局"。
全局（②③④⑤⑥）定的是"这张片子整体长什么样"；⑦ 只回答"人在这张片子里够不够、像不像人"。

## 44 什么算成功 / 不做什么

```
成功 = 不变量全过 + 三条关系成立 + 人目检同意     （三条缺一不算）
不做 = 打靶（点值/封顶/给多少算多少）
      · 拿 LR 当标定台（跑一轮看给多少）
      · 闭环（读 ③ 改参再导）
      · 为单张图打补丁
      · 把"多做几根旋钮"当成"多做一件事"（②③④⑤ 是一件事的四个面）
```

## 45 与引擎的分工（不变）

```
引擎：卷/纸（风格）· 颗粒/光晕/柔光（质感）· 自己的测光出片 · 报"还能抬几档" · 白点
LR  ：落点（②）· 白黑两端（③⑤）· 影调形状（④⑥）· 局部（⑦）· 颜色（⑧）
人  ：意图（亮/暖/浓/软）· 审片
```

## 47 公式与数值的出处（**不许自己跑标定**）

> 规矩：凡是**能查、能推**的量，一律查或推；只有"公开数据里没有、又必须有个数"的，才许从
> **大师语料的区间**里取（那是数据，不是我的实验）。**任何"我渲一批量出来"的常数，作废。**

### 47.1 三类来源，按优先级

| 优先 | 来源 | 例 |
|---|---|---|
| ① 标准 / 定义 | CIELAB、感光测定标准 | L\*↔Y 互换；RMS 粒度的定义 |
| ② 论文 / 厂家数据表 / 厂商文档 | 胶片 datasheet、光源与打光文档、肤色偏好研究 | 影调肩部形状；主光:辅光比；记忆色方向 |
| ③ 大师语料的**区间** | 我们自己的语料测量（64 张匹配卡 + 733 张成片） | 可行域的上下界（见 §40②） |
| ✗ 我跑的标定 | 渲一批、量一量、凑一个数 | **全部作废** |

### 47.2 逐项出处（本设计用到的量）

| 量 | 出处 | 用法 |
|---|---|---|
| L\* ↔ 亮度 Y | **CIELAB / CIE 1976 定义**（分段式，可逆） | 直接算，不测 |
| 每档曝光抬多少 L\* | **CIELAB 的局部斜率** `dL*/dlog2Y`（`expose.eval_slope`） | 算，不测；它随起点变化（暗处小、中调大），这本身就是标准的一部分 |
| 主光:辅光比 | 厂商与教材口径（Sekonic《Studio Lighting: Understanding Ratios》；[链接](https://global.sekonic.com/classroom/studio-lighting-understanding-ratios/)） | 只给**方向与档级**（2:1=1 档、4:1=2 档…），不给"我们该补几档" |
| 颗粒 RMS 粒度 | **ANSI/I3A IT2.40**（RMS granularity，48 µm 孔径、净密度 1.0；对应 ISO 6328 一类） | 引擎的 `rms_granularity` 就是按这个规格实现的，直接引用 |
| 胶片肩部 / 趾部形状 | 厂家 datasheet 的 D-logE 曲线（Kodak/Fuji） | 形状靠卷纸，不靠 LR 曲线去造 |
| 肤色偏好（"白、有血气"） | 视觉研究：记忆色/偏好肤色比实测更亮、略更饱和（如 [Vision Research 2023 不同肤色组的偏好肤色](https://www.sciencedirect.com/science/article/pii/S0042698923000342)、[Color Research 肤色印象建模](https://onlinelibrary.wiley.com/doi/pdfdirect/10.1002/col.70114)） | **只当方向**；剂量进可行域，不设点值 |
| 逆光/开放阴影比直射低几档 | 摄影实践口径（开放阴影约 2~2.5 档） | 只当"关系的量级"，具体区间从语料取（§40②） |
| **LR 的 Highlights / Shadows / Whites / Blacks** | **无公开传递函数**（Adobe 只说"按亮度区域自适应、比曲线复杂"；第三方是对手感的仿写） | 只当方向；幅度靠"一次算、一次验" |
| **LR 点颜色的 SatScale / HueShift** | **无公开式** | 同上 |
| 可行域的区间上下界 | **大师语料**（`refcards` 的 profile ± IQR） | 这是唯一"自己标"的合法部分，而且标的是**区间** |

### 47.3 操作规则（写死，防止再犯）

```
1. 需要一个新常数时，先问三句：
     a. 标准/定义里有没有？        → 有就直接算（例如 L* 与 Y 的互换）
     b. 论文/厂家数据/厂商文档有没有？→ 有就引，并写进注释（不写在这份设计里）
     c. 都没有？                  → 只许从**大师语料的区间**取，且取的是**区间**
2. 任何"我渲一批、量出来"的常数，一律不许进代码。我已经犯过一次：
   把 20 L*/档、12 C/单位、62、1.0 档封顶 写进了常数区 —— 全部作废。
   其中"每档抬多少 L*"本来就是 CIELAB 能算的，根本不该去测。
3. 查不到闭式的（LR 的 Highlights/点颜色），**不许编斜率**，只能：
   给方向 · 一次算 · 一次验 · 记账。
```

## 48 术语更正（2026-10-29 深夜）：**只有一种卡 —— 匹配卡**

### 48.1 作废的旧概念（文档与代码里都要删干净）

| 作废 | 为什么 |
|---|---|
| **生产卡**（卡38 / xhs预设 / 滨田预设 那三张） | 它把"介质"和"风格"切成两层，结果匹配只能选卷纸、风格另算 —— 匹配就没用了 |
| **参照卡**（64 张大师画像，只用来出网页） | 同上：画像算完就扔，一套也没进过求解 |
| **大师预设 / 大师卡 / 大师成片区** | 更老的概念（"照大师配方调我们的预设"），方向早就废了 |
| 任何"选卡 → 再套风格"的两层说法 | 现在只有一层 |

### 48.2 现在只有一种卡：**匹配卡**

一张匹配卡 = **一套风格**，自带三样东西：

```
① 介质：卷 / 纸 / 画幅
② 画像：分布区间（p5/p25/p50/p75/p95/clip/p1）· 脸 L/C/h
        关系（脸/背景亮部、人物中位/背景中位、暖冷、光比）
        形状（toe / shoulder / contrast_win / skew）
        色彩（中性轴五段 a/b、色相六段 share 与 C）
③ 风格档：柔光 / 光晕 / 颗粒的强弱档
```

**匹配 = 从所有匹配卡里挑最贴这批的那一张**（或几张，人定）。
挑完之后，**引擎侧和 LR 侧的每个值都从这张卡算**：

| 层 | 算出来的东西 | 怎么算 |
|---|---|---|
| 引擎 | 印相曝光 | 一次出片内二分（黑 ≤ 卡的 p1 区间 / p95 ≤ 卡的 p95 区间） |
| 引擎 | p95_max / black_max / p5_min | **卡画像的区间**，不是卡里写死的常数 |
| 引擎 | 画幅 `film_format_mm` | 卡的介质 |
| 引擎 | 颗粒 / 染料云 / 光晕 | 卡自带的规格与风格档（**不从成片数字反推**——空间族无跨链等价） |
| LR | 可行域（区间/关系/形状/色彩） | 卡的画像（§40②） |
| LR | 每一步的边界与解锁条件 | 由同一份可行域推 |

### 48.3 每张卡风格不同 = 要的，不是 bug

同一批照片换一张匹配卡，出来的就是**另一套风格**（另一卷纸、另一套区间、另一个形状）。
⇒ **卡与卡之间的差异必须保留**；不许为了"统一"把它们抹平（以前干过：把三张同卷同纸的卡当一张算）。

### 48.4 对代码的要求（下一步，不是现在）

```

· refcards.py       并入匹配卡（画像 = 卡的一部分，不是外挂）
· flow.render_card  从**匹配卡**取介质与边界（不再有卡里写死的 96 / 3）
· lr.solve_one      新增入参：匹配卡（可行域）
· 命名              production / ref / master_preset 等字样全部清掉
```

# 第九部分 · 口径与概念（统一说法，防止各说各的）

> 这一部分只干一件事：**把词定死**。同一个词在测量、求解、验收、目检里必须是同一个意思。
> 出现新词就加在这里；**任何文档/代码/对话里用了一个这里没定义的词，先补定义再用。**

## 49 核心概念

### 49.1 肤色（skin）

```
定义  脸颊上**一个被证明是皮肤的像素**的读数（**不是圆盘中位**）。
量法  画圆（R = 0.30×脸宽）→ 圆里**取一个点** → 用四条证明它确实是皮肤：
        ① 9×9 窗局部平整（a/b 两通道 std 之和 ≤ 6）
        ② 0.06 / 0.10 / 0.14 脸宽三个尺度一致（ΔE ≤ 4）—— 皮肤在任何尺度同色，跨界就跳
        ③ 与圆内中位色接近（ΔE ≤ 8）—— 保证取的是这块脸，不是角落
        ④ L/h 落在宽窗内；且**不许是这块脸最亮/最暗的**（P8~P92）—— 高光阴影不是肤色
取样  点在 1080 域**固定**；同一张图的 ①②③ 必须用**同一个像素**
      （旧"圆盘中位"口径保留为 `SV_CHEEK=circle`，只做 A/B，不用于生产）
出处  `_corpus/kurai/full/skin_point.py` v6（2026-10-28 SV 定："圆已经画出来了，就在圆里取一个点"）
不含  嘴唇 / 眉眼 / 牙齿 / 高光点（FACE 类含它们，所以要用肤色规则再收窄）
输出  L*（CIELAB D65）· C* = hypot(a,b) · h = atan2(b,a)
出处  `_corpus/kurai/full/skin_point.py`（口径细节在那）；色彩空间 = CIELAB D65
```

★ **"脸 L" 一律指这个量**，不指脸掩膜的中位、不指脸框的均值。

### 49.2 脸 vs 人

| 词 | 是什么 | 用在哪 |
|---|---|---|
| **脸** | FACE 类（脸上的皮肤） | 判"主体够不够亮/够不够艳"——判据的**分子** |
| **人** | `1 − BG` 类（不是背景的就是人，含头发/衣服/手） | 局部蒙版的**作用域**；量"人相对背景的明暗" |
| 背景 | BG 类 | 判整幅落点、收白、白点 |

★ 三个不能混：**脸的读数是判据，人的掩膜是作用域，背景是参照。** 用人的亮度当"脸"= 把衣服算进脸。

### 49.3 光向量（light vector）

**它不是三维向量，也不是光源角度。** 它是一组**可测量的证据**，用来回答"光从哪边来、什么性质"。

```
四个分量（都能从单张成片算出来）：
  ① dLR     脸局部坐标下的左右明暗差（再换算到**画面**左右；正 = 画面右亮）
  ② rn90    脸中位 ÷ **近邻背景**的 p90   （近邻 = 外扩约 0.9 个脸宽）
  ③ hvf     发丝 p90 − 脸中位
  ④ clump   脸内 L 去掉一阶斜坡后的残差 std ÷ 脸反差（斑驳/缝隙光）

产出的标签（back / back_side / side / front / dappled）是这四样的**离散化**，
只用于**报告、分组、选区间**，**不直接给任何剂量**。
```

**它做不到的（写在这里防误用）**：
- 前后（z）分量：单图没有深度 ⇒ 推不出"光在身后多远"
- 顶光：上下半脸的差被眼/眉/嘴污染（语料中位就是下比上亮），**量不出来**
- 绝对角度：只有"哪边 + 多强"，没有"多少度"

**用法**：**前馈**（只读 ①，不读 ③），决定用哪一套区间/关系；人可用 `--light` 覆盖。

★ 早期两版自动判据都出过反例（脸÷背景中位、脸vs背景p90），所以现在的口径是
**"宁可弃权"**：证据不够就 unknown，不许猜。

### 49.4 背景：全幅 vs 近邻

| 词 | 定义 | 只能用在哪 |
|---|---|---|
| **全幅背景** | BG 类的全部像素 | 整幅落点、收白、白点 |
| **近邻背景** | BG 类 ∧ 外扩（约 0.9 个脸宽）之内 | 判逆光/侧逆、判"人有没有浮出" |

★ 用全幅背景判逆光 = 会被远处的太阳楼骗（已出过事）。**判光位只用近邻。**

### 49.5 亮度与影调

```
亮度一律 CIELAB D65 的 L*（0–100，浮点）。
统计在**原生分辨率**上做；检测（掩膜/人脸）在 1080 上做再放大 —— 这是测量层的口径。
五分位 p5/p25/p50/p75/p95；形状四项：
  toe = p25 − p5 ｜ shoulder = p95 − p75 ｜ contrast_win = p75 − p25
  skew = (p50 − p5) / (p95 − p5)
白点 = 背景 ∧ L ≥ p95(背景) 的 a/b 中位（用来判白不白、偏不偏色）
```

### 49.6 单位与刻度

```
EV（档）      1 EV = 光量 ×2
每档抬多少 L* 由 CIELAB 局部斜率决定：dL*/dlog2Y = 0.231 × (L + 16)   ← 算，不测
LR 局部曝光   写进 LR 的 LocalExposure2012 = EV ÷ 4（已验三档）
```

## 50 三个判定层，以及它们的优先级

| 层 | 是什么 | 破了算不算错 | 谁给 |
|---|---|---|---|
| **不变量** | T1~T5 / S1~S5（+ 引擎侧 T0） | **算错**，与风格无关 | 物理 / 量化下限 / 生理常识 |
| **可行域** | 匹配卡给的区间 / 关系 / 形状 / 色彩 | 不算错，但**不算完成** | 匹配卡 |
| **意图** | 亮/暖/浓/软 | 不算错，可为空 | 人 |

```
优先级：不变量 > 可行域 > 意图
例外（写死）：脸 vs 背景高光冲突时 —— **脸优先**（背景可以过曝，脸不许被压暗）
```

# 第十部分 · 求解算法 · 验收记账 · 交接契约 · 卡的字段 · 完整流程

## 52 求解算法：哪些能算、哪些不能、一次算怎么编排

### 52.1 按"可算性"分三档（这决定了一次算能不能成立）

| 档 | 旋钮 | 为什么 | 用它的方式 |
|---|---|---|---|
| **可算**（有闭式） | 全局 `Exposure` | `ΔL = eval_slope(L)·EV`，`eval_slope(L)=0.231(L+16)`（CIELAB 推出来，不用测） | **反解**，一次到位 |
| **可算** | 点曲线 | 曲线是我们自己造的 16 点 LUT，位移是显式映射 | **直接算**锚点位移 |
| **可算** | 局部 `LocalExposure` | 写进去 `= EV/4`（已验），ΔL 同样用该处的 `eval_slope` | **反解**，一次到位 |
| 半可算（无公开式） | `Whites` / `Blacks` / `Highlights` / `Shadows` | Adobe 只说"按亮度区域自适应"，第三方是对手感的仿写 | **只在撞边界时做最小修正**，方向明确、幅度取最小步；**不许拿它当落点主力** |
| 不可算（黑箱） | 点颜色 `SatScale` / `HueShift` | 无公开式 | **只给方向**，出片后一次验 |

★ 结论：**"一次算准"的负担全部压在可算的三根上**（曝光 / 曲线 / 局部曝光）；
半可算的四根只做"别越界"；黑箱那根只做方向。

### 52.2 一次算的编排（顺序即依赖）

```
1. 目标区间 ← 匹配卡的可行域（§40②）
2. 曝光   ← 反解（整幅落进区间；脸**不参与**决定）
3. 曲线   ← 显式 LUT 修残差形状（预算内）
4. 局部   ← 反解（只对人；主体 ∩ 亮度范围；被 §40② 关系夹住）
5. 白/黑/高光/阴影 ← 只在 3、4 之后**撞界**时做最小修正（一档为止）
6. 出片一次 → 量 → 验 → 记账
```

**禁止**：第 5 步之后回到第 2 步。那就是闭环（手册"必然振荡"）。
若第 6 步发现不可算的四根没调好 ⇒ **记账，不改参数再导**。

## 53 验收与记账（闭环的后半段）

### 53.1 验收只做一次、只量一份

```
时机：出片之后（③），一次
用量：③ 的测量，**口径与 ① 完全一致**（同一个取样像素、同一套统计）
```

### 53.2 门分三类

| 类 | 内容 | 破了怎么办 |
|---|---|---|
| **硬门（不变量）** | T0（clip / p95 / p1）· T4（脸在区间）· T5（脸不灰）· S1（改色不改明暗）· S2（不动全局）· S3（曲线预算） | 停下，报出来；**不许改参再导** |
| **软门（只报）** | 白点绝对值（卷/纸的账）· 背景爆白（脸优先，可接受） | 只记，不拦 |
| **可行域** | 落进匹配卡的区间/关系 = 完成 | 出界就记账，**仍可交付** |

### 53.3 记账：一条一笔，必须有落点

```
每笔账的字段（写死）：
  哪一条（T4 / rn90 / p95 …）· 实测值 · 门或区间 · 差多少 ·
  归哪一层（卡 / 引擎 / ②③④⑤⑥⑦⑧）· 建议动作（换卡 / 改边界 / 不动）
```

账的去处（三处，缺一不算）：

```
· plans.json     机读（下一次求解要看）
· 验收页 HTML     人读（拍板与目检用）
· 交接.md         跨会话（谁接手都能看到账在哪）
```

## 54 交接契约：① 交给 LR 时必须带什么

```
必须带：
  亮度层 img（七分位 + clip）· shape（toe/shoulder/contrast_win/skew）
  背景 全幅 bg（L/L_p10/L_p90/C/a/b）· near_bg（近邻）
  肤色 skin（L/C/h/xy/rgb）+ 取样可信度
  脸 face_w / face_size / FACE 与 person 掩膜统计
  白点 white_point（a/b/C/L_thr）
  余量 headroom + valid（白端 <1 或被切时必须标"不可信"）
弃权标记：没脸 / 脸太小 / 取样不可信 / 掩膜缺失 —— 都要显式写，不许静默
LR 绝对不许用：③ 的任何量（除了验收那一步）
```

## 55 匹配卡的字段（§48 那张卡的字段级定义）

介质     stock · paper · film_format_mm
        纹理档：grain(rms/dye) · diffusion 档 · halation 档
画像    分布区间：p5/p25/p50/p75/p95 · clip · p1      （取 P10~P90 带，不是中位）
        脸区间：L / C / h

## 56 完整流程（从"给一个照片目录"到"验收页"）

```
0  人给：一个照片目录（可选：意图 亮/暖/浓/软）
      ↓
1  **把整个目录渲完**（不是试点 2 张）：用当前基线卡并行渲 → 量全批 ①
      为什么必须全渲：匹配的输入是"这批的统计分布"，
      2 张只能代表这 2 张；全批才有分布，匹配才有分辨力
      ↓
2  算匹配权重：**全批 ① 的测量** × 每张匹配卡的画像
      → 输出 **5 个候选**（权重 + 理由 + 代价）
      ↓
3  出匹配页 HTML：
      每个候选 = **这套大师的成片样例** + 画像摘要 + 权重 + 用它要付的代价
      ↓
4  **人拍板选一张**（这一步不许系统代选）
      ↓
5  用选定的卡求解**胶片引擎**：
      印相曝光（在卡的区间内二分）+ 介质/纹理 → 渲全批 ①
      · 卡与基线卡**同卷同纸** ⇒ 直接复用步 1 的 ①（不重渲）
      · 不同 ⇒ 重渲一遍（代价照实报：并行下 10 张约 2 分钟）
      ↓
6  用同一张卡求解 **LR 七步**：一次算 → 出 ③ **一次**
      ↓
7  验收 + 记账 + 出**验收页 HTML**（硬门/软门/可行域 + 每笔账）
```

### 56.1 为什么第 1 步必须全渲

```
· 匹配比的是**分布**（clip 中位、天空占比中位、背景跨度中位）⇒ 样本越多越稳
· 2 张的"中位"就是那 2 张，换一张就变；全批才谈得上"这批像谁"
· 全渲的代价已经被并行吃掉（引擎 7 路）⇒ 这一步不再是瓶颈
```

### 56.2 环在哪、不回头的地方在哪

```
闭环只闭在"账"上：7 的账 → 交接/plans.json → 下一次开工读它
**不闭在"这张图上"**：7 出问题不改参数重导（那是闭环）
唯一的例外：人看完 3 或 7 决定**换一张卡** ⇒ 回到 4（这是人的决定，不是系统的迭代）
```

### 56.3 每步的产物（谁给谁什么）

| 步 | 产物 | 给谁 |
|---|---|---|
| 1 | **全批** ① + 全批测量 | 步 2 |
| 2 | 5 个候选 + 权重 + 理由 + 代价 | 步 3 |
| 3 | 匹配页 HTML（含大师成片样例） | **人** |
| 4 | 选定的那一张卡 | 步 5、6 |
| 5 | 用选定卡重渲的 ①（同卷同纸则复用步 1）+ 余量报告 | 步 6 |
| 6 | ③ × N + plans.json | 步 7 |
| 7 | 验收页 HTML + 账 | **人** + 交接 |

## 57 匹配算法（第 2 步怎么算"最像哪张卡"）

> 这一节把**已有的两条资产**接起来：分面标签（定性）与数值画像（定量）。
> 它们以前各跑各的（标签只出网页、`rank_refs` 只比 5 个数值），**没有一处把它们合成一个分数**。

### 57.1 两条通道，各自只负责自己擅长的

| 通道 | 比什么 | 数据在哪 | 作用 |
|---|---|---|---|
| **分面标签**（定性） | 光（source/direction/quality）· 场景（place/type/subtype）· 色彩（color_env）· 构图（framing/subject_position）· 服装 · 背景（palette/type） | `tags_all.json`（64 卡）· 码本 `tagging_method.md` | 回答"这批的**情境**像哪一套" |
| **数值画像**（定量） | p5 / p50 / p95 / contrast / clip / 天空占比 / 背景跨度 | `refcards.profile`（64 卡，中位 + IQR） | 回答"这批的**明暗结构**像哪一套" |

### 57.2 ★ 哪些维度**不能用**（这条比用什么更重要）

```
禁用（自指）：肤色 L/C/h、中性轴 a/b、暖冷 b
  为什么：这些量是**当前基线卡**造出来的，不是这批照片的属性。
  拿它们去比候选卡的画像 ⇒ 分数会系统性地偏向"和基线卡像的卡"，
  换句话说：越比越像基线卡。这是**自指**，不是匹配。

禁用（同源自指）：任何在 ①（已经过了胶片）上算的颜色量
  颜色维只能走**标签通道**（"这套是钨丝暖光 / 阴天冷调"），不能走数值通道。
```

### 57.3 权重从哪来（不许拍）

| 通道 | 权重的出处 |
|---|---|
| 分面标签 | **κ**（评分者一致性，已有 `validation.json`）。κ 高的分面权重大：它说明这个标签**人也能稳定判**；κ 低的分面（如 `composition.framing` κ≈0.21）**降权或不用** |
| 数值画像 | **IQR 归一化**（已有 `refcards.rank_refs`）：每一维用 64 张卡自己这一维的离散度当尺子 |

★ 两条都**不用手调系数**：κ 与 IQR 都是从数据来的。

### 57.4 合成与取 5 个

```
总分 = w_label × 标签距离 + w_num × 数值距离
       （两项都归一化到 0~1；w 的比例取两通道的可用维度数之比，不手调）
排序 → 取前 5 个 → 每一个附：
   · 命中的分面（"光: 阴天柔光 / 场景: 街拍 / 色彩: 冷调"）
   · 差在哪（数值上哪一维偏几个 IQR）
   · **代价**（见 57.5）
```

### 57.5 "代价"是什么（页面上必须显示的东西）

```
代价 = 这张卡**做不到**的地方（来自它的介质与画像）：
   · 余量：它的 p95 区间比我们这批的场景亮部还低 ⇒ 用它要压暗
   · 颗粒：它要求 rms 超出卷的规格表能给的 ⇒ 做不到（空间族无跨链等价）
   · 形状：它的 toe/shoulder 与我们这批的分位差得远 ⇒ 只能靠卡换，LR 不许造
   · 画幅：不同画幅 ⇒ 空间族整体缩放
每一条都要能落到"换它以后画面会变成什么样"，不是一句"分低"。
```

### 57.6 5 个都不行怎么办

```
不做"次优里选一个"的自动兜底。走**做新卡**（人定）：
· 页面直接写"这 5 张都不是这套的方向"
· 给出最接近的两张 + 差在哪个维度 ⇒ 作为新卡的起点
```

### 57.7 代码现状（已有 / 缺）

```
已有：refcards.rank_refs（5 维数值距离 + IQR 归一化）
      tags_all.json（64 卡的 7 个分面标签）
      validation.json（每个标签的 κ —— **权重出处已经在了**）
      master_features_*.json / embeddings_resnet50.npz（画风检索，可作并列参考）
缺：  把标签通道接进分数；κ 加权；**排除自指维**（现在 rank_refs 里 L/C/h 还在比）
      代价计算；5 个候选的页面
```

## 59 意图与批次

### 59.1 意图怎么进匹配

```
意图**不改变"像哪一套"**，只改变候选之间的**排序偏好**：
  更亮 → 偏向 p50/p95 区间偏高的卡
  更暖 → 偏向暖冷值偏正（暖）的卡
  更浓 → 偏向色相六段 C 偏高的卡
  更软 → 偏向颗粒更细 / 柔光档更高的卡
意图为空 ⇒ 不参与排序（不许给默认值）
```

### 59.2 意图怎么进求解

```
意图只产生**偏移**，且偏移必须落在可行域内。
出域 ⇒ **取边界**（贴着区间边缘停），不是破域。
```

### 59.3 一张卡对整批

```
默认：**一批一张卡**（人拍板的那张），全批用它。
混合批（同一目录里明显两种场景）：
  · 不自动拆
  · 匹配页上写一句"这批可能含两类场景（依据：光位/场景标签分布是双峰）"
  · 拆不拆由人定；拆了就变成两批、各拍一张卡
```

### 59.4 换卡要留痕

```
换卡 = 人的决定，但必须记：
  换前卡 / 换后卡 · 换的原因（人说的那句话）· 影响哪几张 · 是否重渲
换卡之后从**步 5**重来（不是从步 2）
```

# 第十二部分 · 求解设计（细化）与测量契约

> 这一部分是 §52 的落地细化 + §54/§55 的字段级契约。
> **目的**：让人可以拿这份去重测大师作品，也让代码有唯一的字段真源。

## 61 求解设计（细化到能写代码）

### 61.1 三根可算的旋钮：反解式

```
① 全局曝光 Exposure
   目标：把整幅的 p50 放进卡的 p50 区间（只在出界时动）
   ΔL = eval_slope(L_p50) · EV,   eval_slope(L) = 0.231·(L+16)      ← CIELAB，可算
   ⇒ EV = (clamp(p50, 区间) − p50) / eval_slope(p50)
   注：斜率随起点变，所以必须在**当前 L** 上算，不能用一个常数（老错）

② 点曲线（16 点 LUT，显式）
   目标：把**形状**（toe/shoulder/contrast_win/skew）拉进卡的形状区间
   每一步 = 一个锚点的垂直位移；位移直接写进 LUT ⇒ 位移量就是答案
   预算：每锚点 ≤3 L*（S3）；超预算 ⇒ 记账，不许加宽

③ 局部曝光（主体蒙版）
   目标：把人（含脸）的中位/亮部放进 §40② 的关系区间
   LocalExposure2012 = EV/4  ⇒  EV = 4 · LocalExposure2012
   ΔL = eval_slope(L_person) · EV    ⇒  EV = ΔL / eval_slope(L_person)
```

### 61.2 三根半可算的：只做"撞界最小修正"

```
Whites / Blacks / Highlights / Shadows：无公开传递函数 ⇒ **不许当落点主力**
用法（写死）：
  · 触发：只有当 ①②③ 之后，white/clip 仍越界，或 black/p1 仍越界
  · 幅度：一档最小可行（LR 的最小可见步），**不迭代第二次**
  · 记账：动了几档、为什么、还差多少
```

### 61.3 求解顺序与"一次算"的边界

```
可行域(卡) → ① 曝光 → ② 曲线 → ③ 局部 → ④ 撞界最小修正 → 出片一次 → 验
                                                              └→ 不达标：记账，不回头
```

### 61.4 冲突消解（写死优先级）

```
1. 硬不变量（T0~T5 / S1~S5）永远优先
2. 硬不变量互斥时：**脸优先于背景高光**（§50 的例外条款）
3. 可行域内多解：取**旋钮动得最少**的解
4. 可行域不可达：贴着最近的边界停，并记账"这条没落进去"
```

### 61.5 失败怎么记（一条一笔，结构化）

```
{ dim: 'p95' | 'face_L' | 'person_vs_bg' | ...,
  got: 95.7, want: [88.0, 93.0], gap: +2.7,
  layer: 'card' | 'engine' | 'exposure' | 'curve' | 'local' | 'white' | 'color',
  action: 'none' | '换卡' | '改边界' }
```

## 63 卡 = 一个目录（2026-10-29 SV 定，**以此为准**）

### 63.1 规则

```
一个目录 = 一套大师作品 = 一张匹配卡 = 一种风格。
新增大师作品 ⇒ 放一个新目录 ⇒ **它就是一张新卡**，零配置。
```

这条是 SV 定的工作流：**可扩展**比"统计上更纯"重要。下面写清"卡里装什么"，
让这条规则不靠统计假设也站得住。

### 63.2 卡里装什么、不装什么

| 装 | 为什么 |
|---|---|
| **样片**（目录里的代表图） | 人拍板看的是这个；它才是"风格"的直接证据 |
| **界面**：卷 / 纸 / 画幅 / 纹理档 | 介质就是风格的一半（§48.2） |
| **形状**：toe / shoulder / contrast_win / skew | 影调的"性格"，与拍什么无关 |
| **色彩**：中性轴 a/b、色相六段 share/C、暖冷 | 色彩渲染的性格 |
| **关系**：脸÷背景亮部、人÷背景中位、光比 | 相对量，抗内容（拍亮处拍暗处都成立） |
| **光**：source/direction/quality 分布 | 这套作品多在什么光下 |

| **不装** | 为什么 |
|---|---|
| **绝对落点**（p50 / p95 / clip 的分布） | 它随**拍什么**变，不随**风格**变。拿它当可行域 = 把场景当风格 |

### 63.3 证据（方差分解，`design/style_or_scene.py`）

对鹿井 62 套 662 张算"套内方差 ÷ 总方差"（w）：

```
w 小 ⇒ 由"哪一套"决定 = 风格量；  w 大 ⇒ 由"哪一张"决定 = 场景量

bg.a 0.55 · bg.b 0.60 · shape.skew 0.60 · shape.toe 0.60 · img.contrast 0.60
img.p50 0.62 · warm_cool_b 0.58 · light_ratio 0.64 · img.p95 0.66 · skin.h 0.70
shape.contrast_win 0.72 · bg.L_p90 0.74 · skin.C 0.76 · img.clip_pct 0.78
```

**读数**：所有量都在 0.55~0.78，即"套内变化 ≈ 套间变化"。
这不是"目录不是一种风格"，而是——**我们量的这些数，本来就被"拍什么"主导**。
所以：

```
· 目录仍然是卡（SV 的规则，保留）
· 但卡的**数值可行域**只收"形状 / 色彩 / 关系"（相对量），
  **绝对落点不进可行域** —— 它由批自己的直方图 + 不变量（T0/T1）管
· 套内的分布区间只当**参考**（在匹配页上显示"这套通常落在哪"），不当门
```

### 63.4 对前面条款的修正

```
§40② a「分布区间」 —— 降级为**参考**，不进可行域；可行域 = b 关系 + c 形状 + d 色彩
§55「画像：分布区间」 —— 保留但标注"只作参考与代价，不作门"
§62.2「分布 p10~p95」 —— 仍然要测（分析要用），但**不喂给求解器的可行域**
```

### 63.5 这条规则为什么可扩展

```
新增作品 → 新目录 → 新卡（样片 + 介质 + 形状/色彩/关系）→ 立刻能出现在匹配页里
不需要：重新标定、重新拟合、改代码
```

# 第十三部分 · 求解要什么数据（按机制）· 新增大师卡的测量流程

> §62 是按字段列的；这一部分按**机制**列，并且给出"新加一个大师目录卡"的固定流程。

## 64 每个机制吃什么（按机制，不按字段）

### 64.1 匹配机制（选哪张卡）

| 吃 | 粒度 | 来源 | 现状 |
|---|---|---|---|
| 这批的场景特征：天空占比、背景跨度、光位分布 | 批（多图统计） | 我方 ① | ✓ |
| 卡的**分面标签**：光 / 场景 / 色彩 / 构图 | 卡（一套一个分布） | 大师目录标定 | ✓ |
| 卡的**样片** | 卡 | 大师目录 | ✓ |
| 分面权重 = **κ** | 全局 | 两人复核 | ⚠ 光分面没有 κ |

**禁用**：我方自己的颜色（自指）、绝对落点（§57.2 / §63）。

### 64.2 光向量（前馈：决定用哪套区间）

| 吃 | 为什么 |
|---|---|
| 脸局部坐标（双眼线 + 眼→嘴轴） | 把"左右"换算到画面坐标，不然左右会反 |
| **近邻背景**（外扩 0.9 脸宽）的 p90 | 判逆光只能用近邻，全幅会被远处的太阳骗 |
| 发丝区 p90 − 脸中位 | 轮廓光证据（`rim` 已有近似量） |
| 脸内亮度去掉一阶斜坡后的残差 | 斑驳 / 缝隙光 |

产出 `d_lr_img / ratio_near90 / hvf / clump` → 离散成 back / back_side / side / front / dappled。
**只读 ①（前馈），不读 ③。** 顶光与前后（z）分量**测不出来**（§49.3）。

### 64.3 ★ 背景—人物亮度关系（现在最缺的一块）

| 吃 | 现状 |
|---|---|
| **人体掩膜** 的 L 中位 / p95 / 占比 | ❌ 大师数据里**没有** `person` 这一块 |
| 背景（全幅 + 近邻）的 L 中位 / p90 | 全幅有；近邻缺 |
| 两者**在同一张图内**的差 | ❌ 缺 |

**为什么最关键**：1627 的"人物浮出画面"就是没有这条约束。
**必须是同一张图内同时量的两个数** —— 拿"这批的脸"减"那套的背景"是两件事，不成立。

### 64.4 胶片引擎求解

| 吃 | 从哪来 |
|---|---|
| 卷 / 纸 / 画幅 / 纹理档 | 卡的介质（§55） |
| p95 ≤ 93 · clip < 0.5% · p1 ≥ 1.0 | **不变量**（§63.7），不来自卡 |
| `headroom_ev` + 可信标记 | 引擎出片时报（只对线性底片有意义；大师成片没有） |

**不需要**：卡的绝对落点、颗粒的数值对齐（空间族无跨链等价）。

### 64.5 LR 七步

| 步 | 吃 | 可算性 |
|---|---|---|
| ② 曝光 | 整幅 p50 + 区间 | 可算（CIELAB 反解） |
| ③ 白端 / ⑤ 黑端 | clip_pct · p1 · p5 | 半可算（只知方向） |
| ④ 高光 / 阴影 | 亮部占比 · 暗部占比 | 半可算 |
| ⑥ 曲线 | 形状四项 + 卡的形状带 | 可算（显式 LUT） |
| ⑦ 局部 | 人物/脸的量 + **人 vs 背景关系** + 掩膜 | 可算（EV/4） |
| ⑧ 彩色 | 肤色 C/h · 中性轴 · 色相六段 · 暖冷 | 半可算 |

### 64.6 三种数据来源，不许混

| 来源 | 提供 | 特点 |
|---|---|---|
| **大师作品** | 卡：样片 · 形状 · 色彩 · 关系 · 光分布 | 一次测、长期用；**只作可行域与参考** |
| **我们自己的批** | ① / ③ 的逐图测量 | 每批现测；①②③ **同口径同点** |
| **不变量与物理常量** | p95≤93 · clip<0.5% · EV 换算 · CIELAB | **不来自任何测量** |

混用的三种典型事故：拿大师的背景当我们的背景 · 拿成片的 p95 当底片的 p95 · 拿不同 caliber 的数据相减。

### 65.3 五步

```
1 逐图测       每张图按 65.2 出全量（点口径；掩膜在 1080 域算再放大）
2 自检         design/measure_audit.py <该语料的测量文件>
               必须过：点口径三条证明 0% 超限、脸宽够、n 够
3 套内聚合     每张先算，**再在套内取分位**（P10~P90）；不许先平均再算
4 生成卡       样片 3 张 + 介质（卷/纸/画幅）+ 形状/色彩/关系 + 光分布 + n
5 登记         卡名唯一 ⇒ 自动出现在 `design.cli cards` 与匹配页里；零配置
```

### 65.4 卡生成后要过的自检（四条）

```
① 字段齐全：65.2 里"必需"的一项不缺
② 口径一致：与已有卡是同一个 measure_sha；跨版本不许混
③ 套内一致性：p50 的 IQR 只作**参考**（§63.3），不因它大就判这张卡作废
④ 不许进门的量：绝对落点 / clip 只进"参考与代价"，不进可行域（§63.4）
```

### 65.5 一句话

```
新目录 → 按 65.2 测 → 过 65.3 的自检 → 它就是一张新卡。
不改代码、不改阈值、不重新标定。
```
