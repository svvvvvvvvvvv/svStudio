## 2 误差预算：每段只允许吃这么多

没有预算，就会"下游帮上游擦屁股"——曲线把引擎的错掩掉，点颜色把介质的错掩掉，
于是永远不知道哪一段不对。所以先定预算：

| 段 | 谁 | 允许吃掉的误差 | 超了怎么办 |
|---|---|---|---|
| 曝光落点 | 引擎（测光掩膜） | 脸 L 中位 ±1.5 | 换掩膜档位；仍不行 ⇒ 判卡不匹配 |
| 明暗分布 | 引擎（卷/纸形状） | gq 五个分位各 ±3 L* | 超了说明介质形状不对 ⇒ **不许曲线补**，回 L0 |
| **曲线位移** | LR | 每个锚点 **≤3 L\*** | 超了 ⇒ 介质形状不对 = 换卷/纸（**人定**） |
| 白点 | 引擎（入口 WB） | a/b ±2 | 超了 = 入口参数没解对 |
| 彩度（脸） | 引擎 amount | **+1.8 C**（见 §4） | 超了 ⇒ 换卷/纸 或 交 LR（须在 LR 量程内） |
| 色相（脸） | 引擎 γ | ±10°（贵，见 §4） | 超了 ⇒ 换卷/纸 |
| 肤色残差 | LR 点颜色 | ×2.2（两票叠加） | 超了 ⇒ 卷纸层的账（换卷/纸，**人定**） |

**这条表的作用**：曲线和点颜色都有"能吃多少"的上限。上限不是技术限制，是**诊断边界**——
一旦某一段顶到上限，说明错在它上游。

## 3 引擎求解的三个修正（这一轮想清楚的）

### 3.1 L2 是「选」，不是「解」

上一轮我写"L2 逐图只许动测光掩膜 + 锚权重"。想深一层：**这不是求解，是选择**。

- 掩膜只有几档：`matrix`（整幅）/ `person`（人）/ `face`（脸）
- 锚权重 `w` 是混合系数（`ev' = (1−w)·ev + b`）

所以 L2 的正确形式是：**按图的类别查表选档**，选完渲一次验证，**不做反馈迭代**。

分类依据（都能从我们的测量里拿到）：
```
有脸且脸够大 → face 掩膜
有脸但脸小   → person 掩膜
没脸         → matrix
逆光（脸/背景亮度比 < 1.0）→ 加大 w
顺光（比 > 1.3）           → 减小 w
```
这样既避免振荡（不是反馈），又利用了手册那条"有脸用脸 r²=0.890"。

### 3.2 amount 与 γ 不是"联合解"，是"先 C 后 h 补偿"

上一轮我写"amount 与 γ 必须二维联合解"。想深一层：**两者的代价差 7 倍**，不该平权：

| 旋钮 | 对 h 的斜率 | 对 C 的代价 |
|---|---|---|
| `amount` | +19.9 / 单位 | **+2.3 C / 单位**（贵） |
| `γ` | **+145 / 单位** | **+0.27 C / 单位**（≈免费） |

⇒ 正确的顺序是：
```
① 用 amount 把 C 调到靶（它会顺带把 h 推走）
② 用 γ 把被推走的 h 拉回来（γ 对 C 几乎无副作用）
③ 复查 C 是否被动（按 +0.27/单位 估，可忽略）
```
**不需要二维优化器**，因为 γ 那一侧几乎是"免费的单向补偿"。

### 3.3 每根旋钮的"可达量程 vs 实际缺口"必须对账

这是上一轮漏掉的一步。光有斜率不够，要算**能不能达到**：

| 缺口 | 数值 | 唯一可用的引擎旋钮 | 该旋钮能给的量 | 判定 |
|---|---|---|---|---|
| 肤色 C | 9.7 → 20.3，**+10.6** | `amount`（现值 1.2，上界 2.0） | +0.8 × 2.3 = **+1.8** | ❌ **差 6 倍，引擎无解** |
| 肤色 C（换 γ_blue） | 同上 | `γ_blue`（+14 C/单位） | 需 dγ≈0.76 | ⚠️ 能到，但会大幅改色相与中性轴 ⇒ **脏解** |
| 肤色 h | 48.5 → 57.2，**+8.7°** | `γ`（+145/单位） | 需 dγ≈0.06 | ✅ **便宜，能解** |
| 白点 | −1.2/−1.5 → 0 | 入口 WB（tint/温度） | 量程足够 | ✅ 能解 |
| 暖冷 b 形状 | −5.09 vs −0.45 | 连续旋钮改不了形状 | — | ❌ **只剩换卷/纸** |

**结论（这是这一轮最重要的产出）**：
- **色相、白点：引擎能解，且不贵。**
- **彩度：引擎没有干净的解** —— amount 量程只够 1/6；γ_blue 能到但会把色相和中性轴带飞。
- **暖冷形状：连续旋钮无解，只有换卷/纸。**

## 4 那彩度这笔账该谁出（三个选项，各自的代价）

| 方案 | 做法 | 代价 |
|---|---|---|
| **A 换卷/纸** | 选彩度更高的卷（或纸） | 一次换会动 4 组 couplers γ + halation，**全部靶要重解**；可能连带暖冷形状变好也可能变坏 |
| **B 交 LR 点颜色** | 用两票把肤色 ×2.2 | 能对上数；但**只改脸**，环境还是那个环境 ⇒ "脸/环境比"被人工掰正，介质本身没变 |
| **C 重新审视靶** | 承认卡 1 的彩度是被它自己的调色抬上去的 | 可能就是我们该停的地方（今天 SV 说过"昨天的成片甚至有点饱和高了"） |

**我的判断顺序：先 C（核靶）→ 再 A（换卷）→ 最后才 B。**
理由：B 是"把缺陷藏进 LR"，一旦用了，引擎那笔账就永远查不出来。

## 6 LR 这一段的内部分工（别自己跟自己打）

```
B 曲线：只搬明暗形状
   · 输入=①的 gq 五分位，输出=卡的五分位
   · 硬约束：每个锚点位移 ≤3 L*，且不许动 p50（曝光是引擎的事）
   · 它会推色相（实测 +13.8°）⇒ 记账，不在这里修

C 点颜色：只修肤色残差
   · 输入=②，靶=卡的 C/h 分布（中位 + IQR）
   · 剂量批次级一套；取样点逐图（该图自己测出来的肤色）
   · 三条硬约束：SrcHue≤5.95 · 饱和/亮度窗全开 · 必须带 ColorVariance
   · 两个门：明暗门、选择性门
```

**B 与 C 的顺序不能反**：曲线推色相 +13.8°，若先解 C，解完会被 B 再推一次。

## 7 对账：现在这批的账怎么记

```
✅ 能解：白点（入口 WB）· 色相 +8.7°（γ）
⚠️ 无干净解：彩度 +10.6（amount 只够 +1.8）
❌ 无解：暖冷 b 形状反（−5.09 vs −0.45）⇒ 只能换卷/纸
```

⇒ **这批如果只调连续旋钮，最多把白点和色相弄对；彩度和形状这两笔必须走 L0。**

所以下一步该做的不是"解一轮"，而是**先核靶**：卡 1 的彩度 20.3 到底是不是我们该追的？
如果是——那就得真的换卷/纸，而不是在 LR 里把脸掰浓。

## 8 卷子怎么选（第 2 项）

**输入**：拍摄条件（光位 / 场景 / 有无大片植被或天空）+ 目标手感（人给）。
**画像**：五个轴（从 profile 直算，不渲）：速度 · 红过量 · 蓝过量 · 反差 · 防光晕等级。
**硬约束**：卷自带配套纸（profile 里的 `target_print`）⇒ 选择空间是**三组阵营**，不是 20×8：

| 组 | 卷 | 配套纸 |
|---|---|---|
| Kodak 民品 | portra 160/400/800(+push)、gold 200、ektar 100、ultramax 400 | kodak_portra_endura |
| Fuji | c200、pro 400h、xtra 400 | fujifilm_crystal_archive_typeii |
| Kodak 电影 | vision3 200t/250d/500t/50d、verita 200d | kodak_2383 |

**流程**：先定组（组决定纸 ⇒ 白点/反差/中性滤片）→ 组内按轴挑 → 渲 1~2 张代表图验证 → 定稿后余差全交 LR。

**判据**：卷的选择由**风格意图**决定，不由数值差决定。数值只回答一件事：
**这卷能不能把系统带进「LR 补得动」的范围**。带不进 ⇒ 这卷不合适（不是这卷有毛病）。

## 9 LR 两段的细则（第 3 项）

### 9.1 B 曲线（影调）

```
输入      ①（引擎片）的整幅五分位
输出      一条 ToneCurvePV2012（16 点）→ 得到 ②
靶        目标五分位（来自卡或风格决定）
硬约束    ① 只搬形状，p50 不动（曝光归引擎；两处同时动就会打）
          ② 每个锚点位移 ≤3 L*（超了说明介质形状不对 ⇒ 换卷/纸，人定）
          ③ 曲线会推色相（实测 +13.8°）⇒ 记账，不在这里修
停止      五锚点残差 ≤1 L*，或 4 轮
失败      触界 / 不收敛 ⇒ 报出残差历史 + 触界项，不许加宽预算硬跑
```

### 9.2 C 点颜色（肤色）

```
输入      ②（过曲线未加色）的肤色点 + 目标肤色分布（中位 + 宽度）
取样点    逐图：用该图自己测出来的肤色（圆里取点 + 四条证明）
剂量      批次级一套：
            scale = (C靶 / C现 − 1) / 0.58     ← 实测：饱和 0.6 ⇒ C ×1.35
            shift = Δh / 30°                    ← ±1 = ±30°
            两者夹 ±1；超了用两票叠加（上限 ×2.2）
硬约束    SrcHue ≤ 5.95 · 饱和/亮度窗全开 · 必须带 ColorVariance
两个门    明暗门：点颜色不许改变皮肤 L 分布
          选择性门：背景 a/b 与背景占比不许动
停止      肤色中位 |ΔC| ≤ 1.4、|Δh| ≤ 5°（量化下限），或 4 轮
```

**B 必须先于 C**：曲线推色相 +13.8°，若先解 C，解完会被再推一次。

## 10 三态的交接与回归检查（第 4 项）

### 10.1 交接契约

每一态都要留一份**同口径测量**（`m_state1/2/3.json` 就是），且**代码 sha 必须一致**。
换口径 ⇒ 三态一起重测，不许只重测其中一态。

### 10.2 回归检查（防"下游替上游擦屁股"）

| 改了谁 | 必须检查 | 阈值 |
|---|---|---|
| 引擎（L1 参数） | ② 相对 ① 的**曲线位移**是否仍 ≤3 L* | 超 ⇒ 介质形状对不上 |
| 引擎（换卷/纸） | 白点、五分位、肤色 C/h 全部重测 | 任一项符号翻转 ⇒ 记一笔，别急着调 |
| 曲线 B | ③ 的肤色 C/h 变化量 | 只允许"记账量"（曲线自身的 +13.8°） |
| 点颜色 C | ③ 的皮肤 L 分布、背景 a/b | 不许动 |

### 10.3 回滚点

每步落值前存一份参数快照（引擎侧 = params json，LR 侧 = XMP）。**没有快照不许改值。**

## 11 验收口径（第 5 项）

分三层，**三层不许混**：

| 层 | 判什么 | 谁判 | 判据 |
|---|---|---|---|
| **能用**（技术底线） | 不剪、不偏、不过曝/欠 | 数值 | clip < 阈值 · 白点 a/b ±2 · 脸 L 在带内 |
| **能对**（结构） | 分布与形状 | 数值 | 五分位各 ±1 L* · 肤色**中位 + 宽度**落带 · 两个门不破 |
| **好看**（审美） | 手感 | **人** | 看片。数值只负责把它送进「值得看」的范围 |

**明确两条**：
1. **数值验收只到第二层**；第三层永远是人，不许用数值冒充。
2. 第二层的判据只用**比 / 分布 / 秩**；任何绝对量跨组相比一律无效。

# 第三部分 · 目标从哪来（2026-10-29 收尾）

> 上一节留的洞：「卡」废掉以后，"该到哪儿"没有定义了。这一节补上。

## 13 核心转换：从「打靶」改成「守不变量 + 实现意图」

旧体系：给一个数（卡的中位），解到它上面去。**问题**：那个数来自别人的成片，
而别人的成片是别人的风格 + 别人的调色 —— 追它等于追别人的口味。

新体系：不问"该到多少"，问两件事：

```
① 有没有破不变量？（破了就是错，与风格无关）
② 有没有实现意图？（意图是人给的，可以为空）
```

**意图为空时，系统只满足不变量**——输出就是"这卷该怎么出"。这才是"胶片风格"的含义：
风格来自卷、纸、显影，不来自某个数字。

## 14 不变量清单（全部可测，都有阈值）

### 14.1 技术不变量（引擎负责；破了 = 成像错误）

| # | 不变量 | 判据 | 阈值来自哪 |
|---|---|---|---|
| T1 | 白端不剪 | `clip_pct` < 阈值 | 物理：剪掉的细节不可恢复 |
| T2 | 黑端不堵 | `p1` > 阈值 | 同上 |
| T3 | 白点不偏色 | 白点 `|a|,|b|` ≤ 2 | **量化下限**（8-bit a/b 分辨率 ~1） |
| T4 | 脸不过曝/不欠 | 脸 `L*` 落在 55~85 | 生理常识区，不是某个靶 |
| T5 | 脸不灰 | 肤色 `C*` ≥ 10 | 低于此即"发灰"，与风格无关 |

### 14.2 结构不变量（LR 负责；破了 = 用了下游补上游）

| # | 不变量 | 判据 |
|---|---|---|
| S1 | **改色不改明暗** | 点颜色前后，皮肤 L 分布 p10/p50/p90 变化 ≤1 |
| S2 | **改局部不动全局** | 背景 a/b、背景占比变化 ≤ 阈值 |
| S3 | **曲线不替介质背锅** | 曲线每锚点位移 ≤3 L* |
| S4 | **不许把脸推出人样** | 改色后肤色仍在 T4/T5 之内 |
| S5 | **一段顶到上限就是上游错** | 任一段触界 ⇒ 回上游，不许加宽预算 |

## 15 意图（人给，可为空）

| 维度 | 例 | 谁给 |
|---|---|---|
| 亮 / 暗 | 「再亮半档」 | 人 |
| 暖 / 冷 | 「暖一点」 | 人 |
| 浓 / 淡 | 「淡一点」 | 人 |
| 软 / 硬 | 「柔一点」 | 人（走卷纸或柔光档，不是 USM） |

意图只改**方向与幅度**，永远不许把系统推出不变量区。**冲突时以不变量为准。**

## 16 于是"匹配"变成"选卷纸"

旧匹配：拿一批图去比一堆"卡"，输出排序。
新匹配：**拿拍摄条件 + 意图，去比一堆"卷纸组合"，输出排序**（三组阵营 → 组内按五轴挑 → 1~2 张代表图验证）。

**没有卡，就没有"靶数值"，只剩"候选 + 理由 + 人挑"。**

## 17 求解器因此变成两件事

```
引擎求解： 选卷纸（按条件+意图）  →  满足 T1~T5
LR 求解：  实现意图（亮/暖/浓/软）→  满足 S1~S5
```

**都不"打靶"。** 遇到"某个量偏离了某批成片"，那不是缺陷，那是**风格差异**。

## 18 阈值怎么定（避免旧靶从后门回来）

```
量化下限（T3、容差）     → 由位深/分辨率算，不是拍的
物理不可逆（T1、T2）     → 剪了就没有，阈值取"可见剪裁"的量级
生理常识（T4、T5）       → 人的脸不会那么暗/那么灰，取宽区间
结构（S1~S5）            → 由"谁负责什么"推出来
```

**关键区别**：不变量是**宽区间**（"不许越界"），靶是**窄点**（"必须到这里"）。
旧体系死在把窄点当标准；新体系只用宽区间。

# 第四部分 · 收口：引擎只做质感与风格（2026-10-29 定）

## 19 最终分工

| | 引擎 | LR |
|---|---|---|
| **做** | 卷/纸（风格）· 颗粒 · 光晕 · 柔光（质感）· 出片留余量 · 白点按卷纸配对 | 曝光落点 · 明暗分布 · 颜色（饱和度/色相/局部肤色）· 逐图任何微调 |
| **不做** | 任何逐图的曝光/亮度落点 · 任何"追某个数"的颜色对齐 | 质感（做不到，也不该做） |
| **判据** | T0 余量 · T3 白点 | S1~S5 结构不变量 + 意图 |

## 20 引擎侧因此只剩三件事（都不逐图）

```
① 选卷/纸         ← 风格由它决定（卷自带配套纸，三组阵营）
② 收片时的余量校验 ← T0：**p95 ≤ 93、clip < 0.5%、p1 ≥ 1.0**
   （旧写 p99≤92 / clip<1% / p1≥3 —— 已作废：比任何一套大师都严 3~6 L*，真跑把它证伪了，见第七部分 §25）
③ 白点按配对给定   ← T3：|a|,|b| ≤ 2（由卷+纸的配对关系决定，不是每批解）
```

**没有逐图参数。** 同一批所有图用同一套引擎参数出片 —— 这是最大的简化。

## 21 引擎里那几个"自己的测光"要留着

手册 §15.1：引擎的印相配平锚**写死 0.184 ⇒ 不读图 ⇒ 不振荡**。
它做的事是"把中灰归一"，效果恰好就是**保证每张的出片余量一致**。

所以：
- **保留** 引擎自带的中灰归一 / auto_exposure —— 它不是"我们的曝光旋钮"，是**余量保证机制**
- **不要再** 在外面乘我们的 EV / PE（那就是手册说会振荡的那条路）
- 它若把某张曝到余量不足（T0 不过），那是**卷/纸或入口 WB 的问题**，不是"再乘一个系数"

## 22 随这条决定作废的东西

| 作废 | 原因 |
|---|---|
| 脸锚闭环（`run919_anchor.py` 那套） | 曝光归 LR，不需要在引擎侧解 |
| `person_pe_band` / `person_pe_target_l` / 服装带 / `lc` 动态 | 都是"引擎侧调曝光落点"的机制，整体不需要 |
| `−36 L*/EV` 斜率标定 | 同上；换卷/纸不用再重标 |
| 曝光三层主人的记账 | 只剩引擎自带归一这一层 |
| `PERSON_PE_*` 一整套环境变量与常数 | 同上 |

## 23 LR 侧因此变重（但它是为这个而生的）

```
曝光落点    → Basic 曝光 / 曲线 p50
明暗分布    → 曲线（每锚点位移不再受 3 L* 约束？—— 不，仍受约束见下）
颜色        → 全局饱和/鲜艳度 + 点颜色（肤色）+ HSL（必要时）
```

**唯一保留的约束**：曲线位移仍受 S3（≤3 L\*）限制 —— 但那是为了防止"曲线替介质背锅"，
而不是限制 LR 的表达力。**LR 的曝光（Basic 的 Exposure 滑杆）不受这条限制**，
它本来就是用来定落点的。

## 24 一句话总结

> **引擎交一张"带余量、不偏色、有胶片质感的底片"；LR 决定这张底片最终长多亮、什么颜色。**
> 引擎不追任何数值，只守余量和白点。

# 第五部分 · 「以人为本」保留，但迁到 LR（2026-10-29 定）

## 25 结论：原则保留，执行位置改变

「以人为本」不是某个引擎旋钮，是**一条"看哪里"的规则**：曝光/明暗以**人（脸）**为准，
不以整幅直方图为准则。这条规则与在哪个工具里执行无关。

```
引擎上的旧形态：测光掩膜（face/person/matrix）+ 服装带 + 逆光换锚 + pe 闭环
LR 上的新形态：  Basic 曝光以脸为目标 + 曲线管形状 + Highlights 收白 + 点颜色管肤色
```

## 26 旧设计里要保留的四条规则

| # | 规则 | 为什么保留 | 当年证据 |
|---|---|---|---|
| H1 | **有脸用脸** | 脸的读数比"人"更准 | `r²(颊~脸) = 0.890` vs `r²(颊~人) = 0.346` |
| H2 | **降级链**：脸 → 人 → 整幅 | 小脸/无脸不能硬算 | 掩膜覆盖率守卫 [0.005, 0.70]，超界弃权 |
| H3 | **白端保护**（不为提脸把白推爆） | 逆光提亮最大的副作用 | `clip_hi 0 → 11.06` 那次 |
| H4 | **逆光识别**（脸比背景暗 ⇒ 该提的是脸） | 顺光/逆光要相反处理 | 逆光组脸 +17.6、变差 0 张 |

（光位 `lighttype` / `rim` 作为先验可以留，但它是**辅助**，不是判据。）

## 27 在 LR 里怎么落地（一一对应）

| 旧机制（引擎） | LR 对应做法 | 说明 |
|---|---|---|
| 测光掩膜选"看哪里" | **Basic 曝光以脸的读数为目标** | 脸要落到哪，是 LR 的事 |
| `pe` 闭环调落点 | 曝光滑杆 + 曲线 p50 | 不再闭环，**一次算一次验** |
| 胶片肩部压高光 | **Highlights 滑杆 + 曲线肩部** | 这是 LR 的强项：压亮部、不动中间调 |
| 服装带（亮中性子集） | 同上：Highlights + Whites 的上限约束 | 白端不许推爆 |
| 逆光换锚 | 逆光 ⇒ 先提曝光、再收 Highlights | 两步，不是一步 |
| 脸锚 `−36 L*/EV` 标定 | **不需要**（LR 的曝光是 1 EV 直读） | 引擎标定全部作废 |

## 28 LR 上这条规则的三条约束

```
L1 脸是【约束】，不是【唯一目标】：脸要落进合理亮度区（T4：55~85），
                              但不必落到某个具体值
L2 脸优先（2026-10-29 晚改）：脸必须进区，且**不许被收白压暗**（Δ ≤ 1 L*）；
                          背景过曝可以接受，收不住就接受，不回引擎
                          （旧写法「没有白端预算就不许提」已废：那等于让背景的账压住脸）
L3 逆光与顺光【分别处理】：逆光 = 提曝光 + 收白；顺光 = 只做微调
   ⚠ 光位**由人给**（`--light`），不由测量猜（见 §28 末段：两版自动判据都出过反例）
```

**L3 怎么落到数值（2026-10-29 真跑后补，原来是句空话）**

```
目标点 = 下界 + 落点容差 (+ 逆光补偿)
  落点容差 3.5 L*：实测落点误差 |残差| 中位 0.92 / P90 2.30 / 最大 2.88（n=5）
                  —— 贴边 1.5 时误差一来就掉出区（DSCF1627 给 +0.88，实测 54.2，差 0.8）
  逆光补偿 4.0 L*：同一 L* 的脸在逆光下看起来更暗（1289 光比 0.91，提到 56.8 仍显暗）
  ⇒ 顺光目标 58.5 / 逆光目标 62.5 / 上限 70（只在区间中段，不贴顶）
```

**光位判据：双区统计（2026-10-29 晚，查过论文/专利后改）**

```
出处：专利 CN109815905B（亮区 vs 暗区均值差超阈值 ⇒ 逆光）
     专利 CN102013006B（前景掩膜内**绝对暗**像素占比超阈值 ⇒ 逆光）
     论文 Tsai & Yeh, IEEE TCE 2010（YIQ + 照明分析，模糊分类 back/normal/front-lit）

现在用的两个量（测量层新加）：
  gap  = 背景亮部 L_p90 − 脸 L     ← 双区对比
  dark = 脸掩膜内 L≤40 的像素占比   ← 前景暗占比
判据：dark ≥ 0.35 且 gap ≥ 12 ⇒ backlit ｜ gap ≥ 35 ⇒ backlit
      dark ≤ 0.12 且 gap ≤ 12 ⇒ frontlit ｜ 其余 ⇒ **unknown（模糊的交给人）**
```
**只会判错成 unknown，不会判错成相反方向**——这是刻意的：宁可不判，不许误导。
人可以用 `--light` 覆盖。

**分寸（有出处，取代自定的 58.5）**：逆光时脸提到「**比天空暗半档**」就停
（`bg.L_p90 − 8 L*`），不是提到跟背景一样亮——那是资料里反复强调的"人会飘"。

**处理顺序（三份实操资料口径一致）**：先救脸（只碰脸、不碰天）→ 再压环境高光 →
最后补饱和（+8~12，否则"像蒙了层灰纱"）。我们 ②→③→⑥ 的顺序与此一致，
**但 ② 是全局曝光**（整幅跟着亮），所以真正的提脸应尽量交给 ⑥ 肤色亮度。

**轮廓光保护**：收白把发丝亮边压掉一半以上就报警（`rim.bright_share` → 日志）。
"亮边还在 ⇒ 可以停；亮边没了 ⇒ 提过头"——这是实操资料给的停手标准。

**旧判据（已废弃，留作教训）**

```
判据一（旧）：脸 L ÷ 背景【中位】L   ⇒ 逆光时背景中位落在暗部（树皮/石墙）
              反例：DSCF1608（真逆光）被算成顺光
判据二（新）：脸 L vs 背景【亮部】p90 ⇒ 画面里有天空时 p90≈天空
              反例：DSCF1307（脸被太阳直照，明显顺光）被算成逆光
⇒ 单张图没有可靠的自动判据。真正可靠的证据是**轮廓光**（脸外圈比脸亮），测量层还没量。
⇒ 现在：`--light backlit|frontlit` 由人给；不给就 unknown，所有"逆光才做"的动作
  （落点 +4、肤色 +0.15）都不触发。测量仍记 `light_gap`/`light_span` 当旁证。
```

## 29 于是"以人为本"这件事的完整归属

| 环节 | 谁做 | 用什么 |
|---|---|---|
| 找到人/脸 | 引擎（已实现，成熟） | `person_masks` / YuNet；掩膜在 1080 上算 |
| 判断"该看哪里" | **LR 求解器** | 有脸看脸 → 没脸看人 → 都没有看整幅 |
| 执行提亮/收白 | **LR** | 曝光、Highlights、曲线；不用引擎 pe |
| 校验 | 数值 | T4（脸在合理区）+ T1（不爆白） |

**注意**：LR 的"按亮度局部"（Highlights）等于"按位置局部"的近似——
它会连带同亮度的白裙/白墙。这条要在验收时看（S2 选择性门的变体）。

# 第六部分 · LR 侧的分工与求解（2026-10-29 定）

> 引擎已收口为「卷纸 + 余量 + 白点」。**下面这一整张表，全是 LR 的活。**

## 29.5 「以人为本」实际上线状态（2026-10-29 首次真跑后）

| 规则 | 设计写了 | 代码里 | 状态 |
|---|---|---|---|
| H1 有脸用脸 | 脸比"人"准（r² 0.89 vs 0.35） | `pick_lookat`：face_w ≥ 40 ⇒ 用 skin.L | ✅ 在用（9/9 张都走脸） |
| H2 降级链 脸→人→整幅 | 小脸/无脸不能硬算 | 只有 脸→整幅；**"人"这一档不存在**（测量层不给人体亮度） | 🟡 少一档 |
| H3 白端保护 | 不为提脸把白推爆 | 已改成 L2「脸优先」+ ③ 按脸进退 | ✅ 在用 |
| H4 逆光识别 | 逆光该提的是脸 | **光位由人给**（`cli run --light backlit/frontlit`）；不给=unknown，逆光动作全不触发 | ⚠ 自动判据**已废弃**：两版判据都出反例（见下） |
| — 局部提脸 | 没写 | **点颜色的亮度**（`lum`）：只作用于肤色范围 | ✅ **不做蒙版**，用肤色亮度代替（10-29 实测：脸 +9.1 格时背景只 +0.5） |

## 30 LR 的职责清单

| # | 职责 | 旋钮 | 判据 |
|---|---|---|---|
| 1 | 判断"看哪里" | 无（选择） | 有脸→脸，没脸→人，都没有→整幅 |
| 2 | **曝光落点** | Basic `Exposure` | 脸进 55~85；目标点 = 下界+3.5（逆光再加 4），提完会爆白交给 ③ |
| 3 | **高光收白** | `Highlights` | **脸没被压暗**（Δ ≤ 1 L\*）+ `clip_pct` 尽量小；收不住接受背景爆 |
| 4 | **只修不变量** | 曲线 | 爆白/堵黑才动，p50 不动，每锚点 ≤3 L\*；**不追形状**（形状归卷/纸） |
| 5 | **全局彩度** | `Saturation` / `Vibrance` | 只在需要时用；Vibrance 实测几乎无效 |
| 6 | **肤色（含亮度）** | Point Color：色相内取样 + Sat/Lum | 肤色 C ≥ 10、h 在合理区；**脸不够亮时用它补最后一段**（只动肤色、不动背景） |
| 7 | **色相微调** | HSL（必要时）/ 点颜色的色相偏移 | 同上 |

## 31 求解顺序（从粗到细、从全局到局部）

```
① 定"看哪里"          （选择，不求解）
② 曝光 Exposure       → 脸进合理区
③ 高光 Highlights     → 不爆白
④ 曲线                → 形状
⑤ 全局饱和            → 只在"整幅明显偏灰"时才动
⑥ 点颜色              → 肤色
⑦ 验收三门
```

**为什么这个顺序**：
- **曝光在前**：它是整幅平移，一动全变；先定它，后面的量才稳定
- **收白紧跟**：曝光一提就可能爆，立刻用 Highlights 把白端拉回来
- **曲线在收白之后**：曲线是形状，形状要在"亮度已定"的前提下才谈
- **饱和在曲线之后**：曲线会改分布，分布改了饱和的感受也变
- **点颜色最后**：它只动肤色一块，是最细的一刀

## 32 每步的解锁条件（不达标就不做下一步）

| 步 | 达标条件 | 不达标怎么办 |
|---|---|---|
| ② 曝光 | 脸 L 落在 55~85 | 一次算到位（1 EV ≈ 30 L\*，直读），不闭环 |
| ③ 收白 | 脸**没被压暗**（Δ ≤ 1 L\*）+ `clip_pct` 尽量小 | 加大 Highlights；**脸一掉就回退**；到 −100 仍爆 ⇒ **接受背景过曝**（不回引擎） |
| ④ 曲线 | 只修不变量（爆白/堵黑），**不追形状** | 形状不对 ⇒ 那是卷/纸的事 ⇒ 换卷/纸（**人定**，不是流程自动动作） |
| ⑤ 饱和 | 整幅彩度明显低于"该有的"（由意图决定） | 不需要就不动 |
| ⑥ 点颜色 | 肤色 C ≥ 10 且 h 在合理区 | 超量程 ⇒ 记欠账，不硬顶 |

**③ 的幅度怎么定（2026-10-29 定，别再来一遍）**

`Highlights` **没有公开传递函数**：Adobe 官方只写「按亮度区域自适应、会保护其它区域」，
并明说它「比一条曲线复杂得多」；第三方实现（agx-photo 的 `basic_tone`：
`weight=(u−0.5)/0.5, out=u+weight·h/100·0.5`，sRGB 伽马域）是对**手感**的仿写，不是它的算法。
⇒ 拿近似式算幅度，只会得到一个"看起来很精确"的假值。

所以 ③ 输出的是三样，而不是一个"算出来的值"：

| 输出 | 是什么 |
|---|---|
| **起点档** `−50` | 对分搜索的第一步（量程 0~−100 的中点）。响应单调 ⇒ 对分最省步数，且不给假精度 |
| **阶梯** `next_highlights()` | 出片量脸和 `clip`：**脸被压暗 > 1 L\* ⇒ 回退（脸优先）**；脸没掉但还爆 ⇒ 加大；到 −100 ⇒ **接受背景过曝** |
| **验收量** | **脸 L 掉没掉（主判据）** · `clip_pct`（次要）· `p50` 不动（§33） |

**① 已爆 ≠ 提爆，但要先看爆在哪**：
- **爆在背景** ⇒ **可接受**（脸优先，背景爆是取舍），收白只是让它别太扎眼，收不住也不算账；
- **脸自己贴顶**（L ≥ 99）⇒ **主体丢了**，收白救不回细节，单列出来往上**上游**查（入口曝光/场景），
  这不是"引擎欠账"这种能记账了事的东西。

走到 `−100` 仍爆 ⇒ **接受背景过曝**并记下爆了多少。
**不再有"回引擎要余量"这个出口**：回引擎实际只会整幅压暗＝拿脸换背景，
与"脸优先"相反，也越过了分工（§19 引擎不碰逐图曝光落点）。

## 33 三处冲突，各自的裁决

| 冲突 | 裁决 | 理由 |
|---|---|---|
| **曝光 vs 曲线的 p50** | 曲线**不许动 p50**（S3） | 两处同时平移就会打 |
| **Highlights vs 曲线肩部** | **只用 Highlights**，曲线肩部不动 | 两者功能重叠；Highlights 是"按亮度局部"，比曲线精确 |
| **全局饱和 vs 点颜色** | **先全局、后局部**；全局只补"整幅偏灰"，不许用它补肤色 | 全局会连带环境，而肤色是局部问题 |

## 34 LR 侧的"靶"其实也是不变量

引擎收口之后，LR 的判据同样不是"追某批成片"，而是：

```
T1 不爆白   T4 脸在 55~85   T5 肤色 C ≥ 10
S1 改色不改明暗   S2 改局部不动全局   S4 不许把脸推出人样
意图（亮/暖/浓/软）：人给，可为空
```

**"该到多少"这件事在 LR 里也不存在了**——只有"不许破"和"如果你要，我可以往哪个方向推"。

## 35 数据接口（LR 求解吃什么）

| 步 | 吃什么 | 哪一态 |
|---|---|---|
| ① 看哪里 | 脸的测量（`face_w`、`face_size`、`skin` 是否有效） | ① |
| ② 曝光 | ① 的脸 L 中位（引擎刚出来的样子） | ① |
| ③ 收白 | ① 的 `clip_pct` / `p99`；③ 验 | ① 算、③ 验 |
| ④ 曲线 | ① 的五分位 → 出曲线；② 是结果 | ① → ② |
| ⑥ 点颜色 | ② 的肤色（过曲线未加色） | ② → ③ |

**忘了这一条就会犯老错**：拿 ③ 的数去定 ② 的参数。

## 36 整套 LR 求解的伪代码

```
for 每张图:
    loc = pick_lookat(measure_①)        # 脸/人/整幅
    ev  = (target_L(loc) - L_①(loc)) / 30      # 1 EV ≈ 30 L*
    kv  = {Exposure: ev}
    渲一次 → 量 ③ 的 clip
    if clip > 阈值:
        kv[Highlights] = -x             # 收白，一次算
    渲一次 → 量 ③
    if 五分位残差 > 1:
        出曲线（每锚点 ≤3 L*）→ 渲
    量 ③ 的肤色
    if C < 10 or h 出合理区:
        点颜色（批次剂量 + 逐图取样点）→ 渲
    验收三门
```

**全部是"一次算、一次验"，不是闭环迭代。** 唯一允许多轮的是点颜色（因为它的斜率有饱和倾向）。

# 第七部分 · 收尾（2026-10-29 白天！真跑之后）

## 25 三个被真跑证伪的判据（都已改，别引用旧的）

| 旧 | 新 | 依据 |
|---|---|---|
| T0：`p99 ≤ 92` | **`p95 ≤ 93`** | 大师 p99 中位 鹿井 94.7 / xhs 97.9 / 滨田 94.6 ⇒ 旧阈值比任何一套都严 3~6 L*，逼着引擎"为留余量把脸压到 L40" |
| T0：`clip < 1%` | **`clip < 0.5%`** | 大师 clip 中位 0.08~0.39% |
| T0：`p1 ≥ 3` | **`p1 ≥ 1.0`** | 大师 p1 中位 鹿井 6.6 / xhs 1.6 / 滨田 16.4（跨语料差 10 倍，3 是拍的） |

**方法论上的教训**：阈值只能从「量化下限 / 物理不可逆 / 生理常识 / 大师实测**区间**」来。
我一上来把"区间"写成了"比区间更紧的点"，结果系统为了满足它去破坏主体。

## 26 卡有三种，数量差别很大

| 类 | 数量 | 有什么 | 能不能渲 | 用途 |
|---|---|---|---|---|
| **参照卡** | **64**（鹿井 62 套 + xhs 1 + 滨田 1） | 画像：脸 L/C/h、p50/p95/p5、反差、clip、天空、光比、暖冷 + IQR | ❌ 没有配方 | "这批该像哪一套" |
| **生产卡** | **3**（卡38 / xhs预设 / 滨田预设） | 配方：卷 / 纸 / 质感档 / 风格档 | ✅ | 真的渲 |
| 意图 | — | 人给的 −1..+1（亮/暖/浓/软） | — | 只改方向 |

**之前我只有"生产卡"这一层**，所以"匹配"退化成在 3 个几乎一样的配置里挑。
参照卡补上之后，匹配才有内容：大师是按**套**拍的（鹿井 62 套，每套中位 10 张）。

## 27 匹配是两步，不是一步

```
① 这批最像哪一套？（64 张参照卡里找，按各维离散度归一化的距离排序）
② 我们的生产卡能不能做到那个像？（feasibility：逐维问"有没有旋钮关得掉"）
   做不到 ⇒ 该做新卡；方向由那一套的画像给
```

第②步的杠杆与可达量（都带出处）：

```
amount      C +2.3/单位，量程 0~2.0（作者给）｜ h +19.9（符号随语料变）
γ_blue      C +14/单位（脏解：会改色相/中性轴）
γ(配比)      h ≈145/单位
LR 曝光      L = 0.231·(L+16) L*/EV（CIELAB 可推），受引擎余量约束
LR 点颜色    C 上限 ×2.2 ｜ h ±30°
LR 曲线      ±3 L*/锚点
换卷/换纸    无界 —— 手册总账：能改分色形状的只剩这条
```

## 28 首次端到端真跑（D:\\照片库\\效果测试919，10 张）

```
RAW → 试点 2 张 → 自动选中卡 → 整批渲 8 张 → 量 ① → LR 计划 → XMP 10 份
    → LR 真的导出 ③ 10 张 → ①→② 回归 10/10
```

| | 我们 ③ | 鹿井大师 |
|---|---|---|
| 脸 L | 58.7 | 71.4 |
| 脸 C | 18.2 | **21.5** |
| 脸 h | 54.5 | **54.1** |
| p95 | 93.1 | 90.6 |
| clip | 0.48% | 0.08% |

**结论：色相与彩度已经对上**（54.5 vs 54.1；18.2 vs 21.5）。
**剩下的是"上段反差"**：p95 高 2.5 L*、脸低 12.7 L*，即亮部堆得太靠白、脸压得太低。

## 29 一个被推翻的中间结论（重要）

我一度判定"我们彩度差 2.3 倍、必须换卷"。
真跑之后：**干净引擎出片 C=21.2，大师 21.5 —— 基本一致**。
那个判断来自旧的 `m_state1`（anchor + 点颜色那条链），是**旧链的产物**，不是介质缺陷。

⇒ 教训：**"和某一批的差"不等于"我们的缺陷"**，必须先确认两边是同一条链、同一口径。
