## 0 先给结论

三件事在引擎里**都是算子**，不是"滤镜强度"：

```
颗粒 = 把整张密度场**重新随机采样**一遍（不是往图上叠噪声）
光晕 = 在**线性曝光**上加一层背反射卷积
柔光 = 把一部分光子**按 PSF 偏折**（能量守恒，无吸收）
```

算子的**系数**是介质属性（卷 / 纸 / 画幅 / 扫描 psf）；**外观**由画面内容自己驱动
（亮的地方自己出晕，没亮光就看不见晕）。所以"动态"能做的事只有三件：

1. **物理换算**（µm↔px、画幅、出图长边）—— 必须自动，且必须做对；
2. **场景选档**（前馈、离散、预先定好值）—— 允许，但收益有限（见 §4）；
3. **意图**（人给：浓一点/软一点）—— 允许。

**逐图闭环调质感 = 没有不动点**（手册 §二 第一原理）。这条不是保守，是 10-21
`ff194eb` 已经用行动定过一次：`targets.py` / `scene.py` / `lighttype.py` 整层删掉，
理由写得很清楚——**sfFilm 管介质，LR 管落点与尺度**。

⚠ 所以本报告的落点不是"加一个自适应层"，而是：**把介质这条路修对，把动态留给该动态的那两根**。

## 3 三个机制（源码要点）

### 3.1 颗粒 = 密度场的随机重采样（`G:292-388` → `D:104`）

```
Var[D] = D·(Dmax − u·D) / N          N = pixel_area / a₁
a₁ = σ₄₈² · A48 / [D_ref·(Dmax − u·D_ref)]        ⇒ a₁ ∝ rms²
```

三个推论，全都和我们有关：

1. **幅度自动随影调**：D=0 与 D=Dmax/u 处归零，中间最响 ⇒ 不需要为"阴影别太吵"做任何事。
2. **分辨率自动**：同一份 rms，长边越大 ⇒ 每像素覆盖的粒子越多 ⇒ 颗粒相对画面越细。
   这就是"2048 不许用颗粒绝对值"的机制根。
3. ★★ **`blur` 糊的是整张密度场，不是"只糊颗粒"**：`apply_grain` 的返回值**就是**密度场
   （`G:374-388` 用随机实现替换 density_cmy，均值不变），所以 `blur` 等价于**给整幅图加一道高斯**。
   补偿它是 `mult_usm_*`（密度域**乘性** USM，质量守恒，`DF:24-58`，作者注释写明
   "used after the pixel-correlating grain blur to recover acutance"）。
   ⇒ **我们 `mult_usm_amount = 0`（10-19 因 1080 黑发白点关掉）+ blur 留着 = 底片被白糊一道、没人补。**

`micro_structure` 的两道内门（`G:150-168`）：`σ = nm·0.001/pixel_µm > 0.05` 且 `blur > 0.4 px`。
在 2048（35mm ⇒ 17.6 µm/px）要 `nm > 880` 才过门，默认 30 nm ⇒ **恒不触发**；
6264 上要 `> 280 nm`，也不触发 ⇒ 这个键在本项目里是**死键**，别再指望它造团簇。

### 3.2 光晕 = boost → scatter → halation，全在**线性 raw** 上（`DF:76-158`，`F:59-61`）

```
E1 = (1−s)·E0 + s·[(1−w)·G(σc) + w·Exp(λt)]E0          散射（能量守恒）
E2 = E1 + a_tot·Σ ρ̂k·G(σh√k)·E1                        背反射（多跳，σ 按 √k 展开）
E2 /= (1 + a_tot)                                        renormalize（白不飘）
```

- `boost_ev`（`BH:27-119`）在散射之前把**被剪掉的高光**按 `2^boost_ev` 指数式"还原"出来，
  阈值 = `midgray·2^protect_ev`。它的物理意义：**真实底片上 Dmax 以上的能量只以光晕形式存在**。
- 所以**光晕好不好看，第一件事是"有没有真高光能量"**。我们 `boost_ev=0` + `protect_ev=4.0`
  （阈值 = 18.4%×16 = 2.94 raw ≈ 中灰以上 4 EV）⇒ boost 恒等，光晕只能吃"没被剪"的那部分。
- `halation_strength` 是**背反射幅度**。作者 tooltip：弱 AH **0.02-0.08**、无 AH **0.08-0.25**。
  我们 **2.5 / 0.8 / 0** ⇒ 红通道是作者"无抗晕"上限的 **10 倍**。这是手调的风格值，不是物理值。
- σ 是 µm ⇒ 自动随画幅/出图尺寸；`HALATION_G_SIGMA_RATIO=0.45` 只是让"多快变红"变快，
  贴边那一瞬的 R/G 仍由幅度比（2.5:0.8 ≈ 3.1）决定。

### 3.3 柔光 = 能量守恒的偏折 + 三族指数 PSF（`DF:182-367`，`DF:664-…`）

```
strength 0.125 / 0.25 / 0.5 / 1.0 / 2.0  →  p_s 0.10 / 0.20 / 0.35 / 0.55 / 0.75
p_s 再乘族增益：glimmerglass .65 · BPM .75 · pro_mist 1.05 · cinebloom 1.00
PSF = w_c·core(16 µm) + w_h·halo(95 µm) + w_b·bloom(380 µm, α3.5)   ← BPM
```

- 我们相机 0.25 ⇒ **p_s = 0.15**；印放 0.125 ⇒ **p_s ≈ 0.075**；
  **两级串联不是相加**：总偏折 ≈ 1−(1−0.15)(1−0.075) ≈ **0.21**。
- λ 全是 µm ⇒ 自动随画幅与出图尺寸（这是它比 `blur` 干净的地方）。
- ★ 模型**无吸收**（作者代码注释原文 "No absorption — energy-conserving"）：
  BPM 的"压黑"是靠散射少 + 绽得少，不是真的吸光。**别按"BPM 会吸光"推方向。**

## 4 什么该动态、什么一旦动态就出事

| 驱动方式 | 例子 | 判 |
|---|---|---|
| **物理换算**（自动） | 长边 → px 键；画幅 → 三条空间族 σ；µm → px | ✅ 必须 |
| **场景选档**（前馈、离散） | 有强光源 ⇒ boost_ev 1.0；逆光 ⇒ 柔光升一档 | ✅ 允许（但要预先定好值） |
| **意图**（人给） | 浓一点 ⇒ rms 升；软一点 ⇒ 柔光升档 | ✅ 允许 |
| **输出统计闭环** | 量出"颗粒不够"⇒ 调 rms 再渲 | ❌ 振荡，无不动点 |
| **逐图改介质系数** | 每张图换 halation_strength | ❌ 物理错：等于每张换一片镜片 |

两条容易想歪的：

- **光晕 / 柔光其实不需要"逐图动态"**：算子对 E 是**线性**的 ⇒ 画面里亮的地方自己出晕，
  没有亮点就看不见 ⇒ "按亮度自适应"这件事**引擎已经天然做了**。
  真正要补的是**缺能量**（boost_ev），不是缺"逐图强度"。
- **颗粒需要的是"归一"，不是"动态"**：现在"团径"和"幅度"挤在同一根 `blur` 上，
  而 `blur` 又是像素键 ⇒ 同一份 JSON 在 1080 / 2048 / 6264 上是三种颗粒。

## 5 我认为值钱的五个改动（按性价比）

### A 颗粒：改成"画面比团径 + 数据表 rms"两参数化

```
clump_frac = 团径 / 画面宽           (起点 0.15%~0.25%，出处 = 10-22 实测注释那组)
blur_base  = clump_frac × 6264        ← 交给 _scale_px_keys 自动落到任意长边
rms        = 数据表规格 × 摊薄补偿     ← 实测三点 20/2.0 → 33/2.8 → 60/4.5（≈线性）
mult_usm   = 与 blur 成对打开         ← 否则 blur 就是在糊整幅
```

⚠ **先量一次校对，不许直接信注释**：`SV:config.py:64-72` 的注释说"2048 下团 3~5 px 对应基准值
2.8~4.5"，但 `_scale_px_keys` 会把基准值 ×2048/6264=0.327 ⇒ 2.8 在 2048 上只有 **0.92 px**。
两者**不可能同时对**（一个按未缩放量的，一个按缩放后的）。
一量就清楚：一张图、同一份 rms、blur 取 2.0/2.8/9.2 三档，量团径。
今天的实际值：`blur 2.0 → 2048 上 0.65 px`、`rms 10（xhs）` ⇒ 颗粒相关长度≈1 px、幅度≈0.5~1 L\*。

### B 打开 `boost_ev`（只给"有光源"的场景档）

没有它，光晕只是在吃"没被剪的高光"；有了它，逆光的太阳/发丝边缘才有真能量可糊。
`protect_ev=4.0` 太高（只碰 ≥16× 中灰 ≈ 中灰 +4 EV），建议 **2.5~3.0** 做两档对比。
物理上这条是"重建被剪掉的辐照度"，不是编数值 —— 但**它会让最亮处更亮**，必须目检。

### C 三张卡的 `print_render.glare` 一律关

不可复现（numba RNG，22 码）。规矩：**测量/取差一律关；要雾感用别的机制**。
顺带解决"缓存键很脆""同参两渲不一样"两个老问题。

### D 补 `_PX_SCALED_KEYS` 的漏项

`grain.mult_usm_sigma`、`scanner.unsharp_mask` 的 σ 都是**像素**单位，一开就会随尺寸变；
现在表里只有 `grain.blur` 和 `scanner.lens_blur` 两根。

### E 接一条 overrides 通路（这是所有"动态"的前提）

```
render_safe(lin, name, cfg, *, overrides=None, …)  →  render(…, overrides=overrides)
design/flow.render_card(...)                        →  把 texture plan 翻成 overrides
```

代价：**不增加渲染次数**（只是每次 render 多传一份 dict）。

## 6 代价与风险（跑之前先看）

```
渲染：render_safe = 6~12 次 render；实测 65 秒/张 @2048、10 张 648 秒。
      加 overrides 不涨次数；要 A/B 三组 = 三倍时间。
判读：颗粒/锐度**只能在全长边判**（2048 上高频已被缩图抹掉），且**不许**用 2048 的颗粒绝对值。
对照：空间族**没有跨链等价**（真实胶片是记录、引擎是叠加）⇒ 不跟大师成片"对数"，只判方向 + 目检。
基线：**不许**用 `grain.active=False` 当颗粒基线（差值 = 一道全图糊 + 颗粒）。
```

## 7 建议的第一炮（还没跑，先报代价）

2 张（1608 逆光 / 1289 顺光）× 3 组，共 **6 次渲染 ≈ 4~5 分钟**：

| 组 | 改动 | 想看什么 |
|---|---|---|
| a | 现状 | 基线（glare 关） |
| b | 团径 0.15% ⇒ blur_base 9.4 + rms 补偿 + mult_usm 成对 | 颗粒读不读得出"胶片"，整幅会不会发软 |
| c | b + `boost_ev=1.0 / protect_ev=3.0` + 印放柔光关掉（避免两级串联） | 高光/发丝边缘的晕是否变厚，白端有没有飘 |

出 6 张**全尺寸裁切**（发丝边缘 / 天空平坦区 / 黑发）+ 一页对比；只判方向与"像不像胶片"。

⚠ 这一炮里有三条是会**改变画面的风格值**（团径、boost、柔光档），按纪律要先过目检再定；
`glare=off`、`_PX_SCALED_KEYS` 补全、overrides 通路属于**技术性**，可以直接改。
