# 测量设计（服从 `设计真源.md`）

> **宪法 = `设计真源.md`**。本文件只写"怎么量"，不写"该多少"；冲突时改本文件。
> 尺子只回答"是多少"，不回答"对不对"。

---

## 1 域与口径

### 1.1 ★ 两层域（先把"跟谁比"分清楚）

| 层 | 域 | 用途 | 能不能跨 |
|---|---|---|---|
| **交付域（唯一可比）** | sRGB · **长边 1080** · **JPEG** | 所有**与卡比对**的量：风格 / 纹理 / 颜色 / clip | 只能在这一层比 |
| 技术域（自用） | 原生 16bit TIFF | 只做**物理底线**（死白、p1），不跟卡比 | 不进任何跨卡比较 |

```
大师作品：本来就只有交付域（1080 JPEG 网络图）——没有"原生"可比
我们的出片：每次导出后**转成同一域**（sRGB / 1080 / Q≈90）再测
引擎标定：也先落到这个域再量（否则标出来的系数跟成片对不上）
```

**这就是"一把尺子"的答案**：统一的不是"分辨率"，是**交付域这个工件**。
测的是**交付物**，不是 16bit 中间态——这也符合"先出成片再量"。

### 1.2 口径

| 项 | 规定 | 为什么 |
|---|---|---|
| 三态 | `①′` 基线 · `①` 正式 · `③` LR 后 | 每个旋钮只对着它作用之前那一态量 |
| 检测分辨率 | **1080** | 快；检测/掩膜只在这里做 |
| **比对分辨率** | **1080（交付域）** | 大师只有这个域；高分辨率比不了 |
| 技术域分辨率 | 原生 | 只给死白/p1 这类物理底线用 |
| 色彩 | sRGB 交付域 → CIELAB D65 | 跨卡可比 |
| 肤色口径 | **FACE ∩ 皮肤似像素**（不画圆），取样点中位 | 圆盘会把背景算进肤色 |
| 量化下限 | u8 一个编码：L\* ≈ 0.4 · a/b ≈ 0.5 · C ≈ 0.2 | 小于一格不做决策 |

**同一个量只有一个定义、一处实现、一个 `measure_sha`。** 换了尺子 ⇒ 三态一起重测，不许只测一态。

### 1.3 比对工件（"同一双眼睛"的落地）

```
任何**与卡比对**的数，必须来自「交付域副本」：
  大师：原图（本来就是 sRGB / 1080 / JPEG）
  我们：把 ①′ / ① / ③ 转成 sRGB / 1080 / JPEG 之后再量

① 的 16bit 只用来：预测、物理底线（死白 / p1）——**不跟卡比**
```

| 步骤 | 比对的工件 |
|---|---|
| 匹配（候选） | **①′ 的交付域副本** |
| LR-B 决策 | ① 的副本预测；**判"在带内"用 ③ 的副本** |
| LR-C 验收 | **③ 的副本** |
| 引擎标定（bloom→p_s 等） | **① 的副本**（与大师同域，否则系数对不上） |

★ 这条和"同一双眼睛"是一回事：眼睛（尺子）可以一样，但**看的东西必须是同一种工件**。

## 2 字段（每个都要能回答：代表什么 / 有哪些同名版本 / 判据用哪个）

| 字段 | 代表什么 | 同名版本（易混） | 判据用哪个 |
|---|---|---|---|
| `skin.L/C/h/a/b` | 观众"看脸"的那个点 | 脸掩膜中位 / 脸内 p90 | 取样点中位 |
| `face_L_med` / `face_L_p90` | 整张脸的亮度分布 | 取样点 | **只报**，不进判据 |
| `face_dark_share40` | 脸内 L≤40 的占比 | 脸内暗部、`dark` | 光位判据的一半 |
| `rim.L_p50/p90` `rim.over_share` | **贴脸那一圈**的亮度与亮边 | 近场 ring、背景 | 轮廓只报；方向判据待用 |
| `rim.bright_share` | 环带里比脸亮一截的占比 | —— | **不判**（门槛跟着脸走，不独立） |
| `near_bg.L_p50/p90` | 整个人周围一圈 | 贴脸圈 / 全局背景 | 只报（"整幅该多亮"的参考） |
| `bg.L_p50/p90` `bg.b_p50` | 背景（含天空） | 贴脸圈 / 近场 | 关系的分母；冷暖 |
| `img.p5/p50/p95` `img.clip_pct` | 整幅分布 | 人 clip / 天空 clip | 形状与白端（整幅） |
| `person.clip_pct` | 人身上爆白 | 整幅 clip | 物理（死白归属） |
| `neutral.share/a/b` | 中性面 | `neutral_axis`（五段） | 有占比才算数 |
| `warm_cool_b` | 亮部 b − 暗部 b | 脸色温 / 背景 b | 冷暖层次 |
| `shape.toe/shoulder/contrast_win/skew` | 形状四项（p25−p5 等） | 曲线形状 | 明暗层次 |

★ 名字带域/单位：`_frac`（0–1）· `_pct`（百分数）· `_native`（原生像素）。历史上 `sky_share` 与 `env_share` 单位不同，被乘错过一次。

## 3 光位**不是**测量

测量只负责给原料，标签在求解层算（唯一一套，双区判据）：

```
gap  = bg.L_p90 − skin.L
dark = face_dark_share40
back  : gap ≥ 35，或（dark ≥ 0.35 且 gap ≥ 12）
front : dark ≤ 0.12 且 gap ≤ 12
其余   : mid
```

为什么不在测量层给标签：两套判据会给同一张图两个答案（1608：旧标签判 `front`，双区判 `back`），后面所有条件带都跟着错。

## 4 尺子的质量（当前实测）

| 源目录 | 有脸 / 总数 | 拒收 |
|---|---|---|
| 鹿井 | 672 / 747 | 75（`roi_empty` 47 · `no_skin` 28） |
| 滨田 | 15 / 22 | 7 |
| xhs | 59 / 90 | 31（`roi_empty` 13 · `no_skin` 18） |

- **拒收率必须随批报**：拒收多说明掩膜/检测在这批图上不稳，结论要打折。
- **xhs 有 29/59 判不出光位**（`gap` 或 `dark` 缺）——先查背景掩膜，不查清就不给 xhs 建条件表。
- **复现性未测**：同一张图连测 5 次，脸 L 离散 ≤1 格才算合格。没测之前，任何"±1 格"的结论都不算数。

## 5 输出契约

```json
{ "_meta": {"dir","n","ok","bad","jobs","generated"},
  "per_image": [ {file, img, shape, bg, person, skin, face, near_bg, rim,
                  neutral, neutral_axis, hue_bands, warm_cool_b, white_point,
                  face_dark_share40, face_L_med, face_L_p90, sky_share_frac} ],
  "bad": [[file, reason]] }
```

- `file` 用相对路径（`/` 分隔），便于跨机。
- 每个记录必须带 `caliber`（口径常数 + sha），否则拒收。

## 6 不测什么

| 不测 | 为什么 | 替代 |
|---|---|---|
| 颗粒 / 锐度的**绝对值** | 1080 复原不了 48µm 颗粒与 MTF50 | 高频只记档（§6.1） |
| 构图 / 被摄体 / 透视 | 不模仿内容 | 人看样片 |
| 光位标签 | 是判据不是测量 | 求解层算 |

### 6.1 质感：高频只记档，**空间族不按卡量**

| 类 | 量 | 处置 |
|---|---|---|
| **高频** | `grain` · `ratio` · `edge` | **只记档**：1080 测不到（744 张：卡内 0.55 vs 卡间 0.51）；且无跨链等价 |
| **空间族** | 柔光 / 光晕 / 眩光 | **不按卡量**：固定值（相机 BPM 1/4 + 印放 1/8、卷的 AH 档、glare 0.03），**验收时可调** |

10-30 拍板：空间族逐卡反解作废（`引擎设计.md` §7.5）。卡上不再带 bloom/halo/veil。

## 8 全量测大师：只补一样

### 8.1 下游要什么（先列消费者）

| 消费者 | 要的量 | 现状 |
|---|---|---|
| 匹配（候选） | 不变量层中位 / 分布 | ✅ 有 |
| LR-A look | hero 样片 + 不变量带 | hero **由人选卡时指定** |
| LR-A 三保护 | `face_C/face_h` 带、饱和带、曲线 p50 | ✅ 有 |
| LR-B 条件 | 光位 + `face_over_bg` / `face_L` | ✅ 部分 |
| 引擎-介质 | 色调 / 色偏量（批级预演） | ✅ 有 |
| **LR-A 分离色调** | **`split_b`**（阴影/高光各自色偏） | ❌ **缺** |
| 引擎-空间族 | —— | **不测**（固定值，验收可调） |
| 引擎-颗粒 | rms 公开规格 | 查表，不测 |

⇒ **只缺 `split_b` 一个量**；hero 由人选，不用测。

### 8.2 口径（绝对阈值，不用图自己的分位）

```
阴影：L* < 20 ，像素 ≥ 0.5% 画面
高光：L* > 80 ，像素 ≥ 0.5% 画面
各取 b* 中位 + C* 中位 ⇒ split_b = {shadow_b, high_b, shadow_C, high_C}
像素不足 ⇒ unavailable（不许给 0）
```

### 8.3 怎么测

```
域  ：交付域（sRGB / 1080 / JPEG）
抽样：全卡全图测一遍；卡级取中位 + IQR
复现：同图连测 5 次，离散 ≤ 量化下限
```

### 8.4 数据契约

```
每图：split_b = {shadow_b, high_b, shadow_C, high_C}
卡级：中位 + IQR + n；与现有字段同一个 json，版本号 +1
```

### 8.5 不测

```
颗粒 · 空间族（柔光/光晕/眩光）· 绝对亮度落点 · 构图 / 内容 · 肤色关系（10-30 拍板不测）
```

### 8.6 谁消费

```
LR-A：split_b → Color Grading（阴影/高光各自的 hue + saturation）
引擎：不消费
```
## 9 口径规则（五条，够用）

```
① 只在**交付域**（sRGB / 1080 / JPEG）里比 —— 我们的出片先转成同一域再测
② 尽量用绝对阈值（L≥95 / L≤10）；用图自己的分位定义出来的量是循环的（永远是那个百分比）
③ 每个量要报"有效像素数"；不足就输出 unavailable，不许给 0
④ 一个量只在它能被解释的图上量（低频三量只在高光孤立、背景够暗的图上）
⑤ 复现性没测过的字段：只存，不进判据
```

## 9.1 砍掉的（附理由）

| 砍掉 | 为什么 |
|---|---|
| **高光 / 阴影面积结构** | 占比随内容变（天空 vs 暗室），不是风格量 |
| **黑白点色偏** | 亮/暗像素不足时就是噪声 |

## 9.2 保留但降级

| 保留 | 降成什么 | 条件 |
|---|---|---|
| 局部对比 / 清晰度 | **线索**（不进引擎反解） | 统一到交付域后**可比**了；但它含 JPEG 压缩，不是引擎参数的函数 |
| —— | —— | 肤色关系 10-30 拍板**不测**（采样器没有臂/中性点） |
| 光位分布 | 元数据 | 标签本身（gap/dark 阈值）未验，不参与判据 |
| **分离色调** | 进卡（LR-A 输入） | 绝对阈值（L<20 / L>80）+ 像素 ≥0.5%；不足给 unavailable |

## 9.3 一句话

**能测的没几个；测不准的存着，不进判据。** 判断"能不能用"只看两件：
**在不在交付域、阈值有没有绝对含义**。

## 9.4 这些量的理论支撑（诚实分级）

| 量 | 理论 | 级别 |
|---|---|---|
| 亮度 / 脸与环境的关系 | 比率原则（Wallach）· 锚定（Gilchrist）· Weber | **定理级**（`理论基础_1030.md`） |

| 分离色调（阴影/高光各自色偏） | 色彩对比 + 行业惯例 | 方向有依据，**强度无理论** |
| 局部对比 / 清晰度 | CSF / 锐度感知 | 理论有；**只能当线索**（含 JPEG 压缩） |
| 空间族（柔光/光晕/眩光） | 能量守恒散射 / 加性光（源码） | **不按卡量**：固定值 + 验收可调 |
| 颗粒 | —— | **无跨链等价**（源码事实），不测 |

★ 只有第一行是"定理级"；其余都是"有方向、没数值"。这决定了它们只能当线索或试验字段。
