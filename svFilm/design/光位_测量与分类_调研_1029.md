## 0 三句话结论

1. **能做到"三个方向"（朝我 / 侧 / 逆），做不到"五个名字"的稳定区分** ——
   因为大师语料自己告诉我们：`front` 和 `side` 在两颊差上分不开（9.7 vs 8.9 L\*），
   而 `back` 分得开（20.3）。名字是**报告**，不是接口。
2. **今天的 bug 不是调参能修的**：三个量的语义各有偏 —— gap 用全幅背景、rim 量的是
   "贴脸背景有多亮"、脸 L 只取**一块颊**。下面用 v6 的 4 张实图逐条对上。
3. **真正该改的是"脸"的定义**：侧光下同一张脸两块颊差 10~26 L\*，取哪块是硬币；
   曝光判据应该看**受光面**，光比只报告、不拉平。

## 2 三个量的语义，和它们各自的偏

```
gap   = bg.L_p90 − face L          ← bg 是**全幅背景**（含天空/远楼/远山）
dark  = face_dark_share40          ← 脸掩膜内 L≤40 的占比（这个没问题）
rim   = 脸掩膜 dilate 9px→25px 环带里 (L ≥ 脸中位+10) 的占比   ← 环带宽度**是死像素**
face L = 一块颊（`pool.sort(key=n)` 取**像素最多**的那块，不是受光那块）
```

四个细则：

1. **`bg.L_p90` 是全幅的**：逆光时确实高，但"人站在阴影里、远处背景是太阳"也高。
   两者物理上完全不同（一个是光源在背后，一个是**景深里另一片被照亮的区域**）。
2. **rim 环带 = 9→25 px（1080 域）**，与脸宽无关。我们的脸 121~164 px ⇒ 环带贴着脸轮廓，
   落在**脸周围的黑发**上；而发丝亮边/肩线亮边在 50~150 px 外。⇒ 见 §1 表的假阴。
3. **`face L` 只取一块颊**，取的是"像素最多"的那块。侧光下两块颊差 10~26 L\* ⇒ 判据的
   分子是**硬币**。`fixed_xy` 只是把这块硬币**冻结**（跨 ①/③ 一致），并没有选对。
4. **`skin.lit` 这个名字是错的**：`lit` = 像素多的那块，实测 1231 的 `lit` L=49.6、
   `shadow` L=56.3 ⇒ **"lit" 比 "shadow" 还暗**。`side_dL` 又取了 `abs()` ⇒ 连符号都没了。

## 4 建议：不做"光位分类器"，做"光的事实向量"

每个量必须**直接对应一个动作**，否则不许进求解（这是纪律第 1 条的另一面：
数值只用于定位、卡边界、判不变量）。

| # | 量（新/改） | 怎么算 | 它决定什么动作 | 谁用 |
|---|---|---|---|---|
| 1 | **face_L_ref**（受光面） | 两半脸的较大者（不是"像素多的那块"） | 曝光落区判据的分子 | LR ② |
| 2 | **ratio_stops** | 亮颊/暗颊 → 换算成档（`ΔL* → Δlog2Y`） | 只**报告**；决定点颜色取样点；**禁止拉平** | LR ⑥ |
| 3 | **hair_dL** | `p90(L[HAIR]) − face_L_ref`（HAIR 类**已有**，同一次前向） | 逆光补偿开关（天空封顶 / backlit 彩度） | LR ②⑥ |
| 4 | **bg_near − face_L_ref** | 背景 ∧ `dilate(person, k)`（**近邻**，不是全幅 p90） | 收白要不要动、逆光判据 | LR ③ |
| 5 | **bright_pos**（亮部位置） | 人掩膜内亮像素的**边界距离**（边缘 vs 内部） | 缝隙光：不许用全局曝光/收白把光带压平 | LR ②③ + 引擎 |
| 6 | **edge_hard**（软硬） | 人/脸掩膜内 \|∇L\| 的 p90，按脸反差归一 | 引擎 halation / 柔光档（接上一篇质感调研） | 引擎 |

**为什么 3 能修好 1、2 的错**：发丝是"逆光捕手"。逆光 = 头发接直射太阳 ⇒ `hair_dL` 大；
面光/顺光 = 头发比脸暗 ⇒ `hair_dL` 小。四张图肉眼都对得上（1231 深棕发、1665/1422 金色亮边）。
而且 HAIR 是 `selfie_multiclass` 的第 1 类，**同一次前向里已经算出来了**（现在只取了 FACE/CLOTH/BG），
边际成本 = 0。

**名字怎么处理**：`逆光 ≈ hair_dL 大 + face 暗`、`侧逆光 ≈ 再加 ratio 大`、
`面光/顺光 ≈ hair_dL 小（差在 edge_hard）`、`缝隙光 ≈ bright_pos 在内 + edge_hard 大`。
名字只出现在**报告和目检分组**里，求解器只吃 1~6 这六个数。

## 5 验证方案（不铺全量，先量一臂）

**第一臂（4 张，只看数能不能分开）**：1231 / 1526 / 1665 / 1422。
新量算出来若 `hair_dL(1231) < hair_dL(1608)`、`bright_pos` 能把 1526 的假 rim 排掉 ⇒ 方向成立。
代价：4 张 × 一次测量（HAIR 免费）≈ 10 秒。

**第二臂（20 张人工判读 + 混淆矩阵）**：从 auto 判据的 backlit 桶按脸 L 分层各取几张
（P10 / P50 / P90），我逐张看图定性，算三个方向类的混淆矩阵。
这是**唯一能解掉「逆光 45~70 循环论证」的办法** —— 代价 20 张看图 + 20 行手标。

**第三臂（语料）**：`m_*_v2.json` 的 859 张重测一遍（只加 HAIR/近邻/半脸三个量）。
代价：**859 张 × ~3 秒 ≈ 43 分钟单核，6 进程 ≈ 8 分钟**；按纪律要先报再跑。
**铺之前先把第一、二臂做完** —— 量具没验过就铺全量是重复劳动（今天 rim 已经吃过一次）。

## 6 对后续求解的直接影响（这就是"给引擎和 LR 用"）

```
LR ② 曝光：判据换成"受光面进区"（face_L_ref），zone 按方向分两套（逆光 45~70 / 其余 55~85）
           逆光不再由 --light 人给，由 hair_dL 判；人仍可覆盖
LR ③ 收白：看 bg_near（近邻背景），不看全幅 p90 ⇒ 天空不再冒充逆光
LR ⑥ 点颜色：取样点固定到**受光面**（现在固定到像素多的那块，可能是背光面）
引擎 质感：hair_dL + edge_hard 决定 halation/boost/柔光档（接 质感_动态调用_调研_1029.md）
```

一条边界要写死：**光比只报告，不许拉平**。把侧光提成面光就是"用下游补上游"的反向版，
而且大师语料里 `side` 占一半 ⇒ 拉平等于把一半的风格改掉。

## 8 逆光下的肤色亮度，能不能由"背景"算出来

> 2026-10-29 晚追加。用已有语料（733 张有皮肤+背景）算的，没有新跑测量。

### 8.1 语料里确实有一条很干净的比例

```
ΔEV = log2( Y(脸) / Y(背景亮部 p90) )          脸比"场景最亮的那片"低几档

                比值(脸/bgP90) p25/50/75      档差 p25/50/75 (EV)      n
逆光 backlit        0.51 / 0.55 / 0.60          −2.35 / −2.09 / −1.83   43
未知/3-4 unknown    0.72 / 0.79 / 0.84          −1.15 / −0.85 / −0.62   423
顺光 frontlit       0.91 / 0.96 / 1.09          −0.33 / −0.13 / +0.32   267
```

这条阶梯**很干净**（逆光 −2.1 EV ≈ 摄影里"开放阴影比直射太阳低 2~2.5 档"那条老经验），
而且和交接里 0.55 / 0.79 / 0.96 那组数一致。

**但它不能当"逐图目标"用**，三条理由都是实测的：

1. **没有杠杆**：逆光桶里 `bgP90` 只在 **87.3~97.4**（p10~p90）之间，极差 10 格。
   背景几乎不变 ⇒ 在这个桶里，"脸=0.55×背景"和"脸=49"**在观测上完全等价**，分不开。
2. **全语料不相关**：`r²(脸 L ~ bgP90) = 0.01`（733 张）。脸的亮度和背景的亮度**没有**统计关系。
3. **物理上本来就不该有**：逆光时照亮脸的是**天空光**，不是背景。把镜头从太阳楼转向一堵暗墙，
   照在脸上的光一点没变 ⇒ 脸的亮度是"绝对的"（天空光的水平），背景的亮度是"画面里有多少
   被晒到的东西"。两者都由太阳决定，**是兄弟不是父子**。

⇒ 所以"逆光下肤色亮度 = 背景亮多少"这条路，**在值上不成立**。

### 8.2 但这条比例有一个真正有用的用法：分"暗得有理由"与"暗得没理由"

现在的判据只有一个绝对区间（45~70），它对下面两种 48.7 一视同仁：

```
48.7 配背景亮部 97  ⇒  差 2.1 档  ⇒  **就是逆光该有的样子**，别动（动了就把逆光拉成面光）
48.7 配背景亮部 70  ⇒  差 0.5 档  ⇒  脸太暗了（背景都不亮，脸凭什么这么暗）⇒ 该提
```

做法：

```
期望脸 L = 背景亮部(近邻) × R(光源/光位)
     R ≈ 0.55（直射太阳下的逆光）· 0.79（侧逆/3-4）· 0.96（顺光）
     R 必须挂**光源类**：阴天/室内时 天空光 ≈ 太阳光 ⇒ R 要换到 0.85~0.95 那一档
欠曝 = 实际脸 L < 期望 − 1 档(≈8 L*)
目标 = 欠曝时提到 min(期望, 区间上界)；不欠曝就不动（区间当**夹子**，不是目标）
```

⚠ 三条硬约束：

1. **背景要用近邻**（`bg_near`），不是全幅 p90 —— 1231 的假逆光就是全幅里有远处的太阳楼；
2. **R 只能读 ①**（引擎底片），绝不能读 ③（我们自己的输出）—— 读 ③ 就是手册那条"必然振荡"；
3. **R 只有在"背景被太阳晒到"时有效**。当背景是阴天/室内时，`bgP90` 反映的就是天空光本身，
   ratio 天然接近 1，硬套 0.55 会把脸压暗 1.5 档。⇒ §4 的 `edge_hard / source` 不是可选项，
   它决定用哪一档 R。

### 8.3 和现有实现的关系

现在的 `目标 = 区间下界 + 3.5 = 48.5`，对典型逆光（bg 91）来说 **恰好等于 0.55×91 = 50**。
所以它在"典型日光逆光"上没错 —— 错在它**不随场景变**，也**不能区分该不该动**。
换成 8.2 那条以后，同一个 48.5 会带上一句"因为背景亮部 91、差 2.1 档，这是逆光的正常值"。

**区间别删**：语料里 81% 的逆光脸落在 45~70，但 **16% 低于 45**（大师故意的深逆光）。
把它当硬门会去"修"那 16% ⇒ 区间只能当**上界夹子**和"提亮之后别冲出"的保护。

### 8.4 还差的一步（要量，不是推）

`R` 的**光源分支**目前只有 daylight 一种证据（语料全是白天街拍）。要补就得有
"阴天逆光 / 窗光逆光 / 傍晚逆光"的样本。语料标签里有 `overcast 18`、`daylight_window 87`、
`tungsten 62`，够做一个分支验证 —— 但那要**重测**（近邻背景 + HAIR），
和 §5 第三臂同一次跑完，不要为它单独铺一遍。
