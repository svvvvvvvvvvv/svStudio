# 纪律

> 先读本文，再读 `设计真源.md`。冲突时：**纪律 > 设计 > 代码**。
>
> **最高规则只有一条：对齐人选的那张大师卡。**
> 卡不是合格证，是这张卡的风格/关系目标；物理底线只是防止事故，不是风格目标。
>
> **脸和背景都成立。** 用背景换脸、或用脸换背景，都算错。
>
> **人目检是唯一验收。** 机器只出片 + 目检页 + 诊断；不宣布“过/不过”。

## 六条

1. **卡是唯一目标**
   用卡的关系 / 形状 / 配比 / 分布，不用单点、不用区间靶、不设“背景 L=30”这类数字。
   写不出“对齐卡的哪一项”，这一步不许存在（物理底线除外）。

   **引擎 PE 是目录级**：每个内容目录/卡标一个；PE 不对，先修 PE，不拿 LR 硬拉。

2. **WB 是目录级/组级，不是图级**
   一个目录一个 WB：cast 目标 + 引擎 temperature/tint；跑批时整组一个。
   逐图 WB 会把一组色调拆散；一批里有两套光 ⇒ 拆批，不是逐图调。
   **不拿成片白点反解解码 WB**；白点只做诊断。
   **一张卡一个局部蒙版**；不逐图换多组蒙版。

3. **物理底线之外，不设创作门**
   只拦：死白、p1 死黑、量程、非单调、肤色崩。
   不再用“一档 10 UI”“cap ±0.2”“必须 −10”这类未经验证的政策当目标；
   剂量由卡和 ③ 验证决定。

4. **顺序：WB → 曝光/明暗 → 颜色 → 局部 → 细节**
   先让整幅/背景成立，再补脸；局部永远在全局之后。
   局部补脸用**脸/肤色蒙版**，不能用 subject 整身蒙版把白衫一起抬。

5. **不逐图打补丁**
   参数只挂三层：卡 / 场景类 / 意图。代码里不许按 stem、文件名、“这批都欠曝”分支。

6. **先查资料，再定系数**
   有公开公式/文档/开源实现就用；查不到就写“没有公开闭式”，用卡 + ③ 验证，
   不编斜率、不编绝对系数。分析模型只放 `analysis/`，生产不 import。

   **不准拿 LR 当数值试验台**：不许反复改参数、导出、量数来“凑”目标；
   一次验证只用于确认公式/文档，不用于搜系数。参数关系必须来自官方文档、
   作者源码/手册、他人实现或已有标定；没有出处就不写进生产代码。

## 归因

不达标只有一种结论：**流程或实现哪一段没做到**。
“场景没余量 / 素材不行 / 换纸 / 这张本来就过曝”只能是现象，不能当结论。
每条不达标后面必须写“漏在哪一段”。

## 每轮标准动作

```
1 设计对齐（不跑、不谈参数）→ 2 写代码+单测 → 3 出片 →
4 量 ③（只定位）→ 5 目检（先看图）→ 6 不达标→找漏 → 7 记账
```

## 谁有权改什么

| 类别 | 谁定 |
|---|---|
| 技术性（bug/工具/物理换算） | agent 直接改 |
| 卡级参数（WB/明暗/肤色方向） | 人定卡；agent 按卡算 |
| **风格/意图（亮/暖/浓/软）** | **人** |
| **审片（好不好看）** | **人** |
