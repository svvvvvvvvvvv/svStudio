# 第一部分 · 六条铁律

> **优先级先定死（2026-10-29）**：**脸（主体）> 背景高光 > 其它**。
> 任何一步只要把脸压暗了就是做错，哪怕背景因此更爆。
> 「回引擎」有两层意思，必须分开说：**换卷/换纸 = 人的决定**；
> **让引擎改曝光或多留余量 = 越界，禁止**；收白收不住的后果是**接受背景过曝**，不是回引擎。

### 1. 不许打数值靶
**判据**：出现"把某个统计量调到 X 才算对"就违规——包括"和大师的某个数对上"。
**数值只有三种合法用途**：
- **定位问题**（"p95 比上一态高 6 L\*，说明是②提亮顶上去的"）
- **卡物理边界**（白平台 100 / 量化下限 ±1 L\* / 滑杆量程 ±100 / 大师实测**区间**）
- **判过不过的不变量门槛**（T 系列、S 系列）
**阈值只能从四个来源来**：量化下限 · 物理不可逆 · 生理常识 · 大师实测**区间**。

### 2. 不许为单张图 / 单批图打补丁
**判据**：代码里出现按 `stem`、按文件名、按"这批都欠曝所以加 0.3 档"的分支 = 违规。
**参数只许挂三层**：卷纸（生产卡）· 场景类（逆光/顺光/爆白，由测量自动判）· 意图（人给）。
`solve_one(rec)` 的签名里不许出现 stem。

### 3. 先查资料，再动手
**判据**：说不出出处就动手 = 拍脑袋。要查**四类**：GitHub 实现 · 论坛/厂商文档 · 专利 · 论文。
**查不到就明说"没有公开闭式"，不许自己编一个斜率**（编出来的"看起来很精确的假值"比不给更糟）。
**已有结论**：`Highlights/Shadows/Whites/Blacks` 无公开传递函数（Adobe 官方只说"按亮度区域自适应"）；
`Saturation/Vibrance` 同上；点颜色无公开式。这类只当**方向**用，幅度靠出片验收。

### 4. 不许乱跑
三种"跑"各有门槛，**跑之前先报代价（多久 / 占多少核 / 多少张）**：
| 跑什么 | 规矩 |
|---|---|
| **LR** | **不许拿 LR 当标定台**（不许"跑一遍看看给多少"）。只有**出 ③ 成片**才驱动 LR，且只在 `[4b]` 那一步显式调 |
| **胶片引擎**（渲染批） | 先试点 2 张 → 报代价 → 等命令；不许拿整批当试验田 |
| **测量**（量图） | 判一件事默认 **10~30 张 + 看图**；要铺开先报代价。**为了拿统计量跑全量 = 违规**（犯过：验一根判据跑了 905 张 / 37 分钟） |

### 5. 先出成片，再量，再目检
**判据**：拿中间态（① 引擎底片 / 我们自己过 LUT 的仿真）的量当结论 = 违规。**①≠成片。**
**完整流程五段，缺一段不算**：引擎出片 → LR ②③ → 导出成片 ③ → 量 ③ → 目检。
**目检规矩**：一页 HTML、图竖排占满宽、同屏可看、挂资料库；
**不许拼图 / 多格矩阵 / `<table>`** 撑破手机屏；**链接独占一行**。

### 6. 分工不许越界
| 层 | 只许管 | 不许碰 |
|---|---|---|
| **引擎** | 卷/纸（风格）· 颗粒 · 光晕 · 柔光（质感）· 自己的测光出片 · 报"还能抬几档" · 白点 | 任何逐图的**曝光落点 / 明暗分布 / 颜色** |
| **LR** | 看哪里 · 曝光落点 · 收白 · 曲线 · 饱和 · 肤色/色相 | 卷纸质感、颗粒 |
| **人** | 意图（亮/暖/浓/软）· 审片（好不好看、像不像大师） | ~~具体参数~~ |

两条硬边界（都违反过，各挨过一次）：
1. **引擎不管脸、不管落点**——为了"留余量"在引擎里按脸推曝光 = 把刚拆掉的搬回去。
2. **算值不依赖 LR**——公式要能查、能离线复算；只有"出 ③ 成片"才驱动 LR。

# 第二部分 · 不达标怎么归因

**只有一种结论**：流程或实现哪一段没做到，所以在这类图上不成立。
「场景没余量 / 素材不行 / 换纸 / 这张本来就过曝」可以是**现象描述**，**不能是结论**。
报告里每条"不达标"后面必须跟一句"漏在哪一段"；写不出来 = 还没查完。

**唯一例外**：换卷/换纸是**设计选择**（要另一种风格），不是"解决不达标"的手段。

```

5 目检         一页 HTML，先看图再谈数
6 不达标→找漏  回 1 或 2；禁止写"场景不行/换纸"
```

**做对了只有三条同时成立**：方法论正确 + 设计正确 + 人目检同意。
**禁止**用"统计量到靶"或"和大师数值接近"宣布做对。

# 第五部分 · 工程硬约束

```
层序：`_scene_engine["*"]` → `_stock_engine[预设]` → 轴层（后者盖前者）
`presets.render()` 裸调**不读** targets.json ⇒ 生产路径 = `targets.scene_engine(...)` 整份传 overrides
overrides 键名 = 运行时属性路径；**必须整份传**（只传一根会让 print_render.chemistry 静默死）
`print_render.glare` 永不可复现（numba RNG）⇒ 同参两渲取差先关 glare；2048 不许用颗粒绝对值
`film_format_mm` = 画幅**长边** mm（70 vs 36 ⇒ σ_px ×0.514）
改 JSON：newline='' 读 + jsonsafe.probe 探排版 + 原子写 + json.loads 验 + **邻键还在**
Windows glob('*.jpg') 与 '*.JPG' **不分大小写** ⇒ 一律小写后缀过滤一次 + set 去重
渲前先 Test-Path 验 RAF 目录；run_shards 不可靠 ⇒ 逐张直调或手分片
中文标签必须走 `_lib.label.text()`（PIL 默认字体没汉字 ⇒ 乱码烧进成片）
新预设必须同时登记 `presets._DESC` 与 `selftest._PRESETS`
方向断言先量一臂（↑X ⇒ 偏Y 一律实测；滤片/γ/耦合按名字推必错）
卷/纸在预设里是 params 构建时传入，**overrides 改不了**
引擎手册只写引擎事实（机制/单位/量程/契约/坑 + 文件:行号）；
  不写我们的预设状态、拍板、目检、复盘、commit 号；手册与代码冲突 ⇒ 以代码为准、改手册
```

# 第七部分 · 已作废（重开必须带新证据）

| 作废的规则 / 结论 | 何时 | 为什么 |
|---|---|---|
| 引擎侧「动态 PE / `person_pe_band` / `print_exposure`」当曝光落点 | 10-29 | 曝光/影调归 LR；引擎不碰逐图落点 |
| LR「两道预算取小」+ 余量不够记欠账 | 10-29 | 拿引擎的账卡死 LR 的曝光 ⇒ 余量 0 时曝光恒 0、脸永远进不了区 |
| LR「余量不可信 ⇒ 拒算曝光」 | 10-29 | 同上；余量只作记录，越过白平台交给 ③ |
| 「降白端换余量」（`scan_white_level` 调低） | 10-29 | 零和：砍多少报多少（恒等式）；还赔 5 个 L\* 高光 |
| 「放松 `black_max` / 下移暗部锚点 / 关掉测光」求余量 | 10-29 | 三条全实测否掉：精确没改 / 暗部黑 2%→16% / 整批欠曝 1.4 档 |
| 「`HIGHLIGHT_POLICY = −35`」当收白幅度 | 10-29 | 无公开函数，改成对分搜索（起点 −50 + 出片验收） |

| 「目标性参数必须用户拍板」 | 10-29 | 改为：方向人给，数值我定（依据调研+实测） |

# 第八部分 · 红灯清单（我自己犯过的，开工前扫一眼）

| 犯过 | 长什么样 | 正确做法 |
|---|---|---|
| 拿统计量宣布做对了 | "和大师 p95 差 0.3，说明对了" | 只报流程/设计对不对，对错由目检定 |
| 为判一件事跑全量 | 905 张 / 37 分钟 | 10~30 张 + 看图；铺开前报代价 |
| 拿中间态当成品 | 拿引擎底片比大师成片 | 同态才可比 |
| 越界到引擎找余量 | 改白端/暗部锚点/关测光 | 曝光归 LR；引擎只报余量 |
| 拍脑袋定参数再让人拍板 | "锚点 3.5 行不行" | 参数我定，只让人判取舍与审美 |
| 把"做不了"当结论 | "这批没余量，得换纸" | "流程哪一段没做到" |
| 跳过设计直接写代码 | 先实现再补自证 | 先对齐设计 |
| 只量一半信息给结论 | 只看 p95 不看直方图形状 | 看相对位置/区间占比/平台/暗部够不够黑 |
| 用我的判断取消他的需求 | "量到没收益"就收工 | 要不要做由目标定，顺序让他定 |
