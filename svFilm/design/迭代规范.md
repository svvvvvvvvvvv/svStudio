# 迭代规范（2026-10-29 SV 定，之后每轮都按这个来）

> 这份是**硬规矩**，不是建议。写代码前先读一遍；报告前对着红灯清单自查一遍。

## 一、八条，逐条落到判据

### 1. 不许打数值靶

**原话**：「不允许去打数值靶」「别搞打靶打靶 看直方图」

**怎么算违反**：出现任何"把某个统计量调到 X 才算对"的判据（均值/中位/分位/直方图某段占比），
包括"和大师的某个数对上"。**大师的统计值是线索，不是靶。**

**允许的用法**（仅此三种）：
- 定位问题："这张 p95 比上一轮高了 6 L\*，说明是②提亮顶上去的"
- 卡物理边界：白平台 100、量化下限 ±1 L\*、滑杆量程 ±100
- 判"过/不过"的门槛：T1 不爆白 / T4 脸在 55~85 / T5 肤色 C≥10（这是不变量，不是靶）

**靠什么保证**：判据只许来自「量化下限 / 物理不可逆 / 生理常识 / 大师实测**区间**」。
写代码时凡出现 `target_`、`ideal_`、`should_be` 这类名字，先停手看它是不是靶。

---

### 2. 不许为某一张照片打补丁

**原话**：「为某个照片打补丁」（禁止）

**怎么算违反**：代码里出现按 `stem`、按文件名、按"这张图很特殊"分支的参数或特例。
也禁止"这批图都欠曝，所以给这批加 0.3 档"——那是给批次打补丁，同样不许。

**只允许三种分层**：卷/纸（生产卡）· 场景类（逆光/顺光/爆白，由测量自动判）· 意图（人给）。
参数只能挂在这三层上，**不许挂在图上**。

**靠什么保证**：`solve_one(rec)` 只吃测量，签名里没有 stem；新加参数前先问"它属于哪一层"。

---

### 3. 先跑完整流程出成片，再量，再分析

**原话**：「用完整流程跑的成片再去量数值分析」

**怎么算违反**：拿中间态（①引擎底片 / 我们自己过 LUT 的仿真）的量当结论，
或者没出 ③ 就宣布"达标了"。**①≠成片，中间态的量只能用来定位流程，不能用来判对错。**

**完整流程 = 五段，缺一段都不算**：
```
① 引擎出片（卷/纸/质感/白点）→ 量
② LR 曝光 → ③ 收白（同一张 XMP 里落下去）
③ LR 导出成片 → 量
④ 目检（人看）
⑤ 不达标 → 回流程/实现找漏
```

**靠什么保证**：`cli run` 的 `[4b]` 段（`--export`）是必经，不是可选；
量 ③ 的入口现在**还没有**（见《对齐审计》G1）。

---

### 4. 必须给我目检

**原话**：「并给我目检」「不要拼图 一张一张竖排列…我在手机上看」「白天成片传资料库用 html」

**怎么算违反**：只给数字不给图；给拼图/多格矩阵；给一堆散图目录让他自己翻。

**规矩**：一页 HTML，图**占满宽、竖着往下排**，同屏能看；挂在资料库根下；
链接**独占一行**，前后不加任何字符。

**靠什么保证**：每轮收尾必须有这一页。现在这页还是人手写的（见《对齐审计》G3）。

---

### 5. 不达标 = 流程或实现的问题，不许怪场景

**原话**：「如果有地方不达标 就是流程的问题实现的问题 没有做到普遍性和适用性」

**怎么算违反**：结论里出现「这批场景没有余量」「素材不行」「得换纸/换卷」「这张本来就过曝」
当作**终点**。这些可以是**现象描述**，但不能是**结论**——结论必须是
「流程里哪一段没做到，所以在这类图上不成立」。

**唯一例外**：换卷/换纸是**设计选择**（要另一种风格），不是"解决不达标"的手段。

**靠什么保证**：报告里每条"不达标"后面必须跟一句"漏在哪一段"；写不出来就说明还没查完。

---

### 6. 普遍性与适用性

**原话**：「没有做到普遍性和适用性」

**怎么算违反**：一条规则只在少数几张上成立就够了，或者靠"这批刚好都…"成立。

**判据**：同一条规则要能对**整批 + 不同场景（顺光/逆光/爆白/暗场）**给出方向一致的结果；
给不出就说明这条规则缺条件（缺的是"场景判据"，不是"每张微调"）。

---

### 7. 不准钻牛角尖

**原话**：「不准钻牛角尖」

**怎么算违反**：一件事已经能判"做/不做"了还在追小数点后的差别；
为了 0.1 L\* 去跑几十张图；把"参数没标定"当成必须马上解决的阻塞。

**判据**：一件事**能不能判**决定停不停，不追**判得准不准**到无意义的位数。
判不了才继续查；判得了就往下走，把不确定写成账。

---

### 8. 分工与职责必须守住

**原话**：「分工和职责一定要保证好」「曝光影调在lr来调的 引擎干好胶片感的事就行了」

| 层 | 只许管 | 不许碰 |
|---|---|---|
| **引擎** | 卷/纸（风格）· 颗粒 · 光晕 · 柔光（质感）· 出片留余量 · 白点 | 任何逐图的曝光落点、明暗分布、颜色 |
| **LR** | 曝光落点 · 明暗分布 · 高光收白 · 曲线 · 饱和 · 肤色/色相 | 卷纸质感、颗粒 |
| **人** | 意图（亮/暖/浓/软）· 审最终画面 | 具体参数 |

**怎么算违反**：在引擎侧找"曝光/余量/落点"的解法（今天已经犯过一次）；
或者拿 LR 的活去要求引擎（"引擎该多留 0.3 档"）。**越界即违规，与结果好坏无关。**

## 二、每轮迭代的标准动作（照这个顺序，不许跳）

```
1. 设计层对齐       只谈：组成 / 各自负责什么 / 边界 / 怎么协作 / 什么算成功 / 不做什么
                    —— 不动代码、不跑东西、不谈参数
2. 写代码 + 单测    判据先钉住再实现；改了旧行为就改旧断言，不许删了了事
3. 完整流程出片      ①→②→③ 五段走满（G1 补上之前，③ 还是人工）
4. 量 ③             只用它定位问题，不用它宣布对错
5. 目检             一页 HTML，同屏、竖排；先看图再谈数
6. 不达标 → 找漏     回 1 或 2；禁止写"场景不行/换纸"
7. 记账             设计真源 / 交接 / 台账 / 坑表 同步
```

## 三、红灯清单（我自己犯过的，开工前扫一眼）

| 我犯过 | 长什么样 | 正确做法 |
|---|---|---|
| 拿统计量宣布做对了 | "和大师的 p95 差 0.3，说明对了" | 只报"流程/设计对不对"，对不对由人目检 |
| 为判一件事跑全量 | 验一根判据跑了 905 张 / 37 分钟 | 10~30 张 + 看图定案；铺开前先报代价 |
| 拿中间态当成品 | 拿引擎底片去比大师成片 | 差着 LR 那一步，只能同态比 |
| 越界到引擎找余量 | 改白端/暗部锚点/不测光 | 曝光归 LR；引擎只报余量 |
| 拍脑袋定参数再让人拍板 | "锚点 3.5 行不行？" | 参数我自己定（依据=调研+实测），只让人判取舍与审美 |
| 把"做不了"当结论 | "这批没余量，得换纸" | "流程哪一段没做到" |
| 跳过设计直接写代码 | 先实现再补自证 | 先对齐设计，再写 |
| 只量一半信息给结论 | 只看 p95 不看直方图形状 | 看相对位置/区间占比/平台/暗部够不够黑 |

## 四、三条最容易走偏的，单独再说一次

1. **"量"的职责只有一个：定位问题在哪一段。** 量不能证明做对了，只有「方法论对 + 设计对 + 人目检同意」三条同时成立才算做对。
2. **达标判定只许用不变量**（T1/T2/T4/T5 + S1~S4），不许用"像不像某个数"。
3. **不达标的第一反应必须是"流程哪段漏了"**，不是"这张图不行"、不是"换纸"、不是"参数要重调"。
