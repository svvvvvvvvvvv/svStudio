# design/ · 怎么用

> 设计真源是 `E:\ds\photo\分工设计_引擎与LR_1029.md`。这个目录是它的代码化。
> 一句话：**引擎交一张带余量、不偏色的底片；LR 决定它最终多亮、什么颜色。**
> 判据只有「不变量 + 意图」，没有「该到多少」。

## 0 两条硬边界（先看这个，能省很多返工）

```
① 引擎不管脸、不管落点 —— 曝光是 LR 的事。
   引擎只做：选卡（卷+纸+质感档）、用自己的测光出片、报告"还能抬几档"。
② 算值不依赖 LR；只有"出 ③ 成片"这一步才驱动 LR。
   （公式要能查、能离线复算；产品才需要 LR。）
```

## 3 三类"卡"，别混

| 类 | 数量 | 有什么 | 用途 |
|---|---|---|---|
| **参照卡** | 64（大师 62 套鹿井 + xhs + 滨田） | 只有**画像**（中位 + IQR） | "这批该像哪一套" |
| **生产卡** | 3（卡38 / xhs预设 / 滨田预设 —— 名字里带"预设"二字，但它们是**卡**） | 有**配方**（卷/纸/质感档） | 能渲 |
| **意图** | — | 人给的 −1..+1（亮/暖/浓/软） | 只改方向 |

匹配是**两步**：① 在 64 张参照卡里找最像的一套 → ② 现有生产卡能不能做到那个像（`feasibility`）。
做不到就是"该做新卡"，方向由那一套的画像给。

## 4 判据（全部是"不许破"，不是"必须到"）

```
T0  出片：p95 ≤ 93 ｜ clip < 0.5% ｜ p1 ≥ 1.0     ← 阈值来自大师实测区间
T1/T2 终片：clip < 2.5% ｜ p1 ≥ 2.0
T3  白点：|a|,|b| ≤ 2（8-bit 量化下限 ~1）
T4  脸 L ∈ 55~85 ｜ T5 脸 C ≥ 10
S1  改色不改明暗（皮肤 L 分布变化 ≤1）
S2  改局部不动全局（背景 a/b 变化 ≤1）
S3  曲线每锚点 ≤3 L*
S5  一段顶到上限 = 上游错，不许用别的旋钮补
```

**为什么 T0 是 p95 而不是 p99**：大师实测 p99 中位 94.6~97.9，p99≤92 比任何一套都严 3~6 L*，
会逼着引擎"为留余量把脸压到 L40"（真跑踩过）。

## 5 常见坑（都踩过）

| 坑 | 现象 | 记在 |
|---|---|---|
| `render_safe` 的 `p95_max` 是死参数 | 给 80 和 88 出同一张图 | flow.py |
| 曲线 16 点用均匀网格 | 高光锚点在 250/254，修正在 LUT 里被抹掉 | curve.py |
| 锚点位移实测比规划大 | 规划 3.0 量到 3.14 ⇒ 规划预算 2.7 | lr.py |
| 意图被算两次 | 曝光和曲线都加了一次 | lr.py |
| 拿自己出片的偏差当需求 | 拿缺陷当需求（循环论证） | match.py |
| 缺规格的卷被当成"最细" | verita 不在 grain.toml 里 | cards_match.py |
| 曝光不看余量 | 会安静输出 +2.4 档的毁图计划 ⇒ 现在两道预算取小 + 记欠账 | lr.py / expose.py |
| ~~**两道预算取小**~~ | 那是拿引擎的账卡死 LR 的曝光（§19 分工反了）：余量 0 ⇒ 曝光恒 0、脸永远进不了区。现在按脸给满，越过白平台交给 ③ | lr.py |
| 收白拿 ① 的旧 clip 判 | 先收白、后算曝光，顺序倒了 ⇒ 现在判 ①'（提完曝光的态） | expose.py |
| 没脸的图静默不动曝光 | `person` 档 cur=None ⇒ 0 档，等于弃权却不写 | lr.py |
| **降白端"换"余量** | `scan_white_level` 是**上端硬天花**：砍多少就报多少余量（恒等式），还赔掉 5 个 L\* 的高光 ⇒ 零和 | flow.py 常数区 |
| **天花 <100 时 `clip` 恒为 0** | `(L>99)%` 在 95.5 的天花下永不可能触发 ⇒ "clip 全 0"是假达标 | invariants.py |
| `render_card` 的 `p95_max` 入参被忽略 | 算完之后又 `saf.get()` 读回 ⇒ 传什么都没用 | flow.py |
| **`after_ev` 把上端夹在 100** | 一夹就丢掉"过了多远" ⇒ ③ 分不清爆 2 与爆 20 ⇒ 补未截断的 `white_over_L` | expose.py |
| **① 已爆 当成 LR 的活** | ① 的 clip 是引擎丢的细节，Highlights 只压暗、补不回 ⇒ 单列"引擎的账" | lr.py |
| **`m_state*.json` 混着 `_sim.png` / `_it.png`** | 同一张图四个态全进来，9 张算成 36 张 ⇒ 无 `--stem` 时只取 `_engine.tif` | cli.py |
| **给 Highlights 编传递函数** | Adobe 没公开函数，第三方（agx-photo）那份是手感仿写 ⇒ 编出来的斜率是"看起来很精确的假值"；改成对分搜索 + 出片验收 | lr.py ③ |

## 5.5 「以人为本」在 LR 侧落在哪四行（2026-10-29 补齐）

设计出处：分工设计 §25~§29（原则保留，执行位置从引擎迁到 LR）。

| 规则 | 落点 | 判据 |
|---|---|---|
| H1 有脸用脸 | `lr.pick_lookat` → 读 `skin.L` | `face_w_native ≥ 40`（FACE_MIN_W） |
| H2 降级链 | 同上，**降级必须写理由**；人的读数测量层还没接 ⇒ 降到整幅，不假装有 person 档 | 整幅落点没有不变量 ⇒ 曝光**弃权**并写明 |
| H3 白端保护 | `lr.solve_exposure` 两道预算取小：引擎余量 ∩ p95 到白平台 | 差多少记 `exposure_debt`，不硬顶 |
| H4 逆光识别 | `lr.light_state`：脸/背景 <1.0 逆光、>1.3 顺光 | 逆光 ⇒ 提脸 + 预备收白；顺光脸仍低 ⇒ 提示先查测光 |

**L1「脸是约束不是目标」**：脸在 55~85 内 ⇒ 曝光 0 档（不再往 72 硬推）。
**L2 / 顺序**：先 `expose.after_ev()` 算 ①'，再在 ①' 上判收白（原来拿 ① 的 clip 判，顺序是反的）。
**算不了的部分**：`Highlights` 没有公开传递函数 ⇒ 只给政策值 −35 + 明确标"待验收"，③ 必须验 clip。
